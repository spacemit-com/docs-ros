# 策略配置与模型契约

策略 YAML 是训练产物与 SDK 运行时之间的契约，必须与 ONNX 的张量名称、shape、数据类型、观测顺序和动作语义保持一致。

## 1. 配置层级

`LoadPolicyConfigFromYaml` 根据调用方传入的策略名读取 `rl_policy.onnx_infer.policies.<policy_name>`：

```yaml
rl_policy:
  type: onnx_infer
  rl_dt: 0.02
  onnx_infer:
    policies:
      walk:
        model_path: policy/walk/policy.onnx
        model_io:
          inputs:
            - {name: obs, source: observation}
          outputs:
            - {name: actions, target: action}
        action_scale: 0.25
        action_blend_ratio: 1.0
        action_joint_index: [0, 1, 2]
        rl_default_pos: [0.0, 0.0, 0.0]
        observation:
          segment_0_terms: [ang_vel, gravity, command, dof_pos, dof_vel, last_action]
          strict_dim_check: true
```

组件要求策略提供 `model_path`、非空 `model_io.inputs/outputs`、`rl_default_pos` 和至少一个连续编号的 `observation.segment_<n>_terms`。`action_scale`、动作索引、裁剪和其他字段按模型实际契约配置，不能依赖运行时猜测网络类型或张量用途。

## 2. `model_io` 张量绑定

每个 ONNX 输入和输出都必须按张量名显式声明。

```yaml
model_io:
  inputs:
    - {name: obs, source: observation}
    - {name: obs_hist, source: observation_history, history_of: obs}
    - {name: h0, source: feedback, output: hn}
    - {name: time_step, source: constant, value: [0.0]}
    - {name: mask, source: external, key: policy_mask, default: [1.0]}
  outputs:
    - {name: actions, target: action}
    - {name: value, target: expose, key: critic_value}
    - {name: debug, target: ignore}
clip_observations: 100
clip_actions: 100
```

### 输入来源

| `source` | 用途 |
| --- | --- |
| `observation` | 使用 `AssembleObs` 生成的观测，可通过 `offset` 将完整观测分配给多个输入 |
| `observation_history` | 自动维护某个 observation 输入的历史窗口；只有一个 observation 输入时可省略 `history_of`，存在多个时必须显式指定 |
| `feedback` | 将指定模型输出回灌到下一帧输入；可配置初值，未配置时从零开始 |
| `constant` | 使用 `value` 配置的固定张量 |
| `external` | 由上层通过 `SetModelInput` 注入；无 `default` 时必须在首次推理前设置 |

### 输出目标

| `target` | 用途 |
| --- | --- |
| `action` | 作为策略动作输出，每个策略必须且只能配置一个 |
| `expose` | 由上层通过 key 读取 |
| `ignore` | 明确声明该输出不由组件使用 |

输出即使声明为 `action`、`expose` 或 `ignore`，仍可同时作为 feedback 的来源。未声明、重复绑定、张量名不匹配或元素数量不兼容会在初始化阶段失败。

## 3. 观测组装与历史

`observation.segment_<n>_terms` 定义每段的观测项及排列顺序，多段依次拼接后形成完整观测。

| 模式 | YAML 值 | 当前行为 |
| --- | --- | --- |
| 无历史 | 省略 `mode` 或设为空 | 只输出当前帧 terms |
| 变量分组历史 | `flat_history` | 同一 term 的多帧值连续排列；`order` 和 `include_current` 生效 |
| 帧滑窗历史 | `frame_history` | 按完整帧从旧到新排列，当前帧放在末尾；当前实现不使用 `order` 和 `include_current` |

段历史由观测组装器生成，是主观测向量的一部分；`model_io` 的 `observation_history` 则为 ONNX 单独维护一个模型输入，两者不能混为同一配置。

`strict_dim_check: true` 会在 `Init` 时校验观测段计算维度与模型 observation 输入总维度；关闭后只告警，超出的段不会写入，缺少的部分保持为零。无论该选项是否开启，`Infer` 传入的向量长度都必须等于 `ObsDim()`。

常规传感器和命令由 `AssembleObs` 参数提供。额外的策略观测可通过以下方式注入：

- `custom_scalar_keys/custom_scalar_values` 声明标量默认值，由 `SetCustomScalar` 更新。
- `custom_array_dims` 声明数组维度，由 `SetCustomArray` 在 `AssembleObs` 前写入。
- 不属于 observation term 的独立 ONNX 输入使用 `source: external` 和 `SetModelInput`。

当前实现会把未注册的 observation term 当作一维自定义标量，未赋值时保持为零。因此配置拼写错误不一定立即报错，接入新策略时必须核对 term 名称和实际观测值。`last_action` 表示上一帧经过裁剪和平滑后的 action，不是 ONNX 原始输出，也不是映射后的关节目标位置。

## 4. 动作处理与关节映射

动作按以下顺序处理：

```text
ONNX action 原始输出
        │
        ▼
clip_actions 裁剪
        │
        ▼
action_blend_ratio 与上一帧动作平滑
        │
        ▼
action_scale 缩放 + rl_default_pos 偏置
        │
        ▼
action_joint_index 映射到全身关节目标位置
```

`action_scale` 可以是单值或逐动作配置。未被策略动作覆盖的关节保持 `rl_default_pos`。需要记录裁剪和平滑前的模型结果时，使用 `Infer(obs, action, &raw_action)`；普通 `Infer` 返回的是裁剪和平滑后的动作。

`kp`、`kd` 不参与 `PolicyExecutor` 的动作处理。配置加载器只负责返回这些增益，由上层按当前策略组装控制命令。

## 5. 数据类型与 shape 限制

- 当前部署 ABI 固定为 batch=1，不支持运行时改变 shape。
- observation 和 action 使用 float 语义路径；external 和 expose 可通过 `TensorView` 保留模型声明的原生数据类型。
- ONNX `string`、`complex` 不受支持；FP8、INT4 只支持原生 packed buffer，不提供缺少量化参数的 float 自动转换。
- 当前只支持一个确定性关节位置 action。多 action head、随机分布采样、力矩 action 等语义需要扩展公共输出契约，或在导出模型时封装为现有 ABI。

## 6. 上层控制参数

`LoadPolicyConfigFromYaml` 还会返回下列字段，但不在 `PolicyExecutor` 内执行：

| 字段 | 上层用途 |
| --- | --- |
| `rl_dt` | 当前共享运行时使用的策略推理周期 |
| `infer_decimation` | 返回给调用方的兼容字段；当前共享 `StateRL` 不使用它安排推理 |
| `command_init` | 初始化策略命令 |
| `kp` / `kd` | 组装当前策略的关节控制增益 |
| `max_roll` / `max_pitch` | 行为管理或安全逻辑使用的姿态阈值 |

同一 YAML 可以声明多个策略，由调用方按名称分别加载。策略列表、默认策略、前置策略链和运行时切换流程属于上层应用配置，不是 `PolicyExecutor` 内部能力。

配置完成后，按[模型验证与性能评测](4.3.4-模型验证与性能评测.md)检查模型 I/O、组件链路、数值契约和运行性能。

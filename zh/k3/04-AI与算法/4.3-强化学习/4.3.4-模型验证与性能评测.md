# 模型验证与性能评测

本页分开四种结果：ONNX 模型可加载、组件功能链路可运行、组件内延迟达标，以及仿真/实机上的策略效果正确。前三项都不能代替最后一项。

## 1. ONNX 单模型测试

`test_onnx_infer` 可直接检查模型的 I/O 名称、shape、加载和推理情况。

```bash
./output/staging/bin/test_onnx_infer \
  application/native/humanoid_unitree_g1/policy/walk_mjlab/policy.onnx \
  --random
```

该工具使用随机或零输入验证 ONNX backend，它不知道真实观测语义，也不判断策略动作是否正确。

## 2. 批量扫描

以独立子进程扫描指定机型目录下的 `.onnx` 文件，避免单个模型崩溃中断整个扫描：

```bash
./output/staging/bin/test_onnx_infer --scan \
  application/native/humanoid_unitree_g1
```

报告会列出每个模型的输入输出、加载/推理结果和本次测试延迟。批量全部 `PASS` 只证明这些模型可由当前 ONNX Runtime 后端执行。

## 3. 组件全链路测试

`test_policy_executor` 验证 YAML 配置加载、named tensor 绑定、观测组装、多帧推理、feedback、可用的 external/expose 输入输出和动作映射。

```bash
./output/staging/bin/test_policy_executor \
  application/native/humanoid_unitree_g1/config/g1.yaml \
  walk_mjlab \
  application/native/humanoid_unitree_g1
```

对于无默认值、必须由业务链路实时提供的 external input 或 custom array，该工具不能生成真实输入，应改用对应的集成或 replay runner 验证。

模块还提供 `test.yaml` 和 `tests/`，可通过 SDK 根目录的 `robot-test` 运行：

```bash
scripts/test/robot-test list components/model_zoo/rl
scripts/test/robot-test run components/model_zoo/rl --scope pr
SROBOTIS_RL_TEST_POLICY=walk_mjlab \
  scripts/test/robot-test run components/model_zoo/rl --scope scheduled
```

PR 档只验证不依赖模型资源的配置和错误路径；真模型推理冒烟需要先下载 policy，归入 scheduled 档。当前 scheduled 脚本的默认策略名仍为旧键 `motion`，因此需要显式指定 YAML 中实际存在的策略。

### 导出与数值对齐

仓库保留 [pt2onnx.py](https://github.com/spacemit-com/model_zoo_rl/blob/main/scripts/pt2onnx.py) 作为部分 PyTorch/TorchScript 策略的导出辅助工具；其中的结构识别和维度推断不能代替训练框架提供的导出契约，也不表示 C++ 运行时支持直接加载 `.pt`。

接入新策略时，用同一批真实观测序列对比训练端与 ONNX 的原始输出，再核对历史顺序、循环状态、归一化、动作裁剪和关节映射。随机输入测试只能检查执行链路，不能替代这一步。

## 4. Benchmark 工具与方法

| 工具 | 测量范围 | 不包含 |
| --- | --- | --- |
| `run_benchmark_onnx.sh` | synthetic 输入下的 ONNX Run，以及输入更新和 feedback copy 后的 backend step | 观测组装、关节映射、真实传感器数据 |
| `run_benchmark_policy.sh` | `AssembleObs → Infer → MapActionToTargetPos` 组件链路 | 传感器采样、跨进程通信和电机下发 |

`run_benchmark_policy.sh` 使用固定 synthetic robot state。当策略存在无默认值的 external input 或无法生成的 custom array 时，工具会在计时前拒绝；这类策略需使用能提供完整输入的集成或 replay runner 评测。

人形应用的 `policy_adapter`、异步推理线程和动作缓存不在上述组件 benchmark 内，应在[人形方案](/k3/reference-solutions/humanoid)的运行时层单独评测。

### 命令示例

```bash
cd output/staging/bin

# 组件链路：50 Hz 周期释放
./run_benchmark_policy.sh g1 walk_mjlab \
  --provider cpu --threads 2 --affinity 0,1 \
  --ort-spinning off \
  --mode periodic --hz 50 --rounds 1000 \
  --csv /tmp/g1_walk_mjlab.csv

# ONNX backend：背靠背吞吐
./run_benchmark_onnx.sh g1 walk_mjlab \
  --provider cpu --threads 2 --affinity 0,1 \
  --mode throughput --rounds 1000 \
  --csv /tmp/g1_walk_mjlab_backend.csv
```

### 关键参数

| 参数 | 说明 |
| --- | --- |
| `--warmup N` / `--rounds N` | 预热和正式统计轮数 |
| `--mode throughput\|periodic` | 背靠背吞吐测试或绝对时钟周期释放 |
| `--hz N` | periodic 目标频率；未指定时读取 YAML `rl_policy.rl_dt` |
| `--overrun drop\|backlog` | periodic 过载时丢弃过期 release 或保留 backlog |
| `--provider auto\|cpu\|spacemit` | ONNX Runtime provider |
| `--threads N` / `--affinity CPU_LIST` | 线程数和 Linux 进程 CPU affinity |
| `--ep-affinity CPU_LIST` | SpaceMIT EP affinity；CPU 数量必须等于 `--threads` |
| `--ort-spinning on\|off` | ONNX Runtime intra-op worker 空闲时是否 busy-spin |
| `--ep-dump-subgraphs` / `--ep-profile PREFIX` | 导出 SpaceMIT EP 子图或执行 profile |
| `--measure-start-delay-ms N` | START marker 后等待监控器，再开始计时 |
| `--csv PATH` | 保存逐轮原始数据 |
| `--verbose` | 计时结束后打印逐轮数据 |

`throughput` 只反映 service time 和吞吐，不用于得出实时性结论。`periodic` 记录 release jitter、service time、release-to-done response、deadline lateness、miss、drop 和 backlog。P99.99 至少需要 100000 轮，并必须保存 CSV。

CSV 不包含 warmup、rounds 和 overrun 等全部运行参数。正式报告应同时保存完整命令、stdout 和 CSV 原始样本，并记录实际 provider、线程、affinity、编译类型及板端运行条件。

### 指标含义

| 指标 | 含义 |
| --- | --- |
| Avg / Std | 平均延迟与标准差 |
| P50 / P95 / P99 | 50%、95%、99% 样本不超过的延迟 |
| Max | 本次样本中的最大延迟 |
| Miss | 超过周期 deadline 的样本数和比例 |

## 5. 结果记录与复测要求

旧版文档中的 K3 性能数字缺少原始 CSV、完整运行参数和可复现的模型键，且 benchmark 的计时口径已经调整，因此不再作为当前基线。发布新的性能结果时至少应记录：

- RL 组件版本、模型文件校验值和完整 YAML。
- 板卡、系统镜像、电源模式、编译类型及后台负载。
- 完整命令、stdout 和 CSV 原始样本。
- 实际 provider、线程、进程/EP affinity 和 EP 子图覆盖情况。
- Avg、P95、P99、Max、deadline miss，以及测试边界是 ONNX backend、组件链路还是整机闭环。

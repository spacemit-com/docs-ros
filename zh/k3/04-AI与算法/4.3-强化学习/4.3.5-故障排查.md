# 故障排查

## 1. 先确定问题所在层级

1. **模型文件**：使用 `test_onnx_infer` 检查 ONNX 能否加载和执行。
2. **配置与执行器**：使用 `test_policy_executor` 检查 `model_io`、观测组装和动作映射。
3. **策略数值**：逐项对齐训练端与 SDK 端的关节顺序、观测顺序、归一化、默认位、动作缩放和 PD 增益。
4. **仿真或实机系统**：再检查控制周期、传感器坐标、通信、驱动、动力学参数和安全逻辑。

不要用「模型能跑」排除数值契约问题，也不要用「仿真能跑」代替实机闭环验证。

## 2. 常见报错

| 现象 | 常见原因 | 处理 |
| --- | --- | --- |
| `配置文件不存在` | YAML 路径错误 | 使用从 SDK 根目录出发的路径，并确认机型目录名 |
| `策略 'xxx' 的配置不存在` | `rl_policy.onnx_infer.policies` 下没有该 key | 核对命令行中的 `policy_name` 和 YAML 策略名 |
| `ONNX 模型文件不存在` | `model_path` 错误或尚未下载策略 | 确认路径相对于 `robot_dir`，运行对应机型的模型下载脚本 |
| ONNX Runtime 未找到 | 依赖未安装或使用了错误路径 | 按快速开始安装依赖，或设置 `ONNXRUNTIME_DIR` |
| `model_io` 缺少、未绑定或重复绑定 | YAML 声明与 ONNX 实际 I/O 不一致 | 用 `test_onnx_infer` 打印张量名和 shape；逐一绑定输入，并确认每个输出有用途声明或被 feedback 引用 |
| `runtime.provider` 非法或后端不符合预期 | provider 值错误、应用配置覆盖或 EP 初始化失败 | YAML 仅支持 `auto/cpu/spacemit`；核对实际初始化信息，Benchmark 另按命令行选项确定后端 |
| `external 输入尚未设置且无默认值` | 首次推理前没有向上层输入数据 | 在 `Infer` 前调用 `SetModelInput`，或为该输入提供合法 `default` |
| 初始化时报观测段维度不匹配 | 观测 terms、历史长度或模型 observation 输入总维度不一致 | 按训练配置核对 `observation.segment_*`；不要用关闭 `strict_dim_check` 代替修正配置 |
| `Infer` 报观测维度错误 | 调用方传入的向量长度不等于 `ObsDim()` | 使用 `AssembleObs` 的完整输出，检查上层是否截断或重建观测向量 |
| `未知段模式` | 观测历史模式拼写错误 | 仅使用空值、`flat_history` 或 `frame_history` |
| action 维度或关节索引报错 | `action_joint_index`、`action_scale` 或全身关节数不一致 | 核对 ONNX action shape、机型关节顺序和映射数组 |

## 3. 模型能推理，但动作异常

优先核对以下内容：

- IMU 、基座姿态、关节位置和速度的坐标系、单位和正负方向。
- observation terms 的顺序、历史排列、`include_current` 和初始历史填充方式。
- observation term 拼写是否正确；未注册的名称会被当作一维自定义标量，未赋值时保持为零。
- `ang_vel_scale`、`dof_pos_scale`、`dof_vel_scale`、`clip_observations` 与训练配置是否一致。
- `rl_default_pos`、`action_scale`、`action_blend_ratio` 和 `action_joint_index` 是否对应同一份模型。
- 当前策略的 `kp/kd` 是否已由上层随控制命令下发，策略切换后是否同步更新。
- recurrent feedback 的执行器实例是否被每帧重建，external input 的刷新时机是否正确。

如果上述契约尚未逐项对齐，不建议通过放宽维度校验、改大 PD 增益或降低 `action_scale` 直接掩盖问题。

## 4. 延迟或尾延迟异常

- 确认 benchmark 是 `Release` 构建，并记录程序打印的编译参数。
- 区分 `throughput` 和 `periodic`；不要用背靠背吞吐数据代替周期响应。
- 同时记录 provider、线程数、CPU affinity、`ort-spinning`、预热和样本数。
- 使用 `--csv` 保留原始数据，不只依赖 Avg；检查 P95、P99、Max、release jitter 和 deadline miss。
- provider 为 `spacemit` 时，`--ort-spinning off` 只控制 ONNX Runtime intra-op 线程池，不能据此推断 SpaceMIT EP 的 worker 已停止 busy-spin。

基准命令、指标和测试边界见[模型验证与性能评测](4.3.4-模型验证与性能评测.md)。更完整的当前接口限制见 [RL 组件 README](https://github.com/spacemit-com/model_zoo_rl/blob/main/README.md)。

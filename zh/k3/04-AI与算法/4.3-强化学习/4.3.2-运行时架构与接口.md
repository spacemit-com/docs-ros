# 运行时架构与接口

<!-- TODO: 重绘 RL 数据流图，区分 YAML/model_io、观测历史、ONNX/feedback、动作处理与上层 PD 控制。 -->

RL 组件位于 [`components/model_zoo/rl`](https://github.com/spacemit-com/model_zoo_rl)，负责把机器人状态和外部输入转换为 ONNX 模型输入，并将模型输出处理为关节目标位置。组件不依赖具体机器人型号，机型差异由上层提供的模型、YAML 和关节映射描述。

## 1. 组件边界

```text
ONNX 模型 + YAML 策略契约
                 │
                 ▼
       配置解析 / 张量绑定
                 │
机器人状态 ─► 观测组装 ─┐
外部输入 ───────────────┼─► ONNX Runtime ─► action / expose / feedback
常量与反馈状态 ─────────┘                         │
                                                ▼
                                  裁剪与平滑 ─► 关节动作映射
```

主要代码位置如下：

```text
components/model_zoo/rl/
├── include/rl_service.h              # 公共数据结构和 C++ API
├── src/policy_config_loader.cpp      # YAML 策略配置解析
├── src/policy_executor.cpp           # 观测、推理和动作处理编排
├── src/obs_*.{h,cpp}                 # 观测项与历史组装
├── src/backends/onnx_infer.{h,cpp}   # ONNX Runtime 后端
├── example/                          # 功能测试与 benchmark
└── scripts/                          # benchmark wrapper 和模型辅助工具
```

## 2. 调用流程

对外头文件为 `include/rl_service.h`，链接库为 `librl.so`。

```cpp
#include "rl_service.h"
using namespace rl_policy;

// 1. 按策略名加载 YAML
LoadedPolicyConfig loaded_cfg =
    LoadPolicyConfigFromYaml(yaml_path, policy_name, robot_dir);

// 2. 初始化模型、张量绑定和观测组装器
PolicyExecutor policy;
policy.Init(loaded_cfg.exec_cfg);

// 3. 每个推理周期组装观测
Eigen::VectorXf obs;
policy.AssembleObs(gyro, rpy, cmd_vx, cmd_vy, cmd_wz,
                   joint_pos, joint_vel, base_quat, base_vel, dt, obs);

// 4. 推理并映射为全身关节目标位置
std::vector<double> action;
policy.Infer(obs, action);

std::vector<double> target_pos;
policy.MapActionToTargetPos(action, target_pos);
```

`PolicyExecutor` 不使用 `kp`、`kd`，也不负责把关节目标发送给机器人。配置加载器会将这些控制参数放入 `LoadedPolicyConfig`，由上层控制运行时使用。

## 3. 公共接口

| 接口 | 说明 |
| --- | --- |
| `LoadPolicyConfigFromYaml(yaml, name, robot_dir)` | 从 `rl_policy.onnx_infer.policies.<name>` 加载策略，返回执行器配置和上层控制参数 |
| `Init(cfg)` | 加载 ONNX，建立并校验全部 named tensor binding |
| `ObsDim()` / `ActionDim()` | 查询观测与动作维度 |
| `FeedbackStateCount()` / `HasObsHist()` | 查询自动反馈张量数量和模型级观测历史输入 |
| `GetRuntimeInfo()` | 查询实际初始化的 provider、线程和 SpaceMIT EP 状态 |
| `PrintModelInfo()` | 输出模型输入输出张量的名称、shape 和数据类型 |
| `SetCustomScalar(...)` / `GetCustomScalar(...)` | 写入或读取上层计算的自定义标量观测 |
| `SetCustomArray(...)` | 向观测项注入上层计算的数组 |
| `SetModelInput(...)` | 设置 `source: external` 的模型输入，支持 float 数组或原生 `TensorView` |
| `GetModelOutput(...)` / `GetModelOutputTensor(...)` | 读取 `target: expose` 的最近一次模型输出 |
| `AssembleObs(...)` | 按段计算、处理并拼接观测 |
| `Infer(obs, action)` | 按 `model_io` 绑定输入、执行推理和反馈回灌，返回裁剪及平滑后的动作 |
| `Infer(obs, action, &raw_action)` | 在返回处理后动作的同时，取得 ONNX action 的原始输出 |
| `RequestInferenceTermination()` | 请求 ONNX Runtime 中断推理，供上层停止异步推理线程使用 |
| `MapActionToTargetPos(...)` | 将动作按关节索引映射为全身目标位置 |

完整定义和示例见 [C++ 对外头文件](https://github.com/spacemit-com/model_zoo_rl/blob/main/include/rl_service.h) 与 [策略执行器示例](https://github.com/spacemit-com/model_zoo_rl/blob/main/example/test_policy_executor.cpp)。

## 4. 推理后端

`PolicyExecutorConfig.runtime` 支持以下运行参数：

| 参数 | 说明 |
| --- | --- |
| `provider` | `auto`、`cpu` 或 `spacemit` |
| `threads` | CPU intra-op 或 SpaceMIT EP 请求线程数 |
| `affinity` | 传给 SpaceMIT EP 的 CPU 列表 |
| `ort_spinning` | 是否允许 ONNX Runtime intra-op worker busy-spin |
| `ep_dump_subgraphs` | 是否导出 SpaceMIT EP 实际编译子图 |
| `ep_profile_prefix` | SpaceMIT EP profile 输出前缀 |

通用 YAML 加载器解析单策略 `runtime.provider`，支持 `auto`、`cpu`、`spacemit`；其余运行时字段目前通过 C++ 的 `loaded_cfg.exec_cfg.runtime` 在 `Init` 前设置。Benchmark 工具用自身命令行配置覆盖运行时选项，不直接继承 YAML 的 provider。

例如在 `rl_policy.onnx_infer.policies.<name>` 下配置：

```yaml
runtime:
  provider: cpu
```

x86_64 上的 `auto` 使用 CPU provider；RISC-V 上的 `auto` 会尝试注册 SpaceMIT EP，初始化失败时回退 CPU。显式请求 `spacemit` 时，EP 初始化失败会直接报错。EP 注册成功仍不代表全部算子都已分配给 EP，实际 provider 状态以 `GetRuntimeInfo()` 和程序日志为准，算子覆盖情况应通过 EP 子图导出确认。

## 5. 状态生命周期

一个 `PolicyExecutor` 实例会持续保存观测段历史、`observation_history`、feedback 张量、external 输入、最近一次 expose 输出和动作平滑状态。

- feedback 可由配置值初始化；未提供初值时使用零缓冲，之后由绑定的模型输出自动回灌。
- external 输入设置后持续有效，未配置默认值时必须在首次 `Infer` 前由上层设置。
- `GetModelOutputTensor()` 返回的 view 指向内部缓冲区，有效期到下一次 `Infer`。
- 重建执行器会清空上述运行状态；切换策略时应重新加载配置并初始化新实例。
- `RequestInferenceTermination()` 用于停止阶段，不是暂停接口，也不保证在固定时限内完成取消。上层须等待推理线程结束；需要继续推理时重新 `Init()`，以清除终止请求并重建状态。

策略选择、切换时机、前置策略链、控制增益下发和异常处置属于上层行为管理职责，不由 RL 组件调度。配置字段及张量契约见[策略配置与模型契约](4.3.3-策略配置与模型契约.md)。

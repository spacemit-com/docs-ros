# 快速开始

本页在已拉取 SpaceMIT Robot SDK 的前提下，编译 RL 组件并完成一次「YAML 配置加载 → 观测组装 → ONNX 推理 → 关节动作映射」的最短验证。SDK 的拉取和通用构建流程见 [2.3 构建编译](../../02-快速入门/2.3-构建编译.md)。

## 1. 环境准备

### x86_64 开发机

```bash
sudo apt install -y libeigen3-dev libyaml-cpp-dev cmake g++
```

x86_64 的 ONNX Runtime 由 CMake 处理，按以下顺序查找：

1. CMake 参数 `-DONNXRUNTIME_DIR=...`
2. 环境变量 `ONNXRUNTIME_DIR`
3. `/usr/local` 和 `/usr`
4. `~/.cache/thirdparty/onnxruntime/onnxruntime-linux-x64-1.21.0/`
5. 未命中时从 ONNX Runtime 官方 release 下载 `onnxruntime-linux-x64-1.21.0.tgz`

离线或受限网络环境应先准备 ONNX Runtime，并通过 `ONNXRUNTIME_DIR` 指向该目录。独立 CMake 构建还可传入 `-DSROBOTIS_THIRDPARTY_FETCH_OFF=ON`，禁止缺少依赖时自动下载；该选项是 CMake 参数，不是同名环境变量。

### K3 板卡

通过 SDK 构建时，`mm` 会根据 `package.xml` 检查组件依赖。手工准备最小 C++ 环境时安装：

```bash
sudo apt install -y libeigen3-dev libyaml-cpp-dev spacemit-onnxruntime
```

若系统已安装标准 `onnxruntime` 包并与 SpacemiT 定制包冲突，应先卸载该包；不要按某一版系统镜像写死动态库和 Python 包名。

## 2. 编译 RL 组件

在 SDK 根目录执行：

```bash
source build/envsetup.sh
cd components/model_zoo/rl
mm
```

本组件在单配置生成器下未显式指定 `CMAKE_BUILD_TYPE` 时默认使用 `Release`。编译后主要产物为：

| 产物 | 用途 |
| --- | --- |
| `output/staging/lib/librl.so` | RL 策略推理库 |
| `output/staging/bin/test_policy_executor` | 组件全链路功能测试 |
| `output/staging/bin/test_onnx_infer` | ONNX 后端单模型与批量扫描工具 |
| `output/staging/bin/benchmark_policy_executor` | 观测组装、推理和动作映射基准工具 |
| `output/staging/bin/benchmark_onnx_infer` | ONNX backend 基准工具 |

也可以不通过 SDK 构建系统，独立编译组件：

```bash
cmake -S components/model_zoo/rl -B /tmp/rl-build -DCMAKE_BUILD_TYPE=Release
cmake --build /tmp/rl-build -j
```

独立构建的产物保留在 `/tmp/rl-build`，不会自动安装到 SDK 的 `output/staging/`。

## 3. 准备策略资源

测试程序需要机型 YAML 和对应的 ONNX 模型。以 Unitree G1 的 `walk_mjlab` 策略为例，在 SDK 根目录执行：

```bash
SDK_ROOT=$(pwd) application/native/humanoid_unitree_g1/scripts/download_models_g1.sh
```

下载后，配置文件位于 `application/native/humanoid_unitree_g1/config/g1.yaml`，策略资源位于机型目录的 `policy/` 下。

## 4. 运行最短验证

回到 SDK 根目录：

```bash
./output/staging/bin/test_policy_executor \
  application/native/humanoid_unitree_g1/config/g1.yaml \
  walk_mjlab \
  application/native/humanoid_unitree_g1
```

命令格式为：

```text
test_policy_executor <yaml_path> <policy_name> <robot_dir>
```

程序会检查配置加载、模型 I/O 绑定、观测维度、多帧推理、动作维度和关节映射。最终输出「所有测试成功」表示 RL 组件内链路通过。

> 这一结果不包含 MuJoCo 物理仿真、K3 性能评测或实机控制。策略能否正确行走还需继续验证训练与 SDK 数值契约、仿真效果和真实硬件闭环。

要集成 C++ 运行时，继续阅读[运行时架构与接口](4.3.2-运行时架构与接口.md)；要接入新策略，阅读[策略配置与模型契约](4.3.3-策略配置与模型契约.md)；要单独检查模型或测量延迟，参考[模型验证与性能评测](4.3.4-模型验证与性能评测.md)。

# ROS2 相机传感器使用

## realsense 说明

### 安装必要依赖

```bash
sudo apt install udev cmake build-essential
```

安装 udev ，确保没有连接任何 realsense 设备

```bash
cd ~
wget https://archive.spacemit.com/ros2/prebuilt_libs/source_code_common/librealsense-2.57.4.tar.gz
tar xzvf librealsense-2.57.4.tar.gz
cd librealsense-2.57.4/
./scripts/setup_udev_rules.sh
cd ..
rm -rf librealsense-2.57.4 librealsense-2.57.4.tar.gz
```

深度相机建议使用 realsense D4xx 系列

humble 和 jazzy 的库是独立的，各自的版本不同，实际使用请注意区分

### humble

```bash
sudo apt install ros-humble-librealsense2
```

这是一个与 ros2 无关的c++库，对应 https://github.com/realsenseai/librealsense 仓库的 2.57.7 tag

```bash
# 可以查看库的安装位置
# 其中 cmake 导出文件在：/opt/ros/humble/lib/riscv64-linux-gnu/cmake/realsense2/
dpkg -L ros-humble-librealsense2
```

`realsense` 自带的 demo 安装在 `/opt/ros/humble/bin` 里面

**realsense ros2 sdk**

```bash
sudo apt install ros-humble-realsense2-camera
```

该包是对 ros-humble-librealsense2 的封装，对应 https://github.com/realsenseai/realsense-ros 仓库的 4.57.7 tag

### jazzy

```bash
sudo apt install ros-jazzy-realsense2-camera
```

这会安装 `ros-jazzy-librealsense2` 作为依赖包

**版本号:**

```bash
ros-jazzy-librealsense2 2.58.4
ros-jazzy-realsense2-camera 4.58.4
```



## Orbbec 说明

K3 平台可直接通过 deb 包使用 Orbbec 相机。软件包已包含相机驱动、Orbbec SDK、设备枚举工具、launch 文件和 udev 规则，无需下载源码或创建 `orbbec_ws` 工作空间。以下以 ROS2 Humble 和 USB 连接的 **Orbbec Gemini 335** 为例。

### 安装软件包

先按 [ROS2 安装](6.6.1-ROS2-INSTALL.md) 完成软件源配置和 ROS2 环境安装，然后执行：

**Humble**

```bash
sudo apt update
sudo apt install ros-humble-orbbec-camera udev
source /opt/ros/humble/setup.bash
```

 安装 udev 规则：

```bash
sudo install -m 644 \
  /opt/ros/humble/share/orbbec_camera/udev/99-obsensor-libusb.rules \
  /etc/udev/rules.d/99-obsensor-libusb.rules
sudo udevadm control --reload-rules
sudo udevadm trigger
```

**Jazzy**

```
sudo apt update
sudo apt install ros-jazzy-orbbec-camera udev
source /opt/ros/jazzy/setup.bash
```

 安装 udev 规则：

```bash
sudo install -m 644 \
  /opt/ros/jazzy/share/orbbec_camera/udev/99-obsensor-libusb.rules \
  /etc/udev/rules.d/99-obsensor-libusb.rules
sudo udevadm control --reload-rules
sudo udevadm trigger
```

完成后重新插拔相机，以普通用户运行后续 ROS2 命令。建议使用 USB 3.x 数据线和接口。

后文的 DISTRO 按照实际使用的 ROS2 版本填写

### 检查相机和支持的配置

在启动相机节点之前，先确认设备能够被识别，并枚举支持的分辨率、格式、帧率及 IMU 配置：

```bash
ros2 run orbbec_camera list_devices_node
ros2 run orbbec_camera list_camera_profile_mode_node
```

Gemini 335 的设备信息应包含 `Orbbec Gemini 335`、序列号、连接方式和固件版本。本文验证设备通过 `USB3.2` 连接，固件版本为 `1.4.60`，支持后文使用的640×480 彩色 MJPG、深度 Y16 以及 200 Hz 加速度计/陀螺仪配置。

### 启动 Gemini 335

deb 包已经安装了适用于 K3 的 `gemini_335_vslam.launch.py`，可直接启动：

```bash
ros2 launch orbbec_camera gemini_335_vslam.launch.py
```

命令在前台运行，使用 `Ctrl+C` 停止。该 launch 文件的默认配置如下：

| 项目 | 默认配置 |
| --- | --- |
| 彩色图像 | 640×480、30 FPS，设备侧格式 MJPG |
| 深度图像 | 640×480、30 FPS，格式 Y16，软件对齐到彩色图像 |
| 图像同步 | 启用帧同步，使用 `full_frame` 聚合 |
| IMU | 加速度计 200 Hz / 4g，陀螺仪 200 Hz / 1000 dps，合并输出 |
| 时间戳 | 启用主机时间同步，使用 `global` 时间域 |
| 标定与坐标变换 | 发布 CameraInfo、静态 TF 和外参 |
| 点云 | 关闭普通点云和彩色点云，减少 CPU 开销和话题传输带宽占用 |

可通过以下命令查看该启动文件支持的参数：

```bash
ros2 launch orbbec_camera gemini_335_vslam.launch.py --show-args
```

已安装的启动文件位于`/opt/ros/DISTRO/share/orbbec_camera/launch/gemini_335_vslam.launch.py`，可查看其具体配置，无需手工创建该文件。如需修改分辨率或其他节点参数，可将启动文件复制到用户目录后修改，再通过 `ros2 launch /绝对路径/文件名.launch.py` 运行，避免包升级覆盖自定义配置。

### 验证数据输出

保持相机 launch 运行，在另一个终端加载环境并查看话题：

```bash
source /opt/ros/DISTRO/setup.bash
ros2 topic list
```

使用默认 `camera_name:=camera` 时，主要输出如下：

| 话题 | 类型 | 内容 |
| --- | --- | --- |
| `/camera/color/image_raw` | `sensor_msgs/msg/Image` | 彩色图像 |
| `/camera/depth/image_raw` | `sensor_msgs/msg/Image` | 对齐到彩色图像的深度图像 |
| `/camera/color/camera_info` | `sensor_msgs/msg/CameraInfo` | 彩色相机标定参数 |
| `/camera/depth/camera_info` | `sensor_msgs/msg/CameraInfo` | 深度图像对应的标定参数 |
| `/camera/gyro_accel/sample` | `sensor_msgs/msg/Imu` | 合并的加速度计和陀螺仪数据 |
| `/tf_static` | `tf2_msgs/msg/TFMessage` | 相机各坐标系之间的静态变换 |

本节配置下，彩色图像的 ROS 编码为 `rgb8`，深度图像为 `16UC1`；两路图像及其 CameraInfo 的 `frame_id` 均为 `camera_color_optical_frame`。

分别执行以下命令检查数据频率，每条命令使用 `Ctrl+C` 退出后再执行下一条：

```bash
ros2 topic hz /camera/color/image_raw
ros2 topic hz /camera/depth/image_raw
ros2 topic hz /camera/gyro_accel/sample
```

`ros2 topic hz` 显示的是当前订阅端实际接收频率，可能受 CPU 负载和订阅开销影响。彩色/深度图像及其 CameraInfo 使用 `SENSOR_DATA` QoS，自定义订阅程序或可视化工具应选择兼容的 QoS，例如 `best_effort` 可靠性。

可通过服务查询设备信息和 SDK 版本：

```bash
ros2 service call /camera/get_device_info orbbec_camera_msgs/srv/GetDeviceInfo '{}'
ros2 service call /camera/get_sdk_version orbbec_camera_msgs/srv/GetString '{}'
```

若修改了 `camera_name`，需将上述话题及服务中的 `/camera` 前缀替换为对应名称。

### RISC-V 使用限制与排查

当前 RISC-V deb 包不包含厂商闭源库 `libob_frame_processor.so`。Gemini 335 的定制启动文件已使用 `depth_registration=true`、`align_mode=SW` 和`align_target_stream=COLOR`，通过软件将深度图像对齐到彩色图像，并精简了传入节点的参数。启动日志可能提示缺少该库或使用透传处理，可结合图像、IMU 和服务输出判断是否正常运行。

当前 K3 使用流程只验证了 Gemini 335。deb 包还包含其他型号的 launch 文件，可查看已安装的入口：

```bash
ls /opt/ros/humble/share/orbbec_camera/launch/
```

其他 Gemini 330 系列可参考 `gemini_335_vslam.launch.py` 的精简参数和软件对齐方式，但应先枚举目标设备的 profile，逐项验证彩色、深度、对齐及 IMU 输出。GMSL 和以太网型号还需要各自的驱动或网络配置，不能直接套用 USB 配置。如果深度解码、视差转换或必要滤波必需依赖当前 RISC-V 包缺少的闭源扩展，则无法运行。

# 定位导航 · ORB-SLAM3

## 1. 模块概述

- **主要功能**：`orbslam3_run` 基于 ORB-SLAM3 封装 ROS 2 RGB-D 视觉里程计与稀疏地图构建节点。在本项目中，它位于 `middleware/ros2/slam/orbslam3_run`，接收同步的彩色图和对齐深度图，发布机器人位姿、轨迹、跟踪状态及稀疏地图点。
- **规格或特性**：
	- 算法形态：RGB-D 视觉里程计、RGB-D 稀疏 SLAM；
	- 输入分辨率：仅支持 640×480，不在节点内部缩放图像；
	- 推荐帧率：15 FPS；
	- 支持相机：默认配置为 Intel RealSense D455，同时提供 D415 配置；
	- 里程计输出：三维里程计、二维平面里程计和跟踪状态；
	- 建图输出：全局位姿、轨迹、稀疏地图点和跟踪状态；
	- 建图结果：支持保存 ORB-SLAM3 Atlas 和 TUM 格式轨迹；
	- K3 优化：默认启用 SpacemiT RVV 1.0 编译选项。
- **处理流程**：

```text
RealSense RGB-D 相机
        │
        ├── /camera/color/image_raw (640×480)
        └── /camera/aligned_depth_to_color/image_raw (640×480)
                         │
                         ▼
                   orbslam3_run
                    ├── 视觉里程计：odom / odom_2d / tracking_state
                    └── 稀疏建图：pose / path / map_points / Atlas
```

- **相关目录结构**：

| 路径 | 职责 |
| --- | --- |
| `middleware/ros2/slam/orbslam3_run/launch/rgbd_odometry.launch.py` | RGB-D 视觉里程计启动入口 |
| `middleware/ros2/slam/orbslam3_run/launch/rgbd_slam.launch.py` | RGB-D 稀疏建图启动入口 |
| `middleware/ros2/slam/orbslam3_run/config/d455_rgbd.yaml` | D455 里程计配置 |
| `middleware/ros2/slam/orbslam3_run/config/d455_rgbd_slam.yaml` | D455 建图配置 |
| `middleware/ros2/slam/orbslam3_run/config/d415_rgbd.yaml` | D415 里程计配置 |
| `middleware/ros2/slam/orbslam3_run/config/d415_rgbd_slam.yaml` | D415 建图配置 |
| `middleware/ros2/slam/orbslam3_run/README.md` | 模块说明和快速使用方法 |

## 2. 环境准备

### 2.1 前置条件

- **代码获取**：

  SDK 源码获取和基础编译环境配置统一参考 [Linksee 参考方案](../../03-参考方案/3.2-轮式机器人Linksee.md)。完成 SDK 初始化后，回到本文继续操作。

- **运行环境**：
	- K3 系列开发板和 Bianbu 2.6；
	- ROS 版本：ROS 2 Humble；
	- RGB-D 相机：Intel RealSense D455 或 D415；
	- 彩色图和对齐深度图必须同时为 640×480。

- **安装编译与运行依赖**：

```bash
sudo apt update
sudo apt install git cmake ninja-build build-essential patchelf \
  libeigen3-dev opencv-spacemit=4.14.0-2bb4 \
  libboost-serialization-dev libssl-dev libsuitesparse-dev \
  libglew-dev libepoxy-dev libx11-dev libwayland-dev \
  libjpeg-dev libpng-dev libtiff-dev wget
```

[RealSense 包安装参考](../../06-系统与平台/6.6-ROS2/6.6.1-ROS2-INSTALL.md)

- **安装 K3 RVV 版本 ORB-SLAM3**：

```bash
wget https://archive.spacemit.com/ros2/prebuilt_libs/bianbu26/opt/ext/orbslam3_rvv/4452a3c4ab75b1cde34e5505a36ec3f9edcdc4c4/orbslam3.tar.gz
sudo tar xzf orbslam3.tar.gz -C /opt
echo /opt/orbslam3/lib | sudo tee /etc/ld.so.conf.d/orbslam3.conf
sudo ldconfig
```

安装后检查关键文件：

```bash
test -f /opt/orbslam3/share/orbslam3/ORBvoc.txt && echo "ORB vocabulary ready"
test -f /opt/orbslam3/lib/libORB_SLAM3.so && echo "ORB-SLAM3 library ready"
```

- **环境变量与初始化**：

```bash
source ~/spacemit_robot/output/staging/setup.bash
```

- **硬件与连接**：
	- 相机应固定牢靠，并保证视野无遮挡；
	- 建议使用 USB 3.x 连接。USB 带宽受限时仍须保证彩色和深度流均为 640×480@15；
	- 彩色图与深度图必须时间同步，深度图必须对齐到彩色图；
	- 当前节点中的相机安装外参按照现有 D455 机器人安装方式设置。改变安装位置或朝向后，需要同步调整外参。

### 2.2 构建编译

- **SDK 全量编译**：

```bash
cd ~/spacemit_robot
source build/envsetup.sh
lunch # 选择对应的 K3 产品配置
m
```

- **单独使用 colcon 编译**：

```bash
cd ~/spacemit_robot
source /opt/ros/humble/setup.bash
colcon build --packages-select orbslam3_run \
  --cmake-args -DCMAKE_BUILD_TYPE=Release
source install/setup.bash
```

非 RISC-V 主机仅用于代码调试时，需要关闭默认 RVV 编译选项：

```bash
colcon build --packages-select orbslam3_run \
  --cmake-args -DCMAKE_BUILD_TYPE=Release -DORB_SLAM3_USE_RVV=OFF
```

- **产物说明**：
	- SDK 构建产物默认位于 `~/spacemit_robot/output/staging/`；
	- 单独构建产物位于 `install/orbslam3_run/`；
	- ORB-SLAM3 库、Pangolin 和词袋文件默认从 `/opt/orbslam3` 加载；
	- 若依赖安装在其他目录，构建和运行前需设置 `ORB_SLAM3_PREFIX`。

## 3. 示例使用

本节以 RealSense D455 的 640×480@15 数据流为例。各终端均需先加载运行环境：

```bash
source ~/spacemit_robot/output/staging/setup.bash
```

**步骤 1：启动 RGB-D 相机**

```bash
ros2 launch realsense2_camera rs_launch.py camera_namespace:=/ \
  enable_color:=true enable_depth:=true \
  rgb_camera.color_profile:=640,480,15 \
  depth_module.depth_profile:=640,480,15 \
  align_depth.enable:=true enable_sync:=true
```

**预期现象**：以下两个 640×480 图像话题持续发布，且时间戳接近：

- `/camera/color/image_raw`
- `/camera/aligned_depth_to_color/image_raw`

可在新终端检查图像频率：

```bash
ros2 topic hz /camera/color/image_raw
ros2 topic hz /camera/aligned_depth_to_color/image_raw
```

**步骤 2：运行视觉里程计**

```bash
ros2 launch orbslam3_run rgbd_odometry.launch.py
```

**预期现象**：节点完成词袋加载后等待同步图像；相机移动且跟踪正常时，`/orbslam3/odom` 和 `/orbslam3/odom_2d` 持续发布，跟踪状态为 `2`。

```bash
ros2 topic echo /orbslam3/tracking_state --once
ros2 topic hz /orbslam3/odom
ros2 topic echo /orbslam3/odom_2d --once
```

里程计模式默认不发布 TF。需要发布 `orb_odom -> base_footprint` 时执行：

```bash
ros2 launch orbslam3_run rgbd_odometry.launch.py publish_tf:=true
```

**步骤 3：运行 SLAM 建图**

停止里程计节点后启动建图节点，避免两个 ORB-SLAM3 实例重复处理相机数据：

```bash
ros2 launch orbslam3_run rgbd_slam.launch.py
```

**预期现象**：跟踪正常时开始发布当前位姿、轨迹与稀疏地图点，并默认发布 `orb_map -> base_footprint` TF。

```bash
ros2 topic echo /orbslam3_slam/tracking_state --once
ros2 topic hz /orbslam3_slam/pose
ros2 topic echo /orbslam3_slam/map_points --once
```

**步骤 4：保存建图结果**

结束采集后，在退出建图节点前调用：

```bash
ros2 service call /orbslam3_slam/finish_mapping std_srvs/srv/Trigger '{}'
```

默认保存目录为 `~/.ros/orbslam3_slam`，主要输出如下：

| 文件 | 说明 |
| --- | --- |
| `orbslam3_atlas.osa` | ORB-SLAM3 Atlas |
| `CameraTrajectory.txt` | TUM 格式相机轨迹 |
| `KeyFrameTrajectory.txt` | TUM 格式关键帧轨迹 |

调用完成服务后，节点仍保持运行，但不再处理新图像。确认文件保存成功后再退出节点。

**使用 D415 配置**

D415 必须使用对应的相机内参文件：

```bash
ros2 launch orbslam3_run rgbd_odometry.launch.py \
  settings:=$(ros2 pkg prefix orbslam3_run)/share/orbslam3_run/config/d415_rgbd.yaml

ros2 launch orbslam3_run rgbd_slam.launch.py \
  settings:=$(ros2 pkg prefix orbslam3_run)/share/orbslam3_run/config/d415_rgbd_slam.yaml
```

## 4. 应用开发

- **视觉里程计接口**：

| 接口 | 类型 | 说明 |
| --- | --- | --- |
| `/camera/color/image_raw` | `sensor_msgs/Image` | 640×480 彩色图输入 |
| `/camera/aligned_depth_to_color/image_raw` | `sensor_msgs/Image` | 640×480 对齐深度图输入 |
| `/orbslam3/odom` | `nav_msgs/Odometry` | 保留完整三维位姿的里程计 |
| `/orbslam3/odom_2d` | `nav_msgs/Odometry` | 仅保留 x、y 和 yaw 的二维里程计 |
| `/orbslam3/tracking_state` | `std_msgs/UInt8` | 跟踪状态，值为 `2` 表示正常 |

- **SLAM 建图接口**：

| 接口 | 类型 | 说明 |
| --- | --- | --- |
| `/orbslam3_slam/pose` | `geometry_msgs/PoseStamped` | 当前全局位姿 |
| `/orbslam3_slam/path` | `nav_msgs/Path` | 当前建图轨迹 |
| `/orbslam3_slam/map_points` | `sensor_msgs/PointCloud2` | 当前跟踪到的稀疏地图点 |
| `/orbslam3_slam/tracking_state` | `std_msgs/UInt8` | 跟踪状态，值为 `2` 表示正常 |
| `/orbslam3_slam/finish_mapping` | `std_srvs/srv/Trigger` | 结束建图并保存结果 |
| `/orbslam3_slam/reset_map` | `std_srvs/srv/Trigger` | 清空当前活动地图并重新建图 |

- **常用启动参数**：

| 参数 | 适用入口 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `vocabulary` | 两者 | `/opt/orbslam3/share/orbslam3/ORBvoc.txt` | ORB 词袋文件 |
| `settings` | 两者 | D455 对应配置 | 相机和 ORB-SLAM3 参数文件 |
| `publish_tf` | 两者 | 里程计 `false`，建图 `true` | 是否发布位姿 TF |
| `color_topic` | 两者 | `/camera/color/image_raw` | 彩色图输入话题 |
| `depth_topic` | 两者 | `/camera/aligned_depth_to_color/image_raw` | 对齐深度图输入话题 |
| `odom_frame` | 里程计 | `orb_odom` | 里程计坐标系 |
| `map_frame` | 建图 | `orb_map` | 地图坐标系 |
| `base_frame` | 两者 | `base_footprint` | 机器人基座坐标系 |
| `save_directory` | 建图 | `~/.ros/orbslam3_slam` | Atlas 和轨迹保存目录 |
| `map_publish_period` | 建图 | `1.0` | 地图点发布周期，单位为秒 |
| `max_path_poses` | 建图 | `10000` | 轨迹保留的最大位姿数量 |

查看全部启动参数及默认值：

```bash
ros2 launch orbslam3_run rgbd_odometry.launch.py --show-args
ros2 launch orbslam3_run rgbd_slam.launch.py --show-args
```

- **调用方式与注意点**：
	- 配置文件中的相机内参必须与实际相机、分辨率和图像流匹配；
	- 本模块不会把稀疏视觉地图转换为二维占据栅格。Nav2 的障碍物层应继续使用深度点云或激光雷达；
	- 系统中只能有一个节点发布同一组父子 TF，避免与其他里程计或定位模块产生冲突；
	- 更换相机安装位置后，应重新标定并修改机器人基座到相机光学坐标系的外参；
	- 地图点话题使用 transient local、reliable QoS，可视化订阅端需使用兼容的 QoS。

## 5. 调试指南

- **确认图像尺寸与频率**：

```bash
ros2 topic echo /camera/color/image_raw --field width --once
ros2 topic echo /camera/color/image_raw --field height --once
ros2 topic echo /camera/aligned_depth_to_color/image_raw --field width --once
ros2 topic echo /camera/aligned_depth_to_color/image_raw --field height --once
```

  四项结果应依次为 `640`、`480`、`640`、`480`。若输入尺寸不匹配，节点会周期性报告 `ORB-SLAM3 expects 640x480 RGB-D images`。

- **确认图像同步与对齐**：
	- 彩色图与深度图尺寸必须一致；
	- 相机驱动必须启用 `align_depth.enable:=true` 和 `enable_sync:=true`；
	- 两路图像频率波动过大时，优先检查 USB 带宽、供电和连接线。

- **确认 ORB-SLAM3 依赖**：

```bash
ldconfig -p | grep ORB_SLAM3
ls -l /opt/orbslam3/share/orbslam3/ORBvoc.txt
```

  若使用非默认安装位置，在编译和运行终端中设置：

```bash
export ORB_SLAM3_PREFIX=/path/to/orbslam3
```

- **跟踪质量排查**：
	- `tracking_state` 为 `2` 表示正常跟踪；
	- 若长时间无法进入状态 `2`，检查场景纹理、照明、运动速度和深度有效范围；
	- 避免相机快速旋转、镜头遮挡以及面对大面积白墙或玻璃；
	- D415 和 D455 不可混用参数文件，其他相机需要重新标定并创建配置。

- **TF 与位姿排查**：
	- 里程计模式只有设置 `publish_tf:=true` 才发布 TF；
	- 建图模式默认发布 `orb_map -> base_footprint`；
	- 若机器人模型位置或运动方向错误，重点检查相机安装外参和 `base_frame`；
	- 与其他定位节点联合使用时，检查是否存在重复 TF 发布者。

## 6. 常见问题

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 编译提示只能在 RISC-V 上启用 RVV | 在 x86 主机使用了默认编译选项 | 添加 `-DORB_SLAM3_USE_RVV=OFF`；K3 板端保持默认值 |
| CMake 找不到 ORB-SLAM3 或 Pangolin | `/opt/orbslam3` 未安装或安装不完整 | 重新安装预编译包，或通过 `ORB_SLAM3_PREFIX` 指定正确前缀 |
| 启动时找不到 `ORBvoc.txt` | 词袋文件缺失或依赖前缀错误 | 检查 `/opt/orbslam3/share/orbslam3/ORBvoc.txt`，必要时覆盖 `vocabulary` 参数 |
| 持续报告图像尺寸错误 | 相机未按 640×480 启动 | 同时设置彩色和深度 profile 为 640×480，并重启相机驱动 |
| 报告彩色图与深度图尺寸不同 | 深度未对齐到彩色图，或两路 profile 不一致 | 启用 `align_depth.enable`，确认两个输入话题尺寸一致 |
| 跟踪状态始终不为 `2` | 参数文件不匹配、场景纹理不足、光照差或运动过快 | 选择正确的 D415/D455 配置，改善场景和运动条件 |
| 有里程计话题但没有 TF | 里程计模式默认关闭 TF 发布 | 启动时增加 `publish_tf:=true`，并确认没有其他节点发布冲突 TF |
| 建图服务返回成功但找不到文件 | 使用了自定义保存目录或目录权限不足 | 检查 `save_directory` 参数以及目标目录写权限 |
| RViz 无二维栅格地图 | ORB-SLAM3 输出的是稀疏地图点 | 显示 `/orbslam3_slam/map_points`，二维代价地图使用深度点云或激光雷达构建 |

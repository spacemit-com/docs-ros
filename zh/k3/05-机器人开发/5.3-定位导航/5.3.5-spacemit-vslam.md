# 定位导航 · SpacemiT VSLAM

## 1. 模块概述

SpacemiT VSLAM 是 Robot SDK 中面向 K3 的双目定位与三维建图应用。它从双目画面估计相机位姿（VO），也可以融合相机内嵌的 IMU 数据（VIO）。LAS2 从左右图计算以米为单位的深度，并输出与深度对齐的左目彩色图。建图模块融合深度和图像时刻位姿，生成彩色 TSDF 表面和 ESDF 距离切片，供桌面窗口实时显示。

本文运行的是双目 VIO 与实时重建示例。桌面入口默认关闭回环和位姿图优化；窗口显示 `VIO` 表示已进入视觉惯性跟踪。定位库暂不支持保存定位地图或加载地图后重定位。

```text
双目 UVC 相机（内嵌曝光时间戳和 IMU）
  └─ camera_io
       ├─ vio：图像时刻位姿 ──┐
       └─ las2：深度和对齐 RGB ┴─→ esdf_drm：TSDF / ESDF → 桌面窗口
```

项目位于 SDK 的 `middleware/ros2/slam/spacemit-vslam`。主要目录如下：

| 目录 | 职责 |
| --- | --- |
| `modules/camera/` | 相机元数据解析、标定和时间对齐 |
| `modules/vslam/` | 定位库的公开头文件、CMake 配置和 K3 预编译库 |
| `modules/mapping/` | 建图与渲染库的公开头文件、CMake 配置和 K3 预编译库 |
| `src/camera_io/` | ROS 2 相机接入、图像与 IMU 发布、录制和回放 |
| `src/vio/` | 双目 VO/VIO，发布位姿、轨迹、特征和跟踪状态 |
| `src/las2/` | 调用 SDK 的 `stereo_matching`，发布深度与对齐 RGB 描述符 |
| `src/esdf_drm/` | 配对深度与位姿、更新 TSDF/ESDF、渲染和桌面显示 |
| `src/common/` | 深度和特征消息、生命周期工具 |
| `src/bringup/` | 桌面、录制和回放的启动入口 |

## 2. 环境与编译

以下命令在 K3 板端执行。SDK 的获取和基础环境见 [2.3 构建编译](../../02-快速入门/2.3-构建编译.md)。

| 项目 | 要求 |
| --- | --- |
| 系统 | K3、Bianbu 4.0.1、ROS 2 Humble |
| 运行库 | OpenCV 4.10（`libopencv_*.so.410`）、与镜像匹配的 MPP 库和插件、OpenCL 及 EGL/GLES/DRM 图形栈 |
| 相机与标定 | 支持内嵌曝光时间戳与 IMU 的双目 UVC 相机，以及对应实体相机的 Kalibr 标定。普通 UVC 相机的图像流不包含本示例所需的元数据。 |
| 桌面与权限 | 已登录 X11 或 Xwayland 桌面；运行账号能访问相机、MPP、DMA-BUF、GPU 等硬件资源。 |

从 SDK 根目录加载构建环境，再进入模块目录：

```bash
cd "$HOME/spacemit_robot"
source build/envsetup.sh
cd middleware/ros2/slam/spacemit-vslam
mm --with-deps
```

`mm --with-deps` 构建 Camera 模块、ROS 2 包和配套的 MPP、LAS2、IMU 依赖。VSLAM 和 Mapping 使用随项目提供的 K3 Linux RISC-V 64 位库，安装前会校验。缺少系统依赖时按 SDK 提示处理。默认产物在 SDK 的 `output/staging`。如果 SDK 不在上述目录，将 `cd` 中的路径换成实际位置。

LAS2 推理运行库随 SDK 组件提供，应用构建会安装所需文件；无需单独下载 ONNX Runtime 或 SpacemiT EP。深度模型在运行前下载，编译时无需提供模型。

## 3. 运行桌面示例

### 3.1 下载 LAS2 深度模型

使用运行应用的账号下载模型。桌面脚本默认从该账号的 `~/.cache/models/vision/` 加载它。下面的命令在 SHA-256 校验通过后才写入默认文件名：

```bash
model_path="$HOME/.cache/models/vision/LAS2_M_288x384.fp16.onnx"
mkdir -p "$(dirname "$model_path")"
wget -O "$model_path.part" \
  https://archive.spacemit.com/spacemit-ai/model_zoo/vision/stereo_depth/LAS2_M_288x384.fp16.onnx &&
printf '%s  %s\n' aa4f22f0f2433dc317ae3fa028549b9e228200c117d95121e19cfa0f1615145a "$model_path.part" |
  sha256sum -c - &&
mv -- "$model_path.part" "$model_path"
```

这是 VSLAM 使用的 ExternalStereo 模型。LAS2 原有的左右图片 demo 输出视差图，使用另一份同名的 tensor 模型。单独运行该 demo 时，按 [Stereo Matching 指南](https://github.com/spacemit-robotics/perception/blob/main/stereo_matching/README.md) 的“运行图片 demo”小节下载对应模型。

### 3.2 准备相机与标定

项目使用 DECXIN USB/UVC 双目广角相机。单目分辨率为 1920×1200，双目打包输出为 4000×1200，支持 MJPEG 30/60 fps。相机内置六轴 IMU，图像流携带曝光时间戳和 IMU 数据。

默认配置 `src/camera_io/config/usb_stereo_4000x1200.json` 使用 `/dev/video9`，采集 4000×1200 的双目打包 MJPEG，每路输出 640×400。桌面脚本默认以 30 FPS 采集。设备路径和随包提供的 `0.yaml` 仅对应示例配置，运行前应核对设备并使用当前实体相机的标定。

在板端用 `v4l2-ctl --list-devices` 查看设备，再用 `v4l2-ctl -d /dev/videoX --list-formats-ext` 确认采集节点支持的模式；将 `/dev/videoX` 换成查到的设备。复制示例 JSON 到用户配置目录：

```bash
config_dir="$HOME/spacemit-vslam-config"
mkdir -p "$config_dir"
cp "$HOME/spacemit_robot/middleware/ros2/slam/spacemit-vslam/src/camera_io/config/usb_stereo_4000x1200.json" \
  "$config_dir/camera.json"
```

将实机 Kalibr 标定保存为 `$config_dir/calibration.yaml`，然后在 `camera.json` 中核对以下配置：

| 配置项 | 检查内容 |
| --- | --- |
| `camera.device` | 实际图像采集设备。有 `/dev/v4l/by-id/` 路径时优先使用。 |
| `camera.width`、`camera.height`、`camera.fps` | 使用相机支持的采集模式。运行桌面示例时，脚本的 `camera_fps` 参数覆盖 JSON 中的帧率。 |
| `streams.left/right.crop`、`streams.left/right.output` | 裁剪区域与物理左右目及原始标定一致。更改输出尺寸时，同时传入对应的 `image_width` 和 `image_height`。 |
| `calibration.file` | 填写 `calibration.yaml`；相对路径以 JSON 所在目录为基准。相机、VIO 和 LAS2 使用同一份双目标定。 |
| `timestamp.source`、`metadata.region`、`imu.samples_per_frame` | 与相机内嵌元数据协议一致。示例配置使用曝光中点时间戳和每帧 10 个 IMU 样本。 |

Kalibr 的 `cam0`、`cam1` 对应物理左目、右目，标定分辨率对应缩放前的单目裁剪尺寸。程序根据输出尺寸缩放相机内参，畸变参数和刚体外参保持原值。VIO 还需要相机与 IMU 的外参及 `imu0` 中的噪声参数；如单独保存 IMU 标定，启动时追加 `imu_calibration_file:="$config_dir/imu.yaml"`。如果标定包含 `cam0.timeshift_cam_imu`，程序用它校正 VIO 的 IMU 时间戳，保留原始曝光时间戳。

### 3.3 启动并检查输出

在已登录的板端桌面终端中加载 SDK 运行环境，使用上一步配置启动：

```bash
cd "$HOME/spacemit_robot"
source build/envsetup.sh
sros2_setup
config_dir="$HOME/spacemit-vslam-config"
ros2 run bringup run_vslam_desktop.sh \
  camera_config_file:="$config_dir/camera.json" \
  calibration_file:="$config_dir/calibration.yaml"
```

设备及标定与 SDK 内置示例一致时，可以直接执行 `ros2 run bringup run_vslam_desktop.sh`。窗口默认 1280×720；追加 `desktop_fullscreen:=true` 可全屏，追加 `model_path:=/实际路径/模型.onnx` 可指定其他模型存放位置。

相机默认等待 LAS2 初始化。出图后，在有纹理且光照稳定的场景中缓慢平移并小幅转动相机，直到跟踪状态显示 `VIO`。窗口可查看相机画面、彩色深度、轨迹、TSDF 表面以及重力对齐的 ESDF 切片。按 `Ctrl+C` 结束运行。

需要从 ROS 2 检查时，在另一个终端从 SDK 根目录执行 `source build/envsetup.sh` 和 `sros2_setup`，并使用同一 `ROS_DOMAIN_ID`。以下命令逐条执行，每条 `hz` 命令可用 `Ctrl+C` 停止：

```bash
ros2 node list
ros2 topic hz /camera/left/frame_desc
ros2 topic hz /las2/depth_desc
ros2 topic hz /vio/pose/image
ros2 topic echo /vio/tracking_mode --qos-reliability best_effort --once
```

`ros2 topic hz` 是当前订阅端测得的频率，可用来确认数据是否持续到达。通过 `ros2 launch bringup vio_las2_esdf_launch.py --show-args` 查看完整启动参数。录制和回放见 [spacemit-vslam README](https://github.com/spacemit-robotics/ros2_spacemit_vslam/blob/main/README.md)。

## 4. 开发接口

### 4.1 ROS 2 话题

| 默认话题 | 消息类型 | 用途 |
| --- | --- | --- |
| `/camera/left/frame_desc`、`/camera/right/frame_desc` | `mpp_msgs/msg/MppVideoFrameDesc` | 左右目 NV12 图像描述符 |
| `/camera/left/camera_info`、`/camera/right/camera_info` | `sensor_msgs/msg/CameraInfo` | 与输出分辨率对应的相机内参 |
| `/camera/imu/data_raw` | `sensor_msgs/msg/Imu` | 原始 IMU 数据 |
| `/vio/pose/image` | `nav_msgs/msg/Odometry` | 图像时刻位姿，供建图等下游按时间戳配对 |
| `/vio/trajectory` | `nav_msgs/msg/Path` | 位姿轨迹 |
| `/vio/tracking_mode` | `std_msgs/msg/String` | 跟踪状态 |
| `/vio/features` | `common/msg/FeaturePointArray` | 跟踪特征 |
| `/las2/depth_desc` | `common/msg/DmaDepthFrameDesc` | 深度、对齐 RGB 和标定信息 |
| `/esdf/render/frame_desc` | `mpp_msgs/msg/MppVideoFrameDesc` | 供桌面窗口显示的合成帧 |

图像和深度像素保存在 DMA-BUF 中，ROS 2 传递缓冲区描述符和元数据。读取像素时，用 `VB_Import()` 导入描述符中的 token；每次成功导入后都用 `VB_ReleaseBuffer()` 释放对应引用。保留源时间戳、帧号、尺寸、步幅、像素格式和标定；共享输入按只读处理，下游使用有界队列。桌面入口默认关闭高频位姿外推，`/vio/pose/imu` 没有数据时可通过 `/camera/imu/data_raw` 检查原始 IMU。

### 4.2 C++ 接口

| 功能 | 公开头文件 | CMake 目标 |
| --- | --- | --- |
| 双目定位 | `spacemit_vslam.h` | `spacemit_vslam::spacemit_vslam` |
| 建图与渲染 | `spacemit_mapping.h` | `spacemit_mapping::spacemit_mapping` |
| LAS2 深度（ExternalStereo） | `stereo_pipeline.h` | `stereo_matching::external_input` |

ExternalStereo 接收双目 NV12 DMA-BUF 和 Kalibr 标定，输出米制深度及对齐的左目 RGB。

## 5. 常见问题

| 现象 | 检查方法 |
| --- | --- |
| 相机无图像 | 检查 JSON 是否选中了实际图像采集节点、模式是否受支持、设备是否被占用。如果启动还在等待 `/las2/ready`，先查模型和推理日志。 |
| 模型加载失败 | 检查运行账号的默认模型路径和 SHA-256，确认使用 ExternalStereo 模型。也可用 `model_path` 传入经校验的文件。 |
| 长时间显示 `VO - IMU INIT` 或跟踪不稳 | 核对物理左右目、标定与采集模式，检查 `/camera/imu/data_raw` 和时间戳，再在有纹理的场景中缓慢移动相机。 |
| 深度正常但地图不更新 | 检查 `/vio/pose/image` 是否持续发布，以及深度和位姿的源时间戳是否能配对。 |
| 窗口未打开或没有画面 | 在本机桌面检查 `DISPLAY`、`XAUTHORITY` 和 `/esdf/render/frame_desc`。查看 `Desktop EGL ready` 日志中的 renderer；`llvmpipe` 或 `softpipe` 表示使用了软件渲染，应检查板卡图形驱动。 |

如果镜像需要使用已获授权的硬件运行账号，后端与窗口进程应保持相同的运行 UID。可用 `SPACEMIT_DESKTOP_UID` 指定已登录桌面用户的 UID，并保留该桌面的 `DISPLAY` 和 `XAUTHORITY`。运行账号变化时，使用 `model_path` 显式传入可读的模型路径。运行 `ros2 run bringup run_vslam_desktop.sh --help` 可查看无窗口运行和单独启动查看器的方式。

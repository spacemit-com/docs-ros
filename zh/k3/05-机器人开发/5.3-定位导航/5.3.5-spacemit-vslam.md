# 定位导航 · SpacemiT VSLAM

## 1. 模块概述

`spacemit-vslam` 提供面向机器人的双目视觉定位、视觉惯性定位和三维重建能力，位于 Robot SDK 的 `middleware/ros2/slam/spacemit-vslam`。模块将相机接入、VSLAM 和 TSDF/ESDF 建图组织在一个仓库中，通过 ROS 2 包完成数据发布、调度和桌面显示。

主要功能如下：

- 双目 VO/VIO：输出图像时刻位姿、轨迹、特征和跟踪状态；
- LAS2 双目深度：复用 SDK 的 `stereo_matching`，输出深度与对齐 RGB 描述符；
- TSDF/ESDF：融合深度和位姿，生成彩色三维表面及重力对齐的 ESDF 切片；
- 桌面窗口：显示实时图像、彩色深度、TSDF 和 ESDF，可选择普通窗口或全屏；
- K3 数据通路：图像与深度保留在 DMA-BUF 中，ROS 2 / DDS 传输描述符及元数据。

本文示例使用双目 VIO 与实时 TSDF/ESDF 重建。VIO 正常跟踪不等于完成了回环或全局重定位；本文入口默认不开启回环和 PGO。

```text
双目相机（图像内嵌曝光时间戳和 IMU）
  │
  ▼
camera_io ── 左右目描述符 / CameraInfo / IMU
  ├── vio ───────────── 位姿 / 轨迹 / 特征 / 跟踪状态
  └── las2 ──────────── 深度与对齐 RGB 描述符
           │              │
           └──────┬───────┘
                  ▼
               esdf_drm ── TSDF / ESDF / 合成画面
                  │
                  ▼
           esdf_desktop_viewer ── 桌面窗口
```

相关目录及职责：

| 路径 | 职责 |
| --- | --- |
| `modules/camera/` | 原生相机、元数据、标定和时间对齐工具 |
| `modules/vslam/` | CPU/RVV 视觉定位 SDK |
| `modules/mapping/` | TSDF/ESDF、地图与 GLES 渲染 SDK |
| `src/camera_io/` | 相机 ROS 接入、图像与 IMU 发布、录制 |
| `src/vio/` | VSLAM SDK 的 ROS 包装 |
| `src/las2/` | SDK LAS2 深度推理的 ROS 包装 |
| `src/esdf_drm/` | 深度/位姿配对、异步重建与桌面显示 |
| `src/common/` | 公共消息与就绪接口 |
| `src/bringup/` | 跨包启动与运行脚本 |
| `dependencies/` | SDK 依赖路径和来源清单，不存放依赖实现源码 |

MPP、LAS2 和 IMU DDS 继续复用 SDK 已有目录，分别为 `components/multimedia/mpp`、`components/perception/stereo_matching` 和 `middleware/ros2/peripherals/imu`。

## 2. 环境准备

### 2.1 前置条件

SDK 获取、软件源和基础构建环境参考 [2.3 构建编译](../../02-快速入门/2.3-构建编译.md)。首次部署应先准备环境，再进行本模块构建。编译报错时，先保留日志、确认缺少的组件及其版本，不以升级驱动、混用发行版软件包或修改全局环境变量作为默认处理方式。

SDK 工作区应已包含本模块源码和配套的 LAS2 ExternalStereo 后端；仅有 tensor 推理接口的旧 SDK 不能直接构建此示例。

本模块需要：

| 项目 | 要求 |
| --- | --- |
| 开发板 | 支持 MPP、V2D、DMA-BUF、GLES/OpenCL 的 K3 板卡 |
| 系统 | 与板卡驱动配套的 Bianbu 镜像；本示例使用 Bianbu 4.0.1 |
| ROS | 镜像配套的 ROS 2 Humble |
| 构建依赖 | SDK 声明的 CMake/C++、Eigen、YAML、Boost、LMDB、OpenCV、多媒体、Fast DDS 与图形开发库 |
| 相机 | 当前驱动支持的内嵌硬件时间戳/IMU 的双目 USB 相机；普通 UVC 相机不能直接替代该元数据协议 |
| 桌面 | 已登录的图形桌面，具有 X11 或 Xwayland；GPU EGL 支持 DMA-BUF 导入 |
| LAS2 工件 | 与 ExternalStereo 后端匹配的 ORT/EP、开发头文件及 FP16 模型 |
| 标定 | 对应当前实体相机的 Kalibr 双目/相机-IMU YAML，以及 IMU 噪声 YAML |

EGL/GLES 开发库只提供通用接口，不能代替 PowerVR 驱动。K3/Bianbu 配套图形栈应包含 `img-gpu-powervr`、`libegl-pvr0`、`libgbm1-pvr`、`libgl1-pvr-dri`、`libglapi-pvr` 和 `pvr-vulkan-drivers`。本项目 `src/esdf_drm/package.xml` 已声明这些目标机依赖，使用 software-setup skill 时需直接检查该包，或逐包检查。只检查 `src/bringup` 的 SDK 依赖闭包不会递归其 ROS 运行依赖，项目根 `mm` 也不自动遍历子包的系统依赖。其他板子只编译源码、未准备配套驱动，仍可能出现软件渲染；依赖声明不能代替板卡固件和驱动适配。

本次 K3/Bianbu 4.0.1 实测使用现有 `img-gpu-powervr=24.2-6603887bb22`，补装五个 `24.0.1-bb3` 的 PVR 拆分包，与系统 Mesa 26 共存。首次安装驱动后应保存桌面工作并重新登录，使合成器和 Xwayland 加载新驱动；日常启动保持桌面服务运行。可选使用 `eglinfo -B -p x11` 检查 PowerVR/OpenGL ES 3，最终以应用实际 renderer 为准。

例如，在 SDK 根目录使用原有检查器显式检查图形包，以下命令只检查、不安装：

```bash
source build/common.sh
AUTO_INSTALL_DEPS=no check_and_install_dependencies_for_package \
  middleware/ros2/slam/spacemit-vslam/src/esdf_drm none
```

缺项通过 software-setup skill 的板端软件准备流程处理后，再进行下述构建。

ORT/EP 工件由 SDK 配套部署包提供，LAS2 模型需从归档站单独下载，不放入本项目的 `dependencies/`。下载内容保存到用户目录，使用前需确认归档文件已刷新为下述 SHA256 对应的 ExternalStereo 版本。SDK 根目录变量 `SROBOTIS_ROOT` 由 `source build/envsetup.sh` 设置：

```bash
export ARTIFACT_ROOT="$HOME/spacemit-vslam-artifacts"
mkdir -p "$ARTIFACT_ROOT/model"
wget -O "$ARTIFACT_ROOT/model/LAS2_M_288x384.fp16.onnx" \
  https://archive.spacemit.com/spacemit-ai/model_zoo/vision/stereo_depth/LAS2_M_288x384.fp16.onnx
```

示例工件布局：

```text
spacemit-vslam-artifacts/
  onnxruntime/
    LICENSE                  # 配套工件的许可证文件，构建安装时必须存在
    include/                 # 配套 ORT/EP 开发头文件
    lib/                     # 配套 ORT、SpacemiT EP 与 TCM 运行库
  model/
    LAS2_M_288x384.fp16.onnx
```

ORT 工件应完整解包并保留 `lib/` 下的相对 SONAME/dlopen 符号链接，不能只挑选两个目录或单个库文件复制；`LICENSE` 缺失时构建会明确失败。

后端及模型必须配套。匹配的 `LAS2_M_288x384.fp16.onnx` SHA256 为：

```text
aa4f22f0f2433dc317ae3fa028549b9e228200c117d95121e19cfa0f1615145a
```

同名文件不代表同一模型；ExternalStereo 使用的模型与原 tensor SDK 模型分别管理。详细运行库和接口要求见 SDK 中的 `components/perception/stereo_matching/RUNTIME_CONTRACT.json`。

### 2.2 构建编译

在 K3 板端打开未执行 `lunch` 的新终端，使用 SDK 的单模块构建入口。当前 SDK 的 `m` 不提供 `-b` 选项；没有本模块专用 target 时，进入项目目录执行 `mm`，无需新增 target 或修改 SDK 构建脚本。

```bash
cd "$HOME/spacemit_robot"
source build/envsetup.sh
export ARTIFACT_ROOT="$HOME/spacemit-vslam-artifacts"

cd "$SROBOTIS_ROOT/middleware/ros2/slam/spacemit-vslam"
mm -j4 -- \
  -DONNXRUNTIME_ROOT="$ARTIFACT_ROOT/onnxruntime" \
  -DSTEREO_MATCHING_EXTERNAL_INPUT_MODEL="$ARTIFACT_ROOT/model/LAS2_M_288x384.fp16.onnx"
```

上述命令使用默认 `output/staging` 安装前缀。使用隔离输出目录时，应在同一 SDK 环境中另外显式传入 `-DSPACEMIT_SDK_PREFIX="$PREFIX"` 和 `-DMPP_BUILD_DIR="$PREFIX"`，确保消费者从该次构建的安装前缀查找 MPP 与 SDK 依赖。

`mm` 经 SDK 已有的项目 `build.sh` 接口，构建本项目的原生模块、复用依赖和六个 ROS 包。入口内的 CMake/colcon 调度由本项目管理；不需要修改 SDK 的 `build/`、原 IMU 包或 `target/`。

产物说明：

- 默认安装前缀为 `$SROBOTIS_ROOT/output/staging`；
- 节点可执行文件位于 `lib/<ROS包名>/`，共享库位于 `lib/`；
- ROS 配置、启动文件与资源位于 `share/<ROS包名>/`；
- 配套 ExternalStereo 模型安装至 `share/stereo_matching/external_input/model/`；
- ORT/EP 等部署工件按显式提供的路径安装至前缀，不写入项目依赖源码目录；
- 编译期间应停止相机、推理和建图等高负载程序。

新终端加载实际生成的 SDK 运行环境：

```bash
cd "$HOME/spacemit_robot"
source build/envsetup.sh
sros2_setup
```

`m` 用于 SDK 根目录的整体构建，`mm` 用于当前组件构建。本文不要求从 SDK 根目录构建所有其他机器人方案。

## 3. 示例使用

### 3.1 准备相机配置和标定

将实机配置放在用户可读写的运行目录中，避免直接修改安装后的共享配置：

```bash
cd "$HOME/spacemit_robot"
source build/envsetup.sh
export CONFIG_ROOT="$HOME/spacemit-vslam-config"
mkdir -p "$CONFIG_ROOT"
cp "$SROBOTIS_ROOT/middleware/ros2/slam/spacemit-vslam/src/camera_io/config/usb_stereo_4000x1200.json" \
  "$CONFIG_ROOT/camera.json"
```

将当前相机的 Kalibr 标定保存为 `$CONFIG_ROOT/camchain-imucam.yaml`，对应 IMU 噪声标定保存为 `$CONFIG_ROOT/imu.yaml`。相机编号相同不能证明标定适用；更换实体相机、镜头、左右目排列或安装外参后，应使用对应的新标定。

先确认实际设备与支持的采集模式：

```bash
ls -l /dev/v4l/by-id/
v4l2-ctl --list-devices
v4l2-ctl -d /dev/videoX --list-formats-ext
```

`/dev/videoX` 应替换为实际采集设备，不能把硬件解码设备或 UVC 元数据设备当作图像采集设备。建议在 JSON 中使用 `/dev/v4l/by-id/...-video-index0` 的稳定设备路径。

编辑 `camera.json`，重点核对以下字段：

| 字段 | 配置要求 |
| --- | --- |
| `camera.device` | 实际采集设备，优先 stable by-id 路径 |
| `camera.width/height/fps` | 与驱动实际支持的采集模式一致；本文双目示例为 MJPEG 4000×1200@30 |
| `timestamp.source` | 与标定和相机协议一致；示例使用 `embedded_exposure_midpoint` |
| `calibration.file` | 当前相机的 Kalibr YAML 绝对路径 |
| `streams.left/right.crop` | 与物理左右目及标定顺序一致 |
| `streams.left/right.output` | 本例均为 640×400，与启动参数一致 |
| `metadata.region` | 与该相机内嵌时间戳/IMU 数据区匹配 |
| `imu.samples_per_frame` | 与实际相机协议匹配；当前示例为每帧 10 个样本 |
| `buffers.decoder_input_pool.enabled` | 当前 MPP API6 示例设为 `false`，使用标准压缩输入路径 |

当前相机打包格式中，左目裁剪为 `(2080, 0, 1920, 1200)`，右目为 `(160, 0, 1920, 1200)`；这属于该型号的物理排列，不能按画面位置自行交换。其他格式应同步调整相机配置、标定和解析支持。

对于本文 4000×1200@30 的相机，完成设备确认并放好两份标定后，可执行以下配置更新。输入上一条命令查到的实际图像采集设备路径，优先使用 by-id 路径：

```bash
read -r -p '图像采集设备路径：' CAMERA_DEVICE
export CAMERA_DEVICE
python3 - <<'PYCONFIG'
import json
import os
from pathlib import Path

config_root = Path(os.environ["CONFIG_ROOT"])
device = Path(os.environ["CAMERA_DEVICE"])
calibration = config_root / "camchain-imucam.yaml"
imu_calibration = config_root / "imu.yaml"
if not device.is_char_device():
    raise SystemExit(f"图像采集设备不存在或不是字符设备：{device}")
for path in (calibration, imu_calibration):
    if not path.is_file():
        raise SystemExit(f"先准备当前相机的标定文件：{path}")
path = config_root / "camera.json"
config = json.loads(path.read_text())
config["camera"]["device"] = str(device)
config["camera"]["fps"] = 30
config["calibration"]["file"] = str(calibration.resolve())
config["buffers"]["decoder_input_pool"]["enabled"] = False
path.write_text(json.dumps(config, ensure_ascii=False, indent=2) + "\n")
print(f"已更新相机配置：{path}")
PYCONFIG
```

上述片段只更新示例配置，不会修改标定数值或驱动。若硬件支持的采集模式不同，先调整格式、尺寸、裁剪和对应标定，再启动。

关闭可选固定压缩输入池不会关闭图像/深度的 DMA-BUF 输出。若 SDK 提示缺少固定输入池扩展，应核对该选项，不要移除能力检查。

### 3.2 在正常桌面启动窗口

在开发板已登录桌面的终端中启动，SDK、配置和部署工件放在该用户可访问的目录。窗口连接使用当前桌面的 `DISPLAY/XAUTHORITY`，不停止桌面服务。

相机、MPP、V2D、TCM 和 DMA-BUF 访问需要对应权限。本文验证镜像使用管理身份运行整条硬件链路，同时由 `SPACEMIT_DESKTOP_UID` 指定现有桌面用户。显示端仅在建立 X11/Xwayland 连接时使用这个桌面身份，随后恢复运行身份，后端与显示端仍以相同身份交换 DMA-BUF。该选项不会修改 X11 访问规则、共享内存权限或用户组。

以下命令在**普通桌面用户**的终端中执行；`sudo` 使用该系统已有的管理授权，不安装或配置系统环境：

```bash
export CONFIG_ROOT="$HOME/spacemit-vslam-config"
cd "$HOME/spacemit_robot"
source build/envsetup.sh
desktop_uid=$(id -u)

sudo env SROBOTIS_ROOT="$SROBOTIS_ROOT" CONFIG_ROOT="$CONFIG_ROOT" \
  DISPLAY="$DISPLAY" XAUTHORITY="${XAUTHORITY:-$HOME/.Xauthority}" \
  WAYLAND_DISPLAY="${WAYLAND_DISPLAY:-}" XDG_RUNTIME_DIR="${XDG_RUNTIME_DIR:-}" \
  SPACEMIT_DESKTOP_UID="$desktop_uid" ROS_DOMAIN_ID=0 bash -c '
    set -e
    cd "$SROBOTIS_ROOT"
    source build/envsetup.sh
    sros2_setup
    exec ros2 run bringup run_vslam_desktop.sh \
      camera_config_file:="$CONFIG_ROOT/camera.json" \
      calibration_file:="$CONFIG_ROOT/camchain-imucam.yaml" \
      imu_calibration_file:="$CONFIG_ROOT/imu.yaml" \
      camera_fps:=30 image_width:=640 image_height:=400 use_imu:=true
  '
```

如果镜像已允许当前普通用户访问全部硬件资源，且后端与窗口都以该用户运行，可以直接使用同一 `ros2 run bringup run_vslam_desktop.sh ...` 入口，不设置 `SPACEMIT_DESKTOP_UID`。不要将管理身份的后端与另一普通用户的窗口直接混用；当前 MPP 的跨用户 DMA-BUF fd 查询可能失败。

相机 JSON 的 `imu.domain_id` 与 ROS 节点的 `ROS_DOMAIN_ID` 应一致；本示例均使用 0。默认打开 1280×720 普通窗口。需要全屏时，在 `ros2 run` 参数末尾添加 `desktop_fullscreen:=true`。

窗口显示内容：

- 左上：实时左图与彩色深度预览；
- 左侧：彩色 TSDF 表面与相机轨迹；
- 右侧：重力对齐的 ESDF 切片；
- 状态区：VO/VIO 状态、定位/深度/融合帧率及 GPU 时间。

启动后先保持相机平稳，随后在有纹理、照明稳定的场景中缓慢平移和小幅转动。状态可能先显示 `WAIT`、`VO - IMU INIT`，完成惯性初始化后进入 `VIO`。不要把预览已经出图作为 VIO 初始化完成的判据。

相机默认等待 `/las2/ready` 后开始发布，首次模型初始化期间短暂等待属于启动过程。退出时在启动终端按 `Ctrl+C`，让节点完成缓冲释放。

### 3.3 检查输出

在另一个已加载相同 SDK overlay 的终端中执行：

```bash
ros2 node list
ros2 topic hz /camera/left/frame_desc
ros2 topic hz /las2/depth_desc
ros2 topic hz /vio/pose/image
ros2 topic echo /vio/tracking_mode --qos-reliability best_effort --once
```

VIO 状态和元数据话题使用 sensor-data QoS，订阅器应使用兼容的 best-effort/volatile 配置。`ros2 topic hz` 是观察值，多话题 Python 订阅器的接收速率不能直接当作算法吞吐或无损 IMU 发布速率。

## 4. 应用开发

主要接口：

| 接口 | 类型 | 说明 |
| --- | --- | --- |
| `/camera/left/frame_desc`、`/camera/right/frame_desc` | `mpp_msgs/msg/MppVideoFrameDesc` | 左右目 NV12 DMA-BUF 描述符 |
| `/camera/left/camera_info`、`/camera/right/camera_info` | `sensor_msgs/msg/CameraInfo` | 与输出分辨率对应的相机内参 |
| `/camera/imu/data_raw` | `sensor_msgs/msg/Imu` | 硬件时间戳对应的原始 IMU |
| `/vio/pose/image` | `nav_msgs/msg/Odometry` | 图像时刻位姿 |
| `/vio/trajectory` | `nav_msgs/msg/Path` | 有界轨迹输出 |
| `/vio/tracking_mode` | `std_msgs/msg/String` | `WAIT`、`VO - IMU INIT`、`VIO` 等状态 |
| `/vio/features` | `common/msg/FeaturePointArray` | 特征与可选诊断数据 |
| `/las2/depth_desc` | `common/msg/DmaDepthFrameDesc` | 深度、对齐 RGB 和标定元数据 |
| `/esdf/render/frame_desc` | `mpp_msgs/msg/MppVideoFrameDesc` | 用于桌面窗口的 NV12 合成画面 |

使用注意点：

- 描述符中的 token 不是普通进程地址。新增消费者应按 MPP 接口导入，并在所有退出路径释放对应引用；
- 保留帧号、曝光时间戳、尺寸、stride、像素格式和标定，图像与位姿应按源时间配对；
- 不修改共享输入缓冲；队列采用有界处理，过期帧可丢弃，不能让推理或建图阻塞相机/IMU；
- 该入口默认关闭外部高频位姿外推；`/vio/pose/imu` 没有输出不代表原始 IMU 停止，也不代表 VIO 未融合 IMU；
- 应用通用线程默认使用 0–7，LAS2 的 EP 实例亲和参数独立配置，不能根据 `nproc` 推断板卡物理 CPU 状态。

常用参数：

| 参数 | 说明 |
| --- | --- |
| `camera_config_file` | 相机 JSON，包含设备、采集模式、裁剪、元数据和 IMU 协议配置 |
| `calibration_file` | Kalibr 双目及相机-IMU 标定 |
| `imu_calibration_file` | IMU 噪声及随机游走标定 |
| `camera_fps` | 采集帧率，必须是硬件支持的模式 |
| `image_width/image_height` | 双目输出尺寸，须与相机配置一致 |
| `model_path` | 覆盖默认 ExternalStereo FP16 模型路径 |
| `use_imu` | 选择 VIO；关闭后按对应入口和标定运行 VO |
| `desktop_fullscreen` | 普通窗口或全屏 |
| `display_width/display_height` | 桌面窗口尺寸 |
| `las2_instance_count/las2_threads_per_instance/las2_core_affinity` | 推理实例、线程数与 EP 亲和参数 |

查看完整启动参数：

```bash
ros2 launch bringup vio_las2_esdf_launch.py --show-args
```

## 5. 调试指南

### 5.1 相机标定与时间对齐

Kalibr 双目标定应至少包含以下内容：

| 项目 | 要求 |
| --- | --- |
| `cam0`、`cam1` | 分别对应本项目的物理左目、物理右目 |
| `camera_model` | `pinhole` |
| `distortion_model` | 驱动支持的 `equidistant` 或 `radtan` |
| `intrinsics` | 原始单目分辨率下的 `fx, fy, cx, cy` |
| `distortion_coeffs` | 与畸变模型配套的四个参数 |
| `resolution` | 与对应裁剪区域一致，本例为 `[1920, 1200]` |
| `cam1.T_cn_cnm1` | 非零双目基线对应的刚体变换，保留 Kalibr 方向 |
| `T_cam_imu` | 相机与 IMU 的旋转和平移，VIO 需要使用对应标定 |
| `cam0.timeshift_cam_imu` | 标定得到的时间偏移，按程序既有语义应用 |

IMU YAML 使用 `imu0` 节点，包含 `gyroscope_noise_density`、`gyroscope_random_walk`、`accelerometer_noise_density`、`accelerometer_random_walk`，可记录 `update_rate`。实际 IMU 处理频率由相机采集模式及每帧样本数确定；例如 30 FPS × 10 样本为约 300 Hz。

图像和内嵌 IMU 共用硬件时钟。程序按 `原始 IMU 时间戳 - timeshift_cam_imu` 对齐，不给图像添加人为延迟。不要为消除画面抖动随意改时间偏移。

缩放图像时，程序按输出尺寸缩放 `fx/fy/cx/cy`；畸变系数与刚体外参不随分辨率缩放。把原始标定先手工缩放后再传给节点，可能造成重复缩放。

排查顺序：

1. 核对实体相机、左右目、采集模式与标定来源；
2. 核对 JSON 的裁剪区域与 Kalibr 单目原始分辨率；
3. 核对 JSON `calibration.file` 与启动参数 `calibration_file` 使用同一份标定；
4. 查看启动日志中的标定来源、时间偏移、IMU 噪声和运行频率；
5. 观察 `/camera/left/camera_info`、图像/IMU 时间戳及 `tracking_mode`。

```bash
ros2 topic echo /camera/left/camera_info --once
ros2 topic echo /camera/imu/data_raw --qos-reliability best_effort --once
ros2 topic echo /vio/pose/image --qos-reliability best_effort --once
```

### 5.2 桌面窗口

启动命令应在已登录桌面的终端中执行：

```bash
printf 'DISPLAY=%s\n' "${DISPLAY:-}"
ros2 topic hz /esdf/render/frame_desc
```

`DISPLAY` 为空、X11 授权失败或仅有纯 Wayland 而无 Xwayland 时，窗口不能创建。保留当前会话的 `DISPLAY/XAUTHORITY`；使用管理身份时，按 3.2 同时指定桌面 UID。不要执行 `xhost +` 或为了窗口显示关闭桌面。

本入口由 GPU 在后台生成合成帧，再由桌面 viewer 显示；因此内部 `headless_render=true` 表示不直接占用 DRM 扫描输出，前台窗口由 `desktop_viewer_enabled=true` 创建。出现该参数不表示窗口被禁用。

成功创建窗口时应出现 `Desktop EGL ready`，实际 `renderer` 应为 PowerVR。`llvmpipe`、`softpipe` 表示 CPU 软件渲染，单凭 GLES 日志或 HUD 的 OpenCL 耗时不能证明地图渲染正在使用 GPU。窗口默认拒绝已知的软件光栅器并给出驱动检查提示；仅调试时可显式传入 `desktop_allow_software_rendering:=true`。接收并显示帧后出现 `Desktop displayed frames=...`。有合成画面话题但窗口无帧时，检查 DMA-BUF/token 导入错误、桌面用户对 SDK 安装前缀及设备的访问情况，先保留日志。

### 5.3 定位、深度与负载

- 长时间停留在 `VO - IMU INIT`：先确认 IMU 连续、时间对齐和标定匹配，再检查相机是否有足够的平移与转动激励；
- 位姿跳变或跟踪丢失：检查左右目是否交换、畸变模型、纹理、曝光、运动模糊和时间戳单调性；
- 有位姿但无深度：检查配套模型/ORT、`/las2/ready` 和深度描述符，不能用同名 tensor 模型替换；
- 深度有数据而地图不更新：检查图像时刻位姿、深度时间戳、有效深度范围及重力初始化；
- 帧率下降：分开观察相机、VIO、LAS2、融合和渲染耗时；有界队列丢弃过期帧不等于相机故障；
- 不通过扩大队列掩盖负载问题，也不在运行高负载链路时同时编译。

## 6. 常见问题

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| `m -b` 报未知选项 | 当前 SDK 不支持该参数 | 在本项目目录使用 `mm -j4 -- -D...` |
| 找不到 ORT/EP 开发头或运行库 | 配套工件未准备完整或路径错误 | 核对 `ONNXRUNTIME_ROOT`，保留错误，不混用其他模型包中的运行库 |
| 编译通过但启动时模型加载失败 | 模型缺失、ABI 不匹配或误用了 tensor SDK 同名模型 | 核对模型路径及 SHA256，使用 ExternalStereo 配套工件 |
| 相机无图像 | 选择了解码/元数据设备，采集模式不支持或设备被占用 | 按 stable by-id 确认采集节点和实际支持的格式/帧率 |
| 报固定输入池扩展缺失 | JSON 启用了当前 MPP 不支持的可选输入池 | 将该示例配置的 `decoder_input_pool.enabled` 设为 `false` |
| 标定校验失败 | 左右目、裁剪、分辨率、畸变或 IMU YAML 不匹配 | 按 5.1 核对配置，使用当前实体相机的标定 |
| 有图像但 VIO 未初始化 | 缺少有效 IMU 或运动激励 | 核对 IMU/标定/时间戳，并缓慢平移、小幅转动相机 |
| `/vio/pose/imu` 为零 | 本入口默认未启用外部高频外推 | 检查原始 IMU 和图像位姿；按应用需求再选择是否启用外推 |
| 桌面报 `Cannot open X11 desktop` | 无有效桌面会话或用户授权不匹配 | 保留桌面环境；管理身份按 3.2 指定 `SPACEMIT_DESKTOP_UID` |
| TCM 共享内存权限错误或 V2D 访问失败 | 运行身份缺少镜像要求的硬件权限 | 使用已获授权的管理身份启动，先保留日志，不临时 chmod 或改用户组 |
| 窗口持续报 `NV12 DMA-BUF lookup failed` | 后端与窗口跨用户，fd 查询被拒绝 | 按 3.2 保持相同运行身份，桌面连接身份另用 UID 指定 |
| 地图持续更新但没有窗口 | 未启动 viewer 或合成画面未发布 | 使用 `run_vslam_desktop.sh`，核对 `/esdf/render/frame_desc` 和 viewer 日志 |
| 画面与实际运动方向不一致 | 物理左右目或相机/IMU 外参方向错误 | 重新核对标定方向和物理安装，不能靠显示坐标修补里程计 |

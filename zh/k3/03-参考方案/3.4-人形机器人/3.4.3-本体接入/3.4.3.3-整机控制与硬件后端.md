# 整机控制与硬件后端

`components/control/whole_body` 聚合电机、IMU、关节映射和底层安全检查，对共享运行时提供统一关节顺序及 SI 单位的机器人状态和控制接口。

这里的 `whole_body` 指整机硬件抽象和安全执行组件，不是动力学 Whole-Body Control 算法。

## 1. 责任边界

| 层级 | 职责 |
| --- | --- |
| `components/peripherals/motor`、`components/peripherals/imu` | 实现具体设备和总线协议，提供电机与 IMU 的原始收发能力 |
| `components/control/whole_body` | 聚合设备、执行关节映射和安全检查，转换为 SDK 公共状态与控制语义 |
| `humanoid_common/driver_runtime` | 根据机型配置创建后端，通过 transport 交换状态与控制指令，并向 Control 回传结构化故障 |

机型包保存 `whole_body` 所需的设备、关节映射和硬件参数，不在共享组件中硬编码某一款本体。

## 2. 运行时接入

使用实机链路时，target 必须包含 `whole_body` 及机型所需外设组件，YAML 中的 `driver.backend` 设置为 `whole_body`。`driver_runtime` 将公共控制指令转换为整机硬件指令，并回传电机、关节和 IMU 状态。

选择了未编入当前产物的后端时，运行时会在启动阶段明确失败，不会静默切换到仿真或其他后端。

## 3. 已实现的底层保护

`whole_body` 支持直接关节与并联脚踝映射、只读启动、反馈超时和命令看门狗。电机侧按配置区分告警与致命错误，并在映射后、协议编码前检查 KP/KD、估算力矩及命令变化率上限；并联脚踝还可检查 Jacobian 条件数与力矩放大倍数。

扩展诊断接口 `whole_body_get_diagnostics_v2()` 和 `whole_body_get_motor_command_diagnostics_v2()` 提供反馈新鲜度、错误分类、耦合指标和电机命令快照。各安全上限由机型硬件配置提供，`0` 表示未启用对应门限，不能代替实机标定。

底层保护与上层故障锁存分别生效：`driver_runtime` 将设备故障送到 Control，Control 阻止重新上电并通知 HMI；故障解除后仍需 POWER_OFF 下人工确认。机器人本体的急停、机械限位和整机安全检查仍需独立验收。

## 4. 能力边界

- 当前公开机型是否包含 `whole_body` 配置，应以其公开机型包和 target 为准。
- `humanoid_linglong` 已进入当前公开 manifest，并包含 `whole_body` 配置和对应 target；机型包可用仍不等同于已经完成完整实机交付验收。
- 组件可以编译或离线测试，不代表关节方向、零位、限位和安全状态已经在目标本体上验收。
- 实机闭环前需完成机器人模型与关节映射、电机与 IMU 接入、实机启动与标定等机型级检查；对应操作文档仍在整理。

共享运行时如何选择并连接该后端，见[运行时通信与安全](../3.4.2-开发基础/3.4.2.3-运行时通信与安全.md)。

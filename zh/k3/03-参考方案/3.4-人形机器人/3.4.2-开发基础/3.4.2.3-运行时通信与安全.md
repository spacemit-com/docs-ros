# 运行时通信与安全

本页说明人形 SDK 各运行进程之间的数据流、通信方式和状态安全边界。

## 1. FSM 完整链路

FSM 模式同时运行三个进程：

| 进程 | 职责 | 主要数据 |
| --- | --- | --- |
| `hmi_runtime` | 发送状态切换、策略选择、速度和故障确认请求；显示 Control 端回传状态 | `Command`、故障确认序号 →；`ControlStatus`、`FaultStatus` ← |
| `control_runtime` | 接收机器人状态、故障与 HMI 请求，运行状态机和策略，输出关节命令与运行状态 | `RobotData`、`Command`、driver 故障 ←；`ControlCmd`、`ControlStatus`、锁存故障 → |
| `driver_runtime` | 创建仿真或实机后端，转换状态与控制指令，回传后端故障 | `RobotData`、`FaultStatus` →；`ControlCmd` ← |

`control_runtime` 中的行为状态机包含 `POWER_OFF → DAMP → HOME → ZERO → RL` 的正常进入链路和 `SAFETY` 安全状态。HOME 按设定时间完成增益渐变和默认姿态插值后允许进入 ZERO，不单独检查实际关节是否到位；ZERO 对齐所选策略的准备姿态，满足关节位置、速度和持续稳定条件后才允许进入 RL。

默认策略在行为管理器启动阶段预加载；切换策略或重新准备时，在 POWER_OFF/DAMP 下异步完成模型准备，未就绪时阻止 DAMP → HOME。进入 RL 时重置策略运行状态并启动推理线程，不在这一状态切换中加载模型。

`StateRL` 在独立线程中执行策略推理，控制线程读取最新动作缓存并映射关节目标。推理线程忙碌时合并过期请求、使用最新传感器快照；退出 RL 时请求中断正在执行的推理并等待线程停止。

`behavior_manager/policy_adapter` 是行为管理器的内部扩展点，用于将 MJLab、ProtoMotions 和 SONIC 等参考动作或特殊模型输入转换为通用 `PolicyExecutor` 可消费的数据。对于启用 SONIC Kinematic Planner 的配置，Planner 在独立线程中根据速度命令生成参考轨迹；低层关节跟踪仍由 SONIC tracker 策略执行。

## 2. Sim2Sim 简化链路

`control_sim2sim_runtime` 直接调用 `PolicyExecutor` 并与 `driver_runtime` 交换仿真状态和关节目标，不经过 HMI、FSM 和 `policy_adapter`。它适合验证已能由通用策略接口完整描述的 ONNX 策略，不代表完整运行时或实机安全链路已验证。

## 3. 驱动后端选择

`driver_runtime` 读取 YAML 中的 `driver.backend`，在当前构建已包含的后端中选择：

- `mujoco`：将 MuJoCo 的 `SimState` / `SimControl` 与 SDK 公共数据转换，接受 `HYBRID`、`POSITION` 命令；当前不支持非零前馈力矩。仿真组件可在 x86_64 和 riscv64/K3 构建；跨机流程通常由 PC 运行 MuJoCo、K3 运行控制端。
- `whole_body`：将 SDK 公共指令转为整机硬件指令，并回传电机、关节和 IMU 状态。它支持机型配置的直接关节与并联脚踝映射、只读启动、命令看门狗和故障锁存等能力。

选择了未编入当前产物的后端时，`driver_runtime` 会在启动阶段明确失败，不会静默切换到其他后端。

## 4. 进程通信

运行时之间通过 `transport` 交换同一组语义数据，通信实现由 `transport.type` 选择：

- `shm`：同机多进程共享内存通信。
- `udp`：同机或 PC + K3 跨机通信。

FSM 使用 state、control、hmi、status 四个通道。UDP 分别配置 `driver_ip`、`control_ip`、`hmi_ip` 以及四个端口；SHM 使用同一前缀下的四个共享内存通道。

当前 SHM/UDP v5 协议通过 `TransportBaseV2` 在原状态、命令之外传递 `FaultStatus` 和故障确认序号，保留原公共结构及旧接口布局。参与通信的进程必须使用一致协议版本，版本不匹配时拒绝解析。

## 5. 安全边界

- 仿真后端用于验证状态机、通信和控制链，不替代实机的驱动、安全和急停验收。
- `whole_body` 检查设备反馈、命令和映射安全；Control 统一处理 driver 故障、状态超时、无效数据、姿态/角速度超限和策略故障。
- `behavior_manager.rl_safety` 可设置首帧动作等待、已发布动作的最大可用年龄和单次推理时限；单策略 `runtime_safety` 可覆盖，时限为 `0` 时不启用该项检查。这里的动作年龄从推理结果发布时开始计时。
- 故障会锁存并阻止再次上电。电机、IMU 或传输反馈无效时立即保持失能；反馈有效的策略故障或姿态超限可按配置受控卸力。故障条件消失后，仍需在 POWER_OFF 下由 HMI 按 `x` 确认并等待回传。
- Sim2Sim 跳过 HMI 与 FSM，只能证明策略在简化链路中运行，不能作为完整实机链路的验收结果。

## 6. 运行日志与诊断

机型 YAML 的 `logging` 控制事件、时序和遥测记录；数据经有界后台队列落盘，队列满时计数并丢弃日志，不阻塞控制循环。

| 产物 | 用途 |
| --- | --- |
| `events.log` | 生命周期、状态切换、策略和故障事件 |
| `driver_timing.csv`、`control_timing.csv` | 控制周期、迟到和跳周期统计 |
| `driver_motor.csv`、`driver_joint.csv`、`driver_imu.csv`、`driver_coupling.csv` | 物理电机、关节、IMU 和并联机构诊断 |
| `control_trace.csv`、`control_joint.csv` | 控制状态、最终关节目标和反馈 |
| `control_policy_<策略名>.csv`、`control_policy_apply_<策略名>.csv` | 推理观测、各阶段动作，以及动作首次应用的时序和关节目标；通过 `release_sequence` 对齐 |
| `metadata.json`、`artifacts.csv` | 启动配置、构建版本、工作区状态和模型/配置等资产的 SHA256 |

策略 trace 需启用 debug 与 telemetry；分别按实际推理和新动作首次应用记录，不受普通遥测频率降采样。日志字段和配置示例见 [humanoid_common README](https://github.com/spacemit-robotics/humanoid_common#runtime-日志)。

整体软件分层见[SDK 架构](3.4.2.2-SDK架构.md)，硬件侧职责见[整机控制与硬件后端](../3.4.3-本体接入/3.4.3.3-整机控制与硬件后端.md)。

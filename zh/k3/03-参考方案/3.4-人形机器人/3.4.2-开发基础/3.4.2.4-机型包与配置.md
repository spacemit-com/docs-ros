# 机型包与配置

机型包集中保存机器人差异项，使共享运行时和通用组件不依赖某一款机器人本体。

## 1. 机型包职责

`application/native/humanoid_<robot>` 负责组织以下机型资产：

- 机器人关节顺序、控制自由度和关节映射；
- MuJoCo XML 等模型资源；
- 策略模型声明、观测动作参数和控制参数；
- driver、control、HMI 与 Sim2Sim 运行配置；
- 构建安装规则和机型启动脚本；
- 已支持实机的机型所需硬件配置。

共享状态机、通信实现、策略执行器和 MuJoCo 封装不应复制到机型包内。它们分别由 `humanoid_common`、`model_zoo/rl` 和 `simulation/mujoco` 维护。

## 2. 配置与构建目标

target JSON 决定某一构建目标包含哪些组件和机型包，YAML 决定已编入组件在运行时使用哪个后端、通信方式、线程参数和策略资源。

`driver.backend` 只能选择当前 target 已编入的后端。缺少所需组件时应在启动阶段失败，不通过自动回退掩盖构建或配置错误。

## 3. 当前公开范围

当前公开 manifest 中的人形机型包包括 LingLong、Unitree G1、H1-2、R1、青龙和天工，另包含 `humanoid_unitree_go1` 四足兼容性示例。各机型的控制自由度、可用 target、脚本和策略以当前发布版本为准。

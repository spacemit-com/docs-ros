# SDK 架构

人形 SDK 按“机型差异、共享控制逻辑、可复用组件”分层。新机型通过机型包提供配置和资源，不在每个机型中复制运行时、推理器或仿真器。

## 1. 分层与责任边界

| 层级 | 代码位置 | 当前职责 |
| --- | --- | --- |
| 机型应用层 | `application/native/humanoid_<robot>` | 保存关节顺序、运行参数、策略声明、机器人模型、启动脚本等机型资产；有实机后端的机型另外提供硬件配置 |
| 共享运行时层 | [`application/native/humanoid_common`](https://github.com/spacemit-robotics/humanoid_common) | 定义机器人数据与控制契约，组织 HMI、行为状态机、策略调度、进程通信、驱动后端和运行时日志 |
| 策略推理组件 | [`components/model_zoo/rl`](https://github.com/spacemit-com/model_zoo_rl) | 根据 YAML 声明组装观测、绑定 ONNX 输入输出、执行推理并将策略动作映射为关节目标 |
| 仿真后端 | [`components/simulation/mujoco`](https://github.com/spacemit-robotics/simulation_mujoco) | 封装 MuJoCo 模型加载、物理步进、状态读取、控制指令和可视化，支持 x86_64 与 riscv64/K3 |
| 实机后端 | [`components/control/whole_body`](https://github.com/spacemit-robotics/control_whole_body) | 聚合电机、IMU、关节映射与安全检查，对上提供统一关节顺序和 SI 单位的状态与指令接口 |
| 外设驱动层 | `components/peripherals/motor`、`components/peripherals/imu` | 实现具体电机和 IMU 的总线与设备协议，由 `whole_body` 组合使用 |
| ROS 2 控制桥接 | [`middleware/ros2/control/humanoid`](https://github.com/spacemit-robotics/ros2_humanoid) | 将 ROS 2 速度指令接入 Native HMI 通道，复用状态机与 RL 控制链；当前提供 LingLong 配置示例 |
| ROS 2 联合仿真 | [`middleware/ros2/simulation/humanoid_mujoco`](https://github.com/spacemit-robotics/ros2_simulation/tree/main/humanoid_mujoco) | 在同一 MuJoCo 实例中提供 DRIVER 端及 ROS 2 传感器、里程计和仿真时钟，复用 Native 控制进程 |

`whole_body` 在这里指整机硬件抽象和安全执行组件，不是动力学 Whole-Body Control 算法。

## 2. 代码入口

以下只列出稳定的责任边界，具体类和文件以对应仓库为准。

```text
application/native/
├── humanoid_common/
│   ├── include/                 # 数据、行为管理和通信公开接口
│   ├── src/robot_base/          # YAML 读取、公共数据结构和线程配置
│   ├── src/behavior_manager/    # FSM、RL 状态和策略协议适配
│   ├── src/transport/           # SHM / UDP 通信实现
│   ├── src/runtime/             # driver / control / hmi / sim2sim 进程
│   └── src/logging/             # 运行事件和可选遥测日志
├── humanoid_unitree_g1/        # Unitree G1 机型包
├── humanoid_unitree_h1_2/      # Unitree H1-2 机型包
├── humanoid_unitree_r1/        # Unitree R1 机型包
├── humanoid_linglong/          # LingLong 机型包
├── humanoid_qinglong/          # 青龙机型包
└── humanoid_tiangong/          # 天工机型包

components/
├── model_zoo/rl/               # 通用 RL 策略推理
├── simulation/mujoco/          # MuJoCo 仿真
├── control/whole_body/         # 整机硬件状态与控制
└── peripherals/{motor,imu}/    # 电机与 IMU 设备驱动

middleware/ros2/
├── control/humanoid/           # 导航速度指令 → Native HMI 通道
└── simulation/humanoid_mujoco/ # 联合仿真 DRIVER 端与 ROS 2 传感器
```

当前 manifest 还包含 `humanoid_unitree_go1` 四足兼容性示例；它复用同一套运行时，但不属于人形机型。

## 3. 扩展边界

- 机型差异由[机型包与配置](3.4.2.4-机型包与配置.md)收敛；共享状态机、通信和策略调度留在 `humanoid_common`。
- 通用 RL 推理能力由 `components/model_zoo/rl` 维护；人形方案负责机型观测、动作和控制链的对接。
- MuJoCo 与 `whole_body` 分别实现仿真和实机驱动后端，对 `control_runtime` 保持统一的机器人状态与控制语义。
- ROS 2 桥接复用 Native 状态机，不另建一套底层运控。`humanoid_mujoco` 是 `ros2_simulation` 仓库中的包，其仿真节点承担 DRIVER 角色，不能与同一控制链的 `driver_runtime` 重复启动；仿真里程计不等同于实机状态估计。
- 在线训练、VLA、导航和任务编排不是当前运动控制运行时的内部子模块，通过上层功能域与稳定接口组合。

进程关系和控制数据流见[运行时通信与安全](3.4.2.3-运行时通信与安全.md)，本体硬件边界见[整机控制与硬件后端](../3.4.3-本体接入/3.4.3.3-整机控制与硬件后端.md)。

## 4. 验收边界

`humanoid_common`、RL 推理、MuJoCo 和 `whole_body` 都提供构建定义与离线测试入口；具体策略、机型和硬件链路是否可用，仍以对应机型包和发布版本的验证记录为准。

代码存在、仿真通过、K3 策略推理和真实机器人闭环是不同的验收层级。本页只说明软件责任边界，不将组件或后端的存在等同于所有机型已经完成实机验收。

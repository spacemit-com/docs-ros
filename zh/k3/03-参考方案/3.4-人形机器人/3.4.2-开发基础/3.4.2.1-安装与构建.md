# 安装与构建

本页统一说明人形方案在 x86_64 PC 与 K3 板卡上的依赖、代码获取和构建方法。后续仿真和部署页面不再重复这些步骤。

## 1. x86_64 PC 端依赖

支持 Ubuntu 22.04 或 24.04。安装系统依赖：

```bash
sudo apt install -y libeigen3-dev libyaml-cpp-dev libglfw3-dev cmake g++
```

### MuJoCo 与 ONNX Runtime

x86_64 端编译 `simulation/mujoco` 或 `model_zoo/rl` 时，CMake 按以下顺序查找三方包，命中即用：

1. `-DMUJOCO_DIR=...` 或 `-DONNXRUNTIME_DIR=...` 编译参数。
2. 同名环境变量。
3. 系统路径（`/usr/local`、`/usr`、`/opt/mujoco` 等）。
4. 缓存路径 `~/.cache/thirdparty/<name>/<version>/`。
5. 上述均未命中时，从官方 release 拉取预编译包并解压到缓存路径。

| 三方包 | 缓存路径 |
| --- | --- |
| MuJoCo 3.4.0 | `~/.cache/thirdparty/mujoco/mujoco-3.4.0/` |
| ONNX Runtime 1.21.0 | `~/.cache/thirdparty/onnxruntime/onnxruntime-linux-x64-1.21.0/` |

离线或受限网络环境应先准备三方包，并指向实际安装目录：

```bash
export MUJOCO_DIR=/path/to/mujoco
export ONNXRUNTIME_DIR=/path/to/onnxruntime
```

在相应组件目录使用 `mm -DSROBOTIS_THIRDPARTY_FETCH_OFF=ON` 可禁止缺少依赖时自动拉取；独立 CMake 构建同样传入该 `-D` 参数。它是 CMake 选项，不读取同名环境变量。

其他版本见 [MuJoCo Releases](https://github.com/google-deepmind/mujoco/releases) 和 [ONNX Runtime Releases](https://github.com/microsoft/onnxruntime/releases)，ONNX Runtime 版本要求不低于 1.17。

## 2. K3 板卡端依赖

安装系统依赖：

```bash
sudo apt install -y libeigen3-dev libyaml-cpp-dev pkg-config
```

RL 组件的 K3 ONNX Runtime 软件包和冲突处理以[强化学习](/k3/ai/rl)文档为准。`spacemit-tcm` 可按 TCM 诊断需要另行安装。

在 K3 编译 MuJoCo 组件还需 `libx11-dev`。渲染使用 X11/GLX 与 gl4es，由 gl4es 将桌面 OpenGL 转为 PowerVR GLES；gl4es 由组件的 CMake 查找或获取、打补丁并编译。

## 3. 获取代码

PC 与 K3 均需获取人形模块相关代码。SDK 通用说明见[快速入门 · 构建编译](../../../02-快速入门/2.3-构建编译.md)。

```bash
repo init -u https://github.com/spacemit-robotics/manifest.git -b main -m default.xml \
  --repo-url=https://gitee.com/spacemit-robotics/git-repo \
  -g core,model_zoo_rl,humanoid,simulation,control,peripherals
repo sync -j4
```

上述代码集合包含 LingLong 实机链路所需的 `whole_body`、电机和 IMU 组件。仅获取 G1 仿真代码时，可将分组缩减为 `core,model_zoo_rl,simulation,humanoid_common,humanoid_unitree_g1`。

## 4. 选择目标并编译

以 G1 为例，其他机型需替换目标名称：

```bash
source build/envsetup.sh
lunch k3-com260-kit-humanoid-unitree-g1
m
```

编译完成后，脚本和可执行文件安装到 `output/staging/bin/`。`envsetup.sh` 会将该目录加入 `PATH`，完成 `source` 后可直接运行脚本。

构建系统按 target JSON 的 `enabled_packages` 构建所需组件。`humanoid_common` 的 CMake 根据安装目录内的库和头文件探测 MuJoCo、`whole_body` 后端，至少找到一个才生成 `driver_runtime`；运行时再由 YAML 的 `driver.backend` 选择。当前 `enabled_backends` 字段未接入后端编译选择，不能仅靠修改该字段启用后端。

PC + K3 跨机仿真由 PC 运行 MuJoCo driver，K3 运行控制端；K3 本机仿真还需在 K3 编入 MuJoCo 后端，实机 target 则需包含 `whole_body` 和对应外设组件。

完成构建后，按目标环境进入[仿真部署与评测](../3.4.8-仿真部署与评测/index.md)。机型包、target 与运行配置之间的关系见[机型包与配置](3.4.2.4-机型包与配置.md)。

# 快速开始

本页给出 PC 单机 Sim2Sim 的最短验证路径。MuJoCo、RL 推理和控制进程均运行在 x86_64 PC，不需要 K3 板卡。

## 1. 前置条件

- x86_64 PC，Ubuntu 22.04 或 24.04。
- 已按[安装与构建](3.4.2-开发基础/3.4.2.1-安装与构建.md)完成依赖安装、代码获取和目标编译。
- 对应机型的 `policy/` 目录中已有 RL 策略模型。若当前 target 提供模型下载脚本，可运行：

```bash
source build/envsetup.sh
download_models_g1.sh
```

以下以 Unitree G1 为例，其他机型需替换 target、配置和脚本名称。

## 2. 配置本机通信

将 `application/native/humanoid_unitree_g1/config/g1.yaml` 中的 `transport.type` 改为 `shm`：

```yaml
transport:
  type: "shm"

  shm:
    prefix: "g1"        # 共享内存名称前缀（通道：/hmrs_g1_state, /hmrs_g1_control, /hmrs_g1_hmi）
    capacity: 4         # 环形缓冲区槽位数
    slot_size: 4096     # 每个槽位大小（字节，需大于最大 packet）
```

也可以使用本机 UDP，将 `driver_ip` 与 `control_ip` 均配置为 `127.0.0.1`。

## 3. 启动仿真

终端 1 启动 MuJoCo 仿真驱动：

```bash
source build/envsetup.sh
run_driver_g1.sh
```

终端 2 启动 Sim2Sim 控制：

```bash
source build/envsetup.sh
run_sim2sim_g1.sh
```

程序会加载 YAML 中 `rl_policy.default_policy` 指定的策略。MuJoCo 窗口打开后，控制端直接进入 RL 推理循环；机器人应站立并保持姿态。

需要验证状态机、HMI 和策略切换时，继续阅读 [PC 单机仿真](3.4.8-仿真部署与评测/3.4.8.2-PC单机仿真.md)。需要验证 K3 端侧推理时，选择 [K3 跨机 FSM 仿真](3.4.8-仿真部署与评测/3.4.8.3-K3跨机FSM仿真.md)或 [K3 跨机 Sim2Sim](3.4.8-仿真部署与评测/3.4.8.4-K3跨机Sim2Sim.md)。

启动失败时参考[故障排查](3.4.10-故障排查/index.md)。

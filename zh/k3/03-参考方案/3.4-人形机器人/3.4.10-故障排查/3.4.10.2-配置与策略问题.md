# 配置与策略问题

| 现象 | 处理 |
| --- | --- |
| `配置文件不存在: ...` 或 `YAML 解析失败: ...` | 确认启动脚本传入的 YAML 路径；运行 `python3 -c "import yaml; yaml.safe_load(open('g1.yaml'))"` 检查格式。 |
| `[PolicyConfigLoader] ONNX 模型文件不存在: .../policy/...onnx` | 模型尚未下载。运行对应机型的下载脚本，例如 `download_models_g1.sh`，完成后重试。 |
| `[StateRL] IMU 倾角超限!` 后自动进入 SAFETY | 检查策略是否适配当前机型，核对单策略 `max_roll/max_pitch` 和全局 `behavior_manager.safety` 门限；不要为继续运行而盲目放宽。故障解除后还需在 POWER_OFF 下确认锁存故障。 |
| RL 控制不稳定或立即摔倒 | 检查模型输入输出与策略配置是否匹配，并核对 `action_joint_index` 到整机关节的映射及 `rl_default_pos`。 |
| 切到 dance 或 kungfu 后机器人停在 stand | 若目标策略配置了 `prerequisite: stand`，系统会先运行 stand，达到 `duration` 后再切换。检查控制日志、前置策略配置及其模型是否可正常加载。 |

机器人模型与机型 YAML 的关节定义应一致；策略的输入输出维度应与观测、动作配置匹配，动作通过 `action_joint_index` 映射到整机关节。仅控制部分关节的策略，其动作维度可以小于整机自由度。

# 运行时与通信问题

| 现象 | 处理 |
| --- | --- |
| `driver_runtime` 未生成或提示 backend 未编译 | 检查 target 的 `enabled_packages`、MuJoCo / `whole_body` 库与头文件是否已安装，以及 `humanoid_common` 的 CMake 探测日志；编入后再由 `driver.backend` 选择。当前 `enabled_backends` 未接入编译选择。 |
| 进程启动后通信无数据 | UDP：检查 `driver_ip`、`control_ip`、`hmi_ip` 和 state/control/hmi/status 四通道，默认端口为 8800～8803。SHM：运行 `ls /dev/shm/hmrs_*` 检查相同前缀下的四通道。两端须使用一致协议版本。 |
| `[Udp] bind 失败, ip=... port=...` | 端口被占用或 IP 不存在。运行 `ss -ulnp \| grep 880` 检查端口占用，并确认 YAML 中填写的是本机实际 IP。 |
| HMI 已发送请求，但状态没有改变 | 检查 status 回传与 HMI 心跳；再确认 HOME/ZERO 是否到位、是否存在锁存故障。以 Control 回传为准，不以按键发送为成功。 |
| 故障解除后仍不能进入 DAMP/RL | 读取故障来源、代码和 active/latched 状态；确认 active 已清除，回到 POWER_OFF 后按 `x` 并等待确认。仍在发生的故障不可强行清除。 |
| 状态或动作超时触发 SAFETY | 对照 driver 状态年龄、RL 首帧等待、缓存动作年龄和推理时限，结合时序 CSV 检查实际延迟；不要仅放宽门限。 |

跨机问题应分别保存 PC 与 K3 两端日志，并确认监听地址、目标地址和端口与实际部署拓扑一致。日志配置和产物见[运行时通信与安全](../3.4.2-开发基础/3.4.2.3-运行时通信与安全.md#6-运行日志与诊断)。

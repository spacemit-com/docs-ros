# PC 单机仿真

## 1. 验证目标

在一台 x86_64 PC 上运行 MuJoCo 仿真、RL 推理与控制进程，用于开发阶段的快速迭代。PC 单机既可运行 FSM 全链流程，也可运行跳过 FSM 的 Sim2Sim 流程。

## 2. 硬件与前置条件

- x86_64 PC，Ubuntu 22.04 或 24.04。
- 已完成[安装与构建](../3.4.2-开发基础/3.4.2.1-安装与构建.md)。
- PC 已具备 ONNX Runtime。首次构建会自动拉取到 `~/.cache/thirdparty/onnxruntime/`，也可预装到 `/usr/local`。
- 对应机型的 `policy/` 目录中已有策略模型。

## 3. 配置通信

推荐使用本机 SHM 通信。修改 `application/native/humanoid_unitree_g1/config/g1.yaml`：

```yaml
transport:
  type: "shm"

  shm:
    prefix: "g1"        # 通道：state / control / hmi / status
    capacity: 4         # 环形缓冲区槽位数
    slot_size: 4096     # 每个槽位大小（字节，需大于最大 packet）
```

也可使用本机 UDP 通信，将 `transport.type` 设为 `udp`，并将 `driver_ip`、`control_ip` 与 `hmi_ip` 均设为 `127.0.0.1`。FSM 流程使用 8800～8803 四个端口，包含 Control 回传 HMI 的 status 通道。

## 4. 运行 Sim2Sim

终端 1 启动 MuJoCo 仿真驱动：

```bash
source build/envsetup.sh
run_driver_g1.sh
```

终端 2 启动 Sim2Sim 控制：

```bash
source build/envsetup.sh
run_sim2sim_g1.sh
```

该流程加载 YAML 中 `rl_policy.onnx_infer.default_policy` 指定的策略，无需 HMI 操作。以 `walk_mjlab` 和零初始速度为例，机器人应在 MuJoCo 中站立并保持姿态；需要 `policy_adapter` 提供参考动作或特殊模型输入的策略使用下面的 FSM 流程。

## 5. 运行 FSM 全链流程

终端 1 启动 MuJoCo 仿真驱动：

```bash
source build/envsetup.sh
run_driver_g1.sh
```

终端 2 启动 FSM 控制：

```bash
source build/envsetup.sh
run_control_g1.sh
```

终端 3 启动 HMI：

```bash
source build/envsetup.sh
run_hmi_g1.sh
```

在 HMI 主页面用 `→` 请求依次进入 DAMP、HOME、ZERO、RL；待 HOME 完成、ZERO 到位后再请求下一状态。兼容快捷键为 `o` → `h` → `z` → `r`。策略选择、速度控制和故障确认见 [K3 跨机 FSM 仿真](3.4.8.3-K3跨机FSM仿真.md#6-hmi-操作)。

## 6. 运行结果

MuJoCo 窗口打开且控制端持续收到仿真状态，说明进程间通信已建立。Sim2Sim 模式应直接运行默认策略；FSM 模式进入 RL 后，机器人应站立并响应 HMI 速度指令。

出现模型、通信、配置或控制异常时，参考[仿真问题](../3.4.10-故障排查/3.4.10.4-仿真问题.md)。

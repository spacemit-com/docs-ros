# 性能基准与验收

本页定义人形方案从模型推理、控制闭环到任务执行的统一测量口径。通用 RL 模型的接口与验证方法见[强化学习](/k3/ai/rl)。

## 测试环境

记录板卡、系统镜像、CPU 频率与温度、后台负载、SDK 提交、模型校验值、完整 YAML、实际推理后端和线程配置。比较前后版本时保持输入、控制周期、推理周期和统计窗口一致。

先按[强化学习文档](/k3/ai/rl)中的评测方法验证 ONNX 与 RL 组件，再测共享运行时；不要把这三层延迟混为同一指标。

## 实时性指标

`humanoid_common` 提供 `run_benchmark_humanoid_policy.sh`，直接复用实际运行时的 `FSM + StateRL + ThreadLoop`，测量“传感器快照 → 推理线程 → 动作缓存 → 控制线程采用新动作”的异步链路，并支持机型 `policy_adapter` 和参考动作。

完成组件构建和模型下载后，在 SDK 根目录运行：

```bash
cd output/staging/bin
./run_benchmark_humanoid_policy.sh g1 walk_mjlab \
  --provider cpu --threads 2 --affinity 0,1 \
  --ort-spinning off --rounds 1000 \
  --csv /tmp/g1_walk_mjlab_state_rl.csv
```

控制周期默认取 `behavior_manager.control_dt`，推理周期取 `rl_policy.rl_dt`。该工具只测周期运行，不提供吞吐模式；推理过载时沿用 StateRL 合并请求、使用最新快照的行为。

| 指标 | 测量范围 |
| --- | --- |
| 控制周期误差、推理触发抖动 | 周期任务能否按配置及时执行 |
| 唤醒延迟、推理耗时、release-to-publish | 从提交快照到推理结果发布 |
| publish-to-apply、action age、动作更新间隔 | 从结果发布到控制线程采用；action age 从快照 release 到该动作首次采用 |
| deadline miss、合并请求、未应用动作和旧动作复用 | 超时与过载对实际动作更新的影响 |

这里的 `action age` 包含推理耗时，与安全配置 `max_action_age_s` 从动作发布后开始计时的口径不同。报告保留平均值、P95、P99、Max 和原始 CSV，不只比较平均推理时间。

工具中的传感器状态由程序生成，不包含 transport、CAN/关节总线、执行器响应或物理闭环。整机端到端延迟必须结合仿真或实机日志另行测量。

## 稳定性指标

长时间采样应记录动作更新是否持续、超时和合并请求是否增长，以及 CPU 温度和资源占用。短参考动作可用 `--reference-loop` 在本次测试中循环；`--restart-smoke` 检查同一 StateRL 对象退出、重入后能否继续生成新动作。这两项均不代替真实机器人验收。

仿真或隔离测试中还应检查状态超时、推理异常和锁存故障恢复；具体处理见[运行时通信与安全](../3.4.2-开发基础/3.4.2.3-运行时通信与安全.md)。硬件故障注入需另行设计安全条件，不在运行中的实机上直接尝试。

## 任务指标

基础运控检查零速度站立、起步/停止、速度跟随、扰动恢复和状态切换；动作跟踪检查参考动作完成情况及跟踪误差。操作、导航和交互的任务指标随对应功能页补充，不将单模型推理通过换算为任务成功率。

## 结果记录

每次保留完整命令、stdout、CSV、机型配置和模型版本。运行时的 `metadata.json`、`artifacts.csv`、时序及策略日志可用于对齐配置、原始动作和最终下发目标，字段见[运行日志与诊断](../3.4.2-开发基础/3.4.2.3-运行时通信与安全.md#6-运行日志与诊断)。

结论明确写出测量层级：单模型、RL 组件、StateRL 异步运行时、MuJoCo 闭环或实机闭环。本页提供方法，不发布未经复测的历史性能数字。

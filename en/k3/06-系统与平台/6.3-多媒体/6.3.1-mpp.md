# Multimedia · MPP

## 1. Overview

- **Key Features**: MPP (Media Processing Platform) is the SPACEMIT media processing platform, providing core capabilities for video encoding/decoding, video input/output, and image processing. It supports H.264/H.265 encoding/decoding, JPEG encoding/decoding, video capture, display output, and more.
- **Specifications and Features**:
  - Video encoding: H.264/H.265/JPEG encoding, up to 4K@30fps
  - Video decoding: H.264/H.265/JPEG decoding, up to 4K@60fps
  - Video input (VI): MIPI CSI, USB UVC, and other interfaces
  - Video output (VO): HDMI, MIPI DSI, and other interfaces
  - Image processing (V2D): format conversion, scaling, rotation, etc.
  - Muxing/demuxing: MP4, RTSP, and other protocols
- **Directory Structure**:

  ```text
  mpp/
  ├── include/              # Public headers
  │   ├── venc.h           # Video encoding API
  │   ├── vdec.h           # Video decoding API
  │   ├── vi/              # Video input API
  │   ├── vo/              # Video output API
  │   ├── v2d/             # Image processing API
  │   └── sys/             # System management API
  ├── mpi/                 # MPI implementation layer
  │   ├── venc/            # Encoder implementation
  │   ├── vdec/            # Decoder implementation
  │   ├── vi/              # Video input implementation
  │   └── ...
  ├── al/                  # Abstraction layer (module plugins)
  ├── utils/               # Utility library
  ├── sample/              # Sample programs
  ├── test/                # Test programs
  └── CMakeLists.txt       # Build configuration
  ```

## 2. Environment Setup

### Prerequisites

- **Runtime Environment**: Linux kernel, CMake ≥ 3.16, gcc/g++ compiler (C11/C++14 support).

- **Dependencies and External Resources**:
  - Hardware codec driver (kernel module)
  - Third-party libraries: optional FFmpeg, live555 (for RTSP)

- **Environment Variables and Initialization**: Building via SDK requires running `source build/envsetup.sh` followed by `lunch <target>`.

- **Hardware and Connections**: SPACEMIT K1 chip or compatible platform, camera (MIPI/USB), display (HDMI/MIPI).

- **Tools and Permissions**: Access to `/dev/video*` and other device nodes requires appropriate permissions.

### Build

- **Getting the Code**:

  For SDK source acquisition and basic build environment setup, refer to [2.3 Building and Compilation](../../02-快速入门/2.3-构建编译.md). After completing SDK initialization, return to this document and continue.

  All subsequent commands are executed from the spacemit_robot SDK root directory.

- **Module Compilation**:

  ```bash
  source build/envsetup.sh
  cd components/multimedia/mpp
  mm
  ```

- **Artifacts**:
  - Libraries: `libmpp.so`, `libmpp_venc.so`, `libmpp_vdec.so`, etc.
  - Sample programs: `sample/sample_uvc_vdec`
  - Test programs: test executables in the `test/` directory (`test_venc_file`, `test_vdec_file`, etc.)

## 3. Example Usage (From Scratch)

### 3.1 USB Camera Capture and Decoding

**Prerequisites**: MPP compiled, USB camera connected

**Step 1**: Confirm the camera device

```bash
ls /dev/video*
```

Expected result: displays `/dev/video0` or similar device nodes

**Step 2**: Run the UVC capture and decoding sample

```bash
cd output/build/cmake/pkgs/components_multimedia_mpp/sample
# Specify the UVC device node (confirmed in Step 1) and output directory
./sample_uvc_vdec /dev/video0 ./nv12_output
```

Parameter description (command format: `./sample_uvc_vdec [options] [devNode] [outDir]`):

| Type | Parameter | Description |
| --- | --- | --- |
| Option | `--bind` | Use SYS_Bind mode (UVC→VDEC automatic stream transfer); default is manual mode (`UVC_GetFrame` → `VDEC_SendStream`) |
| Option | `-h`, `--help` | Display help information |
| Positional | `devNode` | UVC device node, default `/dev/video0` |
| Positional | `outDir` | Output directory, default `./nv12_output` |

> Note: Options like `--bind` are optional and must appear before positional parameters (`devNode`, `outDir`). The program parses parameters by position, stopping option recognition once it encounters a positional parameter. Therefore, placing `--bind` after the device node will cause it to be incorrectly interpreted as the device node path.

Usage examples:

```bash
./sample_uvc_vdec                              # Manual mode, default device and directory
./sample_uvc_vdec --bind                       # Bind mode, default device and directory
./sample_uvc_vdec /dev/video0 ./nv12_output    # Manual mode, custom device and directory
./sample_uvc_vdec --bind /dev/video0 ./nv12_output  # Bind mode, custom device and directory
```

Expected result: The program captures the USB camera video stream, decodes it, and displays frame rate and resolution information

### 3.2 Video Encoding Example (File to File)

Use `test_venc_file` to encode raw YUV frames to H.264 bitstream.

**Prerequisites**: See Section 2

**Step 1**: Enter the test program directory

```bash
cd output/build/cmake/pkgs/components_multimedia_mpp/test
```

**Step 2**: Run the encoding test

```bash
./test_venc_file ../../../../../../components/multimedia/mpp/test/assets/vi_phy0_last_frame.yuv 1920 1080 ./enc_out.h264 h264 1
```

Parameter description:

| Parameter | Meaning |
| ------------------------------------------------------------------------------ | ----------------------------------- |
| ../../../../../../components/multimedia/mpp/test/assets/vi_phy0_last_frame.yuv | Input YUV file path |
| `1920` | Image width |
| `1080` | Image height |
| `./enc_out.h264` | Output bitstream file path |
| `h264` | Encoding format (supports `h264`, `h265`) |
| `1` | Number of frames to encode |

Expected result:

```text
[INFO] VENC file test: ../../../../../../components/multimedia/mpp/test/assets/vi_phy0_last_frame.yuv 1920x1080 -> ./enc_out.h264 (H.264), frames=1
[INFO] encoded frame 0: size=63778 key=0 pts=0
[INFO] done, encoded 1 frame(s)
```

After encoding, the `enc_out.h264` file is generated in the current directory. Verify using `ffplay enc_out.h264`.

### 3.3 Video Decoding Example (File to File)

Use `test_vdec_file` to decode compressed bitstream to raw YUV frames.

**Prerequisites**: See Section 2

**Step 1**: Enter the test program directory

```bash
cd output/build/cmake/pkgs/components_multimedia_mpp/test
```

**Step 2**: Run the decoding test (MJPEG example)

```bash
./test_vdec_file ../../../../../../components/multimedia/mpp/test/assets/1920x1080.jpg 1920 1080 ./dec_out_nv12.yuv mjpeg
```

Parameter description:

| Parameter | Meaning |
| ------------------------------------------------------------------------- | ---------------------------------------------- |
| `../../../../../../components/multimedia/mpp/test/assets/1920x1080.jpg` | Input bitstream file path |
| `1920` | Image width |
| `1080` | Image height |
| `./dec_out_nv12.yuv` | Output YUV file path |
| `mjpeg` | Decoding format (supports `h264`, `h265`, `mjpeg`) |

Expected result:

```text
[INFO] VDEC file test: ../../../../../../components/multimedia/mpp/test/assets/1920x1080.jpg -> ./dec_out_nv12.yuv, codec=mjpeg, size=105692
[INFO] decoded frame: 1920x1080 planes=2 stride=1920 pts=0
```

After decoding, the `dec_out_nv12.yuv` file is generated in the current directory. Verify using the following command:

```bash
ffplay -f rawvideo -pix_fmt nv12 -s 1920x1080 dec_out_nv12.yuv
```

## 4. Application Development

- **API / Interface**:

  - Headers: `include/venc.h`, `include/vdec.h`, `include/vi/`, `include/vo/`, etc.
  - Libraries: `libmpp.so` and sub-module libraries
  - Main APIs:
    - Encoding: `venc_ctx_create()`, `venc_ctx_init()`, `venc_ctx_encode()`, `venc_ctx_destroy()`
    - Decoding: `vdec_ctx_create()`, `vdec_ctx_init()`, `vdec_ctx_decode()`, `vdec_ctx_destroy()`
    - Video input: VI module APIs
    - Video output: VO module APIs
- **Usage and Notes**:

  - Initialization sequence: create context, initialize, then set parameters
  - Thread safety: a single context does not support concurrent multi-threading; upper-layer locking is required
  - Memory management: input/output buffers must use MPP-provided memory allocation interfaces
  - Resource cleanup: always release resources in order after use (stop first, then destroy context)
  - Hardware acceleration: encoding/decoding automatically uses hardware acceleration without additional configuration
- **Reference demos and example paths**: `mpp/sample/sample_uvc_vdec.c`, `mpp/test/test_venc_file.c`, `mpp/test/test_vdec_file.c`

## 5. Debugging Guide

- Kernel log: `dmesg | grep -E "vpu|codec|MPP"` to view hardware codec logs
- Device nodes: `ls -l /dev/video*` to confirm video devices
- Performance analysis: use the `time` command to measure encoding/decoding duration
- Frame rate statistics: add timestamps in code to calculate actual frame rate

## 6. FAQ

| Symptom | Possible Cause | Resolution |
| -------------- | ------------------------ | ---------------------------------------- |
| Encoding initialization failure | Hardware encoder plugin not loaded | Check if libv4l2_linlonv5v7_codec2.so exists |
| Decoding artifacts | Bitstream format unsupported or corrupted | Confirm bitstream format, use standard test bitstream |
| Low frame rate | High CPU load or insufficient memory bandwidth | Optimize code, reduce memory copies |
| Device node does not exist | Camera not connected or driver not loaded | Check hardware connection, load driver module |

# Multimedia · audio_process

## 1. Overview

audio_process currently includes the DOA (Direction of Arrival) sound localization component, located at `components/multimedia/audio_process/doa`. Based on GCC-PHAT (Generalized Cross-Correlation with Phase Transform), the component localizes sound sources from two-channel audio and outputs the source angle, TDOA, and confidence.

Algorithm Pipeline:

```text
Two-channel input -> Hann window -> FFT -> Cross-power spectrum -> PHAT weighting
    -> Frequency-domain upsampling -> IFFT -> Peak search -> Parabolic interpolation -> TDOA -> DOA
```

The output angle range is `[0°, 180°]`: `90°` indicates directly in front, while `0°` and `180°` indicate the two endfire directions. Different physical channel placements may produce supplementary angles. `ssl_demo` can output `180 - doa` with `--flip`; for example, `0° -> 180°` and `50° -> 130°`.

Main Directories:

| Path | Description |
| --- | --- |
| `components/multimedia/audio_process/doa/include/doa_service.h` | Public C++ API |
| `components/multimedia/audio_process/doa/src/sound_locator.cpp` | GCC-PHAT implementation |
| `components/multimedia/audio_process/doa/examples/ssl_demo.cpp` | C++ example; produces `ssl_demo` |
| `components/multimedia/audio_process/doa/python/` | Python package `spacemit_audio_process` and examples |

DOA is a pure algorithm library and does not require model files. Install missing dependencies first:

```bash
sudo apt install build-essential cmake libfftw3-dev
```

When building the component as part of the voice pipeline, you can use the `target/k3-com260-omni-agent.json` target configuration. The full build for this target does not include audio_process / DOA by default. To use DOA, build it separately from the component directory in the SDK root:

```bash

lunch k3-com260-omni-agent
cd components/multimedia/audio_process/doa
mm
```

After building, `ssl_demo` is installed to `output/staging/bin`. If you need the Python examples, build all Python wheels from the SDK root:

```bash
m -py
```

Alternatively, you can build only this component's Python wheel from the DOA component directory:

```bash
cd components/multimedia/audio_process/doa
mm -py
```

Note: `m -py` / `mm -py` builds wheels with the system Python environment; do not run these commands inside `~/.comm-env`. Use `~/.comm-env` only for the subsequent `pip install` commands and for running Python examples.

```bash
sudo apt install python3-venv python-is-python3 python3-pip
```

## 3. Example Usage

### 3.1 Synthetic Signal Accuracy Test

```bash
ssl_demo -t -d 0.058
```

The `-d 0.058` parameter specifies a microphone spacing of 0.058 m. Adjust it to match the actual hardware. This mode generates synthetic two-channel signals at different angles and reports the estimated angle, error, confidence, and pass/fail result.

To flip the output angle:

```bash
ssl_demo -t -d 0.058 --flip
```

Python version:

```bash
cd components/multimedia/audio_process/doa/python/examples
python ssl_demo.py -t -d 0.058
```

The Python version also supports `--flip`:

```bash
python ssl_demo.py -t -d 0.058 --flip
```

### 3.2 WAV File Test

Run the following command with your own two-channel PCM16 WAV file:

```bash
ssl_demo -f <stereo.wav> -d 0.058
```

Enable per-frame output:

```bash
ssl_demo -f <stereo.wav> -d 0.058 -v
```

If the hardware channel orientation is opposite to the expected orientation, add `--flip` to output the supplementary angle:

```bash
ssl_demo -f <stereo.wav> -d 0.058 --flip
```

Python version:

```bash
python ssl_demo.py -f <stereo.wav> -d 0.058 -v
```

The Python WAV example also supports flipped output:

```bash
python ssl_demo.py -f <stereo.wav> -d 0.058 --flip
```

The input file must be a two-channel WAV file. This document does not assume that the repository includes a test WAV file; the WAV results below are provided as K3 test data.

### 3.3 Live Capture

`ssl_demo` supports live capture mode, but the audio component must be found at build time and linked with PortAudio:

```bash
ssl_demo -l -d 0.058
```

If the live output is the supplementary angle of the expected value:

```bash
ssl_demo -l -d 0.058 --flip
```

Python live mode depends on `spacemit-audio`; see [Build](#build) for installation instructions:

```bash

```

## 4. Application Development

This section explains how application developers can integrate the sound localization component into their own C++/Python applications. The complete API is documented in `components/multimedia/audio_process/doa/include/doa_service.h`; this section covers only the commonly used public interfaces and typical calling patterns. **The DOA component's C++ namespace is `SpacemitAudio::`**, consistent with the audio component. The Python entry point is `spacemit_audio_process.SoundLocator`.

### 4.1 API Reference

The DOA component uses GCC-PHAT for two-channel time-delay estimation. The main entry point is `SpacemitAudio::SoundLocator`. The application supplies the microphone spacing through `mic_distance`, passes stereo PCM data, and reads the localization results.

#### 4.1.1 Common Data Structures

| Type | Description |
| --- | --- |
| `SoundLocatorConfig` | Engine configuration. See the following table for details. **`mic_distance` must match the actual microphone spacing; otherwise, the DOA result will be inaccurate** |
| `SoundLocator` | Main localization class, with `Initialize`, `Reset`, three `Process` overloads, and result getters |

`SoundLocatorConfig` fields:

| Parameter | Default | Description |
| --- | --- | --- |
| `sample_rate` | 16000 | Input stereo sample rate |
| `mic_distance` | 0.058 | Microphone spacing in meters; **change this to the actual hardware value**. The 5.8 cm development-board default is only an example |
| `sound_speed` | 343.0 | Speed of sound (m/s); the default is suitable for normal room conditions |
| `fft_size` | 0 | FFT length; `0` means automatic selection: `2 * frame_size` |
| `frame_size` | 512 | Samples per frame; 512 samples is approximately 32 ms at 16 kHz |
| `avg_frames` | 4 | Number of frames accumulated before producing a result; higher values improve stability but increase latency |
| `confidence_threshold` | 0.1 | Normalized GCC peak-confidence threshold; `IsValid()` returns false below this value |
| `upsample_factor` | 0 | TDOA upsampling factor; `0` selects approximately 4 μs resolution automatically. For microphone spacing below 5 cm, consider setting it manually, such as 8 or 16 |
| `use_fftw_measure` | false | Whether to use `FFTW_MEASURE` to optimize FFT planning during `Initialize()`; initialization is slower but runtime is faster |

#### 4.1.2 Engine Initialization

| Interface | Description | Parameters | Return Value |
| --- | --- | --- | --- |
| `SoundLocator(SoundLocatorConfig)` | Construct the locator; FFT plans are not initialized automatically | `config`: `SoundLocatorConfig` | Instance |
| `Initialize()` | Allocate FFT plans and internal buffers; **must be called once before `Process`** | None | `bool` |
| `Reset()` | Clear the multi-frame accumulator and cached results so the instance can be reused after a context switch or for a new localization interval | None | None |
| `GetConfig()` / `GetMaxDelaySamples()` | Query configuration; `GetMaxDelaySamples()` returns the integer value of `mic_distance / sound_speed * sample_rate`, which can be used to check whether the input delay is within a reasonable range | None | Respective types |

#### 4.1.3 Processing API

| Interface | Description | Parameters | Return Value |
| --- | --- | --- | --- |
| `Process(const float* interleaved, size_t num_frames)` | Process interleaved stereo float data `[L, R, L, R, ...]` | `interleaved`: interleaved samples; `num_frames`: number of frames (2 floats per frame) | `bool`; true when enough frames have been accumulated to produce a new result |
| `Process(const float* ch0, const float* ch1, size_t num_frames)` | Process two separate float channels | Channel pointers; number of frames | Same as above |
| `Process(const int16_t* interleaved, size_t num_frames)` | Process interleaved stereo PCM16; commonly used directly with an `AudioCapture` callback | `interleaved`: PCM16; `num_frames`: number of frames | Same as above |

#### 4.1.4 Result Queries

| Interface | Description | Parameters | Return Value |
| --- | --- | --- | --- |
| `GetDOA()` | Azimuth from the most recent accumulated window | None | `float`, in degrees, range [0, 180]. `90°` = broadside (perpendicular to the array), `0°` = ch1-side endfire, `180°` = ch0-side endfire |
| `GetTDOA()` | Time difference of arrival from the most recent accumulated window | None | `float`, in seconds |
| `GetConfidence()` | Normalized GCC peak confidence | None | `float`, [0, 1] |
| `IsValid()` | `GetConfidence() >= confidence_threshold` | None | `bool` |
| `GetAverageDOA()` | Confidence-weighted DOA across all valid batches since the last `Reset()`; near endfire, this prevents outliers on the opposite side from pulling the result back toward 90° | None | `float`, in degrees. Returns `90` when no valid result is available |
| `GetResultCount()` | Number of valid results produced since the last `Reset()` | None | `int` |

#### 4.2.1 Offline WAV Localization

Use case: evaluate DOA accuracy with a recorded stereo WAV file, typically for regression testing or parameter calibration.

Steps:

1. Configure `SoundLocatorConfig` and **set `mic_distance` correctly**
2. Construct `SoundLocator` and call `Initialize`
3. Pass the complete stereo PCM16 buffer to `Process(int16, num_frames)` at once, or send it in `frame_size` chunks in a loop
4. Read `GetDOA()` / `GetConfidence()` / `IsValid()`

```cpp
#include <iostream>
#include <vector>
#include "doa_service.h"

void LocateOnce(const std::vector<int16_t>& interleaved_stereo,
                int sample_rate, float mic_distance) {
    SpacemitAudio::SoundLocatorConfig cfg;
    cfg.sample_rate = sample_rate;
    cfg.mic_distance = mic_distance;
    cfg.frame_size = 512;
    cfg.avg_frames = 4;

    SpacemitAudio::SoundLocator loc(cfg);
    if (!loc.Initialize()) {
        std::cerr << "Initialize failed" << std::endl;
        return;
    }

    size_t num_frames = interleaved_stereo.size() / 2;
    if (loc.Process(interleaved_stereo.data(), num_frames) && loc.IsValid()) {
        std::cout << "DOA: " << loc.GetDOA() << "°"
                  << "  TDOA: " << loc.GetTDOA() * 1e6 << "μs"
                  << "  conf: " << loc.GetConfidence() << std::endl;
    }
}
```

For the complete example, including synthetic accuracy tests, command-line parsing, and angle flipping, see `components/multimedia/audio_process/doa/examples/ssl_demo.cpp`.

#### 4.2.2 Real-Time Streaming Localization

Use case: connect directly to an `AudioCapture` microphone callback and output a sliding-window DOA once per second, typically for turning a robot toward a sound source or controlling the beamforming direction.

Steps:

1. Configure `AudioCapture` for stereo capture (`channels=2`)
2. In the capture callback, reinterpret the PCM16 bytes as `int16_t*` and pass the frame count to `loc.Process(int16, num_frames)`; **avoid expensive computation in the callback**. The FFT inside `Process` is lightweight, but keeping the hot path limited to passing data and reading results is still recommended
3. Periodically call `GetAverageDOA()` from the application thread to obtain the direction

```cpp
#include <atomic>
#include <chrono>
#include <iostream>
#include <thread>
#include "audio_base.hpp"
#include "doa_service.h"

int main() {
    SpacemitAudio::SoundLocatorConfig cfg;
    cfg.sample_rate = 16000;
    cfg.mic_distance = 0.058f;   // Change to your hardware value
    cfg.frame_size = 512;
    cfg.avg_frames = 4;
    cfg.confidence_threshold = 0.1f;

    SpacemitAudio::SoundLocator loc(cfg);
    if (!loc.Initialize()) return 1;

    SpacemitAudio::AudioCapture capture(-1);
    capture.SetCallback([&](const uint8_t* data, size_t size) {
        const auto* pcm = reinterpret_cast<const int16_t*>(data);
        size_t num_frames = (size / sizeof(int16_t)) / 2;   // Stereo
        loc.Process(pcm, num_frames);
    });
    capture.Start(16000, 2, 4096);   // Stereo, 4096 bytes ≈ 64ms

    for (int i = 0; i < 30; ++i) {
        std::this_thread::sleep_for(std::chrono::seconds(1));
        if (loc.GetResultCount() > 0) {
            std::cout << "[" << i << "s] avg DOA = "
                      << loc.GetAverageDOA() << "°"
                      << "  results=" << loc.GetResultCount() << std::endl;
        }
        loc.Reset();   // Start a new window every second
    }

    capture.Stop();
    capture.Close();
    return 0;
}
```

Shorter `Reset()` intervals provide faster response; longer intervals provide greater stability. A typical interval is 200 ms to 1 s.

#### 4.2.3 Custom Confidence Filtering

Use case: in a noisy environment or when the speaker is not directly in front of the microphones, confidence may drop significantly. The application can decide whether to use the DOA result based on its specific requirements.

Steps:

1. Set `confidence_threshold` higher than the default `0.1`, such as `0.3`
2. If microphone spacing is below 5 cm, increase `upsample_factor` to improve TDOA resolution
3. Filter single-frame results with `IsValid()`, then apply temporal smoothing with `GetAverageDOA()`

```cpp
SpacemitAudio::SoundLocatorConfig cfg;
cfg.sample_rate = 16000;
cfg.mic_distance = 0.040f;     // 4 cm compact array
cfg.confidence_threshold = 0.3f;
cfg.upsample_factor = 8;       // Improve resolution to about 0.5 μs
cfg.avg_frames = 8;            // Enlarge the averaging window

SpacemitAudio::SoundLocator loc(cfg);
loc.Initialize();

// After processing the stream
if (loc.GetResultCount() >= 4 && loc.IsValid()) {
    float doa = loc.GetAverageDOA();
    if (std::abs(doa - 90.0f) > 5.0f) {     // Only output when more than 5° off the front direction
        std::cout << "Sound source direction: " << doa << "°" << std::endl;
    }
}
```

#### 4.3.1 Offline Localization

```python
import numpy as np
from spacemit_audio_process import SoundLocator, SoundLocatorConfig

cfg = SoundLocatorConfig()

cfg.mic_distance = 0.058       # Change to your hardware value
cfg.frame_size = 512
cfg.avg_frames = 4

loc = SoundLocator(cfg)
loc.initialize()

# Stereo PCM16, shape: [num_frames * 2]
stereo_int16 = np.zeros(16000 * 2, dtype=np.int16)  # 1 second of silence as a placeholder
loc.process_int16(stereo_int16)

if loc.is_valid:
    print(f"DOA={loc.doa:.1f}°, TDOA={loc.tdoa*1e6:.1f}μs, conf={loc.confidence:.3f}")
print(f"avg_doa={loc.average_doa:.1f}°, count={loc.result_count}")
```

#### 4.3.2 Context Manager and Real-Time Sliding Window

`SoundLocator` supports the `with` syntax (`__exit__` calls `reset()`, but **`__enter__` does not call `initialize()` automatically**). In a typical real-time pipeline, call `process_int16` from the capture thread and read properties from the application thread:

```python
import time
import numpy as np
import spacemit_audio
from spacemit_audio_process import SoundLocator, SoundLocatorConfig

cfg = SoundLocatorConfig()
cfg.sample_rate = 16000
cfg.mic_distance = 0.058
cfg.frame_size = 512

# Bytes per stereo int16 frame: frame_size * channels * sizeof(int16)
chunk_size = cfg.frame_size * 2 * 2

with SoundLocator(cfg) as loc:
    loc.initialize()  # __enter__ does not initialize automatically; call it explicitly

    spacemit_audio.init(sample_rate=cfg.sample_rate, channels=2, chunk_size=chunk_size)
    cap = spacemit_audio.AudioCapture()

    def on_audio(data: bytes):
        pcm = np.frombuffer(data, dtype=np.int16)
        loc.process_int16(pcm)

    cap.set_callback(on_audio)
    cap.start(sample_rate=cfg.sample_rate, channels=2, chunk_size=chunk_size)
    try:
        for i in range(30):
            time.sleep(1.0)
            if loc.result_count > 0:
                print(f"[{i}s] avg DOA = {loc.average_doa:.1f}°"
                      f"  results={loc.result_count}")
    finally:
        cap.stop()
```

`with SoundLocator(...)` only resets the locator on exit. Similarly, `AudioCapture.__enter__` only returns `self`; **call `start()` and `initialize()` explicitly**.

#### 4.3.3 C++ ↔ Python Interface Mapping

| C++ (`SpacemitAudio::`) | Python (`spacemit_audio_process.`) | Notes |
| --- | --- | --- |
| `SoundLocatorConfig` | `SoundLocatorConfig()` | Python fields use the same names (`sample_rate`, `mic_distance`, etc.) |
| `SoundLocator(cfg)` + `Initialize()` | `SoundLocator(cfg)` + `loc.initialize()` | Python `__enter__` only returns `self` and does not call `initialize()`; `__exit__` only calls `reset()` |
| `Process(const float* interleaved, n)` | `loc.process(stereo_float_numpy)` | Accepts one-dimensional or two-dimensional `numpy` arrays and flattens them automatically |
| `Process(const int16_t* interleaved, n)` | `loc.process_int16(stereo_int16_numpy)` | Directly accepts PCM16 data from `AudioCapture` |
| `Process(const float* ch0, const float* ch1, n)` | `loc.process_separate(ch0, ch1)` | Two separate one-dimensional float arrays |
| `GetDOA() / GetTDOA() / GetConfidence() / IsValid() / GetAverageDOA() / GetResultCount() / GetMaxDelaySamples() / GetConfig()` | `loc.doa` / `loc.tdoa` / `loc.confidence` / `loc.is_valid` / `loc.average_doa` / `loc.result_count` / `loc.max_delay_samples` / `loc.config` | All Python interfaces are properties; there are no getter methods |
| `Reset()` | `loc.reset()` | Corresponding name |

More Python examples are available in `components/multimedia/audio_process/doa/python/examples/`.

## 5. Debugging Guide

When debugging DOA, first fix the microphone spacing and channel orientation, then compare synthetic-signal, WAV-file, and live-capture results:

- Use synthetic signal mode, `ssl_demo -t -d <mic_distance>`, to rule out recording-chain issues
- Use WAV-file mode to reproduce specific hardware samples; enable `-v` to view per-frame angles and confidence
- Before live capture, use the audio component to confirm that a two-channel input device is available
- If the angle is supplementary, first use `--flip` to verify channel orientation, then decide whether the application should swap channels or output `180 - doa`

## 6. FAQ

| Symptom | Possible Cause | Resolution |
| --- | --- | --- |
| Angle is supplementary to the expected value | The physical left/right channel placement is opposite to the algorithm's assumption | Add `--flip` to `ssl_demo`; in an integrated application, swap the channels or use `180 - doa` |
| Large error near 0° / 180° | Microphone spacing is incorrectly configured | Measure `mic_distance` precisely; endfire angles are sensitive to millimeter-level errors |
| No valid result | Low confidence or input is not two-channel | Check the WAV channel count; lower `confidence_threshold` for testing |
| Unstable results | Single-frame noise or reverberation | Increase `avg_frames` or smooth the output in the application |

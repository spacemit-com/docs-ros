# 6.3.3 Audio

## 1. Overview

The audio component is located in `components/multimedia/audio` and provides audio capture, playback, full-duplex I/O, WAV file reading/writing, and resampling capabilities based on PortAudio. Voice modules such as ASR, TTS, VAD, and `omni_agent` rely on it for microphone input, speaker output, and sample rate conversion.

Key Features:

| Category | Support |
| --- | --- |
| Audio I/O | Recording, playback, input/output device enumeration, and full-duplex streaming |
| Data Format | PCM16 little-endian and WAV files |
| Resampling | Linear resampling, optional libsamplerate support, and a RISC-V Vector optimization path |
| API | C++ `audio_base.hpp`, `audio_duplex.hpp`, `audio_resampler.hpp`; Python package `spacemit_audio` |
| Examples | C++ `audio_demo`; Python `python/examples/audio_demo.py` |

Typical Data Pipeline:

```text
Microphone/Sound Card -> AudioCapture -> PCM/WAV/Resampler -> Application Module
Application Module/WAV -> Resampler -> AudioPlayer -> Speaker/Sound Card
```

Main Directories:

| Path | Description |
| --- | --- |
| `components/multimedia/audio/include/audio_base.hpp` | `AudioCapture`, `AudioPlayer`, and global configuration |
| `components/multimedia/audio/include/audio_resampler.hpp` | `Resampler` C++/C API |
| `components/multimedia/audio/include/audio_duplex.hpp` | Full-duplex audio interface |
| `components/multimedia/audio/examples/audio_demo.cpp` | C++ example program |
| `components/multimedia/audio/python/` | Python package `spacemit_audio` and examples |

## 2. Environment Setup

### Prerequisites

- **Runtime Environment**: For SDK source acquisition and basic build environment setup, refer to [2.3 Building and Compilation](../../02-快速入门/2.3-构建编译.md). After completing SDK initialization, return to this document and continue with [Build](#build).

  All subsequent commands are executed from the spacemit_robot SDK root directory.

### Build

Install missing dependencies first:

```bash
sudo apt install portaudio19-dev libsndfile1-dev
sudo apt install libsamplerate0-dev pybind11-dev
```

When building as part of the voice pipeline, use the `target/k3-com260-omni-agent.json` target configuration. From the SDK root directory, build the audio component:

```bash
source build/envsetup.sh
lunch k3-com260-omni-agent
cd components/multimedia/audio
mm
```

After building, `audio_demo` will be installed to `output/staging/bin`. To build the Python wheel, run from the SDK root directory:

```bash
m -py
```

Note: `m -py` / `mm -py` builds the wheel with the system Python environment; do not run these commands inside `~/.comm-env`. Use `~/.comm-env` only for the subsequent `pip install` commands and for running Python examples.

Before running the Python examples, install the virtual-environment dependencies, then create and activate `~/.comm-env`:

```bash
sudo apt install python3-venv python-is-python3 python3-pip
python3 -m venv ~/.comm-env
source ~/.comm-env/bin/activate
```

Then install the Python package using one of two options. Option 1: install the released package directly:

```bash
python -m pip install spacemit-audio \
    --index-url https://git.spacemit.com/api/v4/projects/33/packages/pypi/simple
```

Option 2: return to the SDK root directory and install the locally built wheel:

```bash
python -m pip install output/wheels/components_multimedia_audio/spacemit_audio-*.whl \
    --index-url https://git.spacemit.com/api/v4/projects/33/packages/pypi/simple
```

After installation, you can `import spacemit_audio`.

## 3. Example Usage

### 3.1 List Devices

```bash
audio_demo list
```

The output is grouped into `Input Devices` and `Output Devices`. Use the device index shown here with the `-d` or `--device` option in subsequent recording and playback commands.

### 3.2 Recording

```bash
audio_demo record test.wav --duration 5 --rate 16000 --channels 2 --device -1
```

Expected log output includes:

```text
Recording 5s to test.wav...
Config: 16000Hz, 2ch, device=-1
Opened: 16000Hz, 2 channels
Saved ... to test.wav
```

`test.wav` can be used directly as input for ASR, voiceprint, or VAD file examples.

### 3.3 Playback

```bash
audio_demo play ./test.wav -c 2 -d 1
```

When the input WAV has a different sample rate or channel count from the playback device, the demo converts it automatically. K3 test logs show that 16kHz mono input is converted to 48kHz stereo before playback:

```text
Converting channels 1ch -> 2ch...
Resampling 16000Hz -> 48000Hz...
Opened: 48000Hz, 2 channels, write mode
Done
```

### 3.4 Python Example

After installing `spacemit-audio`, run:

```bash
cd components/multimedia/audio/python/examples
python audio_demo.py record test.wav --duration 5 --rate 16000 --channels 2 --device -1
python audio_demo.py play test.wav --device 1
```

Python examples also support device enumeration, recording, playback, and resampling.

## 4. Application Development

This section explains how application developers can integrate the audio component into their own C++/Python applications. The complete API is documented in `components/multimedia/audio/include/{audio_base,audio_duplex,audio_resampler}.hpp`; this section covers only the commonly used public interfaces and typical calling patterns. **The audio component's C++ namespace is `SpacemitAudio::`** (distinct from the `SpacemiT::` namespace used by other model_zoo components); the Python entry point is the `spacemit_audio` package.

### 4.1 API Reference

The audio component's core types are defined in three public headers: `audio_base.hpp` (capture, playback, and global configuration), `audio_duplex.hpp` (full-duplex), and `audio_resampler.hpp` (resampling, with no independent namespace). PortAudio invokes all callbacks from an internal thread; **do not perform time-consuming inference** in callbacks. Instead, push the data into a queue for processing by application threads.

#### 4.1.1 Common Data Structures

| Type | Description |
| --- | --- |
| `SpacemitAudio::AudioConfig` | Global default configuration: `sample_rate=16000`, `channels=1`, `chunk_size=3200` (bytes per capture callback), `capture_device=-1`, `player_device=-1` (-1 = system default) |
| `SpacemitAudio::AudioCapture::Callback` | Recording callback signature `void(const uint8_t* data, size_t size)`; `data` is PCM16 little-endian byte stream |
| `SpacemitAudio::AudioDuplex::Callback` | Full-duplex callback signature `void(const float* input, float* output, size_t frames, int channels)`; synchronous receive/send PCM float [-1.0, 1.0], `frames * channels` samples per call |
| `Resampler::Config` | Resampling configuration: `input_sample_rate`, `output_sample_rate`, `channels`, `method` (`LINEAR_UPSAMPLE` / `LINEAR_DOWNSAMPLE` / `SRC_SINC_*` etc.) |
| `ResampleMethod` | Resampling method enum: `LINEAR_*` always available; `SRC_*` series requires compile-time `USE_LIBSAMPLERATE`, otherwise automatically falls back to linear |

#### 4.1.2 Global Configuration

| Interface | Description | Parameters | Return Value |
| --- | --- | --- | --- |
| `Init(AudioConfig)` / `Init(int...)` | Set global default configuration; `AudioCapture`/`AudioPlayer` will use these values when passed `-1` | `AudioConfig` or specific fields; any field set to `-1` retains the current value | None |
| `GetConfig()` | Return current global configuration snapshot | None | `AudioConfig` |

#### 4.1.3 Capture and Playback

| Interface | Description | Parameters | Return Value |
| --- | --- | --- | --- |
| `AudioCapture(device_index=-1)` | Construct capture object; `-1` uses system default input | `device_index`: device index | Instance |
| `AudioCapture::SetCallback(cb)` | Register callback, must be called before `Start()` | `cb`: `std::function<void(const uint8_t*, size_t)>` | None |
| `AudioCapture::Start(sample_rate=-1, channels=-1, chunk_size=-1)` | Start capture; any parameter set to `-1` uses global config value | Audio parameters | `bool` |
| `AudioCapture::Stop()` / `Close()` / `IsRunning()` | Stop/close device/status query | None | None / `bool` |
| `AudioCapture::ListDevices()` | Static method that enumerates available input devices | None | `vector<pair<int, string>>`, with each element containing an index and device name |
| `AudioPlayer(device_index=-1)` | Construct player object | `device_index`: device index | Instance |
| `AudioPlayer::Start(sample_rate=-1, channels=-1)` | Start playback stream | Audio parameters | `bool` |
| `AudioPlayer::Write(vector<uint8_t>)` / `Write(uint8_t*, size_t)` | Write PCM16 byte stream | `data`: PCM16 LE bytes | `bool` |
| `AudioPlayer::PlayFile(file_path)` | **Blocking** playback of entire WAV file, internally handles reading, decoding, writing; returns when playback complete | `file_path`: WAV path | `bool` |
| `AudioPlayer::Stop()` / `Close()` / `IsRunning()` / `ListDevices()` | Corresponding capture controls and device enumeration | None | As above |

#### 4.1.4 Full-Duplex

| Interface | Description | Parameters | Return Value |
| --- | --- | --- | --- |
| `AudioDuplex(input_device=-1, output_device=-1)` | Construct full-duplex object, can independently specify input/output devices | Device indices | Instance |
| `AudioDuplex::SetCallback(cb)` | Register synchronous callback, must be called before `Start()` | `cb`: four-parameter callback (input PCM float, output buffer, frames, channels) | None |
| `AudioDuplex::Start(sample_rate=48000, channels=1, frames_per_buffer=480)` | Start full-duplex; **default 48kHz** (K3 sound card hardware limitation), `frames_per_buffer=480` means 10ms@48kHz | Audio parameters | `bool` |
| `AudioDuplex::Stop()` / `Close()` / `IsRunning()` | Status control and query | None | None / `bool` |
| `AudioDuplex::GetSampleRate()` / `GetChannels()` / `GetInputDevice()` / `GetOutputDevice()` | Configuration query | None | Respective types |
| `AudioDuplex::ListInputDevices()` / `ListOutputDevices()` | Static methods to list input/output devices separately | None | Same as `AudioCapture::ListDevices()` |

#### 4.1.5 Resampling

| Interface | Description | Parameters | Return Value |
| --- | --- | --- | --- |
| `Resampler(Config)` | Construct resampler | `Config` | Instance |
| `Resampler::initialize()` | Initialize internal buffers and method; must be called before `Start` | None | `bool` |
| `Resampler::process(vector<float>)` / `process(float*, num_samples)` | **One-shot** resampling; suitable for offline audio blocks | Float PCM | `vector<float>` |
| `Resampler::processStreaming(vector<float>, end_of_input=false)` | Streaming resampling; continuously feed chunks, set `end_of_input=true` on the last chunk to flush internal buffers | Float PCM; whether last chunk | `vector<float>` |
| `Resampler::reset()` | Clear internal state, reuse instance for next streaming audio segment | None | None |
| `Resampler::getRatio()` / `isUpsampling()` / `isDownsampling()` / `getConfig()` | Utility queries | None | Respective types |

### 4.2 C++ Usage Examples

After building the audio component, the above headers and `libspacemit_audio.so` are installed to `output/staging`. CMake for downstream components linking the audio library:

```cmake
add_executable(my_app main.cpp)

find_library(AUDIO_LIB NAMES spacemit_audio
    PATHS ${CMAKE_INSTALL_PREFIX}/lib NO_DEFAULT_PATH)
find_path(AUDIO_INCLUDE_DIR NAMES audio_base.hpp
    PATHS ${CMAKE_INSTALL_PREFIX}/include NO_DEFAULT_PATH)
if(NOT AUDIO_LIB OR NOT AUDIO_INCLUDE_DIR)
    message(FATAL_ERROR "spacemit_audio not found. Build components/multimedia/audio first.")
endif()

target_include_directories(my_app PRIVATE ${AUDIO_INCLUDE_DIR})
target_link_libraries(my_app PRIVATE ${AUDIO_LIB})
```

Package dependencies should be declared in `package.xml` as `<depend>audio</depend>`.

#### 4.2.1 Device Enumeration and Selection

Use case: list available audio devices so users can select a device, specify one in a configuration file, or provide one to a CLI tool with the `-l` parameter.

```cpp
#include <iostream>
#include "audio_base.hpp"

int main() {
    std::cout << "Input devices:" << std::endl;
    for (const auto& [idx, name] : SpacemitAudio::AudioCapture::ListDevices()) {
        std::cout << "  [" << idx << "] " << name << std::endl;
    }
    std::cout << "Output devices:" << std::endl;
    for (const auto& [idx, name] : SpacemitAudio::AudioPlayer::ListDevices()) {
        std::cout << "  [" << idx << "] " << name << std::endl;
    }
    return 0;
}
```

#### 4.2.2 Recording Callback

Use case: Continuously capture from microphone, pass PCM data to upstream processing (VAD, ASR, network transmission, etc.).

Steps:

1. Construct `AudioCapture(-1)` or specify device index.
2. `SetCallback(...)` to register data reception callback; **only lightweight operations in callback** (copy, enqueue), no inference.
3. `Start(sample_rate, channels, chunk_size)` to start; `chunk_size` is byte count, e.g., for 16kHz mono PCM16, 3200 bytes = 100ms.
4. Before exit, `Stop()` + `Close()`.

```cpp
#include <atomic>
#include <chrono>
#include <fstream>
#include <thread>
#include <vector>
#include "audio_base.hpp"

int main() {
    std::vector<uint8_t> buffer;
    std::atomic<bool> running{true};

    SpacemitAudio::AudioCapture capture(-1);
    capture.SetCallback([&](const uint8_t* data, size_t size) {
        buffer.insert(buffer.end(), data, data + size);   // Use lock or SPSC queue in real scenarios
    });
    if (!capture.Start(16000, 1, 3200)) return 1;

    std::this_thread::sleep_for(std::chrono::seconds(5));
    capture.Stop();
    capture.Close();

    // 5 seconds 16kHz mono PCM16 = 160000 bytes
    std::ofstream out("recording.pcm", std::ios::binary);
    out.write(reinterpret_cast<char*>(buffer.data()), buffer.size());
    return 0;
}
```

For the complete example, including WAV header handling, device listing, and command-line parameters, see `components/multimedia/audio/examples/audio_demo.cpp`.

#### 4.2.3 Playback (PCM and WAV Scenarios)

Use case: (a) PCM bytes are already available, such as a TTS synthesis result, and need to be sent directly to the speaker; or (b) a WAV file needs to be played directly.

```cpp
#include "audio_base.hpp"

void PlayPcm(const std::vector<uint8_t>& pcm16, int sample_rate) {
    SpacemitAudio::AudioPlayer player(-1);
    player.Start(sample_rate, 1);
    player.Write(pcm16);
    player.Stop();
    player.Close();
}

void PlayWav(const std::string& path) {
    SpacemitAudio::AudioPlayer player(-1);
    player.PlayFile(path);    // Blocking, internally completes Start/Write/Stop/Close
}
```

`PlayFile` is a blocking interface for synchronous scenarios such as "play a BGM segment then continue". For asynchronous or streaming synthesis and playback, refer to the streaming resampling and `Write` combination in [Section 4.2.5](#425-resampling-including-streaming), or see `tts_stream_demo.cpp`.

#### 4.2.4 Full-Duplex AEC Usage

Use case: when the hardware lacks built-in echo cancellation and software AEC is needed, such as in `omni_agent`'s `voice_chat_aec`. `AudioDuplex` pairs input and output in a synchronous callback, allowing the speaker output to be used as the AEC reference signal.

Steps:

1. Construct `AudioDuplex` and `SetCallback(...)`.
2. In the callback, feed `input` and the reference signal sent to the speaker into WebRTC AEC3 to obtain an echo-cancelled microphone signal, and write the content to be played to `output`.
3. `Start(48000, 1, 480)` to start; K3 sound card hardware limitation is 48kHz, `frames_per_buffer=480` means 10ms blocks.

```cpp
#include "audio_duplex.hpp"

int main() {
    SpacemitAudio::AudioDuplex duplex(-1, -1);
    duplex.SetCallback([&](const float* input, float* output,
                            size_t frames, int channels) {
        // 1. Feed input to AEC3, reference signal is content previously written to output
        // 2. Send AEC output to VAD/ASR
        // 3. Write audio to be played to output (silence placeholder here)
        for (size_t i = 0; i < frames * channels; ++i) output[i] = 0.0f;
    });
    if (!duplex.Start(48000, 1, 480)) return 1;

    // Application thread drives LLM/TTS and other high-level logic...

    duplex.Stop();
    duplex.Close();
    return 0;
}
```

Specific AEC3 integration code: see `application/native/omni_agent/src/aec_duplex_processor.cpp`.

#### 4.2.5 Resampling (Including Streaming)

Use case: the K3 sound card supports only 48kHz, so TTS output at 22050/16000/24000 Hz must be upsampled to 48000 before playback; ASR requires 16000Hz input, so 48000Hz microphone input must be downsampled.

```cpp
#include "audio_resampler.hpp"

// One-shot resampling (complete audio block available)
Resampler::Config cfg;
cfg.input_sample_rate = 22050;
cfg.output_sample_rate = 48000;
cfg.channels = 1;
cfg.method = ResampleMethod::LINEAR_UPSAMPLE;

Resampler resampler(cfg);
resampler.initialize();
std::vector<float> out = resampler.process(input_float_22k);

// Streaming resampling (feed as available, avoid edge distortion)
resampler.reset();
for (size_t i = 0; i + chunk <= input_float_22k.size(); i += chunk) {
    std::vector<float> piece(input_float_22k.begin() + i,
                              input_float_22k.begin() + i + chunk);
    bool last = (i + chunk == input_float_22k.size());
    auto resampled = resampler.processStreaming(piece, last);
    // resampled can be immediately written to AudioPlayer
}
```

RVV acceleration is enabled automatically on the K3 platform, with no extra configuration. In testing, 16k→48k mono resampling latency was < 1ms per 1024 samples.

### 4.3 Python Examples

The Python package is named `spacemit_audio`; for wheel installation, see the [Build](#build) section. The current Python package exposes only `AudioCapture` / `AudioPlayer` / `init` / `get_config` and **does not expose** `AudioDuplex` or `Resampler`. Use the C++ API for full-duplex and resampling.

```python
import spacemit_audio
```

#### 4.3.1 Recording

```python
from spacemit_audio import AudioCapture

chunks = []

with AudioCapture() as cap:
    cap.set_callback(lambda data: chunks.append(data))
    cap.start()
    import time; time.sleep(5)        # Record for 5 seconds
    cap.stop()

print(f"Total {sum(len(c) for c in chunks)} bytes PCM16")
```

The `AudioCapture()` constructor takes no parameters and uses the global defaults (16kHz mono). To change the device or sample rate, call `spacemit_audio.init(sample_rate=..., capture_device=...)` before constructing the object. The callback receives `data` as `bytes` (PCM16 LE).

#### 4.3.2 Playback

```python
from spacemit_audio import AudioPlayer

with AudioPlayer() as player:
    player.start(48000, 1)
    player.write(pcm16_bytes)
    player.stop()
```

Play WAV file directly (blocking):

```python
from spacemit_audio import AudioPlayer

with AudioPlayer() as player:
    player.play_file("test.wav")
```

#### 4.3.3 C++ ↔ Python Interface Mapping

| C++ (`SpacemitAudio::`) | Python (`spacemit_audio.`) | Notes |
| --- | --- | --- |
| `Init(AudioConfig)` / `GetConfig()` | `init(sample_rate=..., channels=..., chunk_size=..., capture_device=..., player_device=...)` / `get_config()` | Python uses keyword arguments; <br>`get_config()` returns dict |
| `AudioCapture(device)` + `SetCallback` + `Start/Stop/Close` | `AudioCapture()` context manager + `set_callback(fn)` + `start() / stop() / close()` | Python uses methods (not properties): `start()`, `stop()`, `is_running()` |
| `AudioCapture::ListDevices()` | `AudioCapture.list_devices()` (static) | Returns `[(index, name), ...]` |
| `AudioPlayer(device)` + `Start / Write / PlayFile / Stop / Close` | `AudioPlayer()` context manager + `start(rate, ch) / write(bytes) / play_file(path) / stop() / close()` | As above |
| `AudioDuplex` full-duplex | **Not exposed in Python** | Use C++ API when software AEC needed |
| `Resampler` resampling | **Not exposed in Python** | Python can use `numpy` + `scipy.signal.resample_poly` as an alternative, or implement linear interpolation. The `Resampler` built into `spacemit_asr` uses linear interpolation only and does not use libsamplerate |

More Python examples: see `components/multimedia/audio/python/examples/`. For integration with ASR/TTS/VAD, refer to [Section 4.3](#43-python-examples) in each model component's documentation.

## 5. Debugging Guide

When debugging audio, verify device enumeration, recording, playback, and sample rate conversion separately first:

- Use `audio_demo list`, `arecord -l`, `aplay -l` to cross-check device indices.
- For recording issues, save WAV and play back to confirm input is not silent, clipped, or mismatched channel count.
- For playback issues, check demo logs for channel conversion and resampling information.
- For Python issues, first confirm `~/.comm-env` is activated and `import spacemit_audio` works.

## 6. FAQ

| Symptom | Possible Cause | Solution |
| --- | --- | --- |
| Device not found | Sound card not enumerated or insufficient permissions | Check devices with `audio_demo list`, `arecord -l`, `aplay -l`. |
| Invalid sample rate error when opening stream | Sound card doesn't support that sample rate | Use 48kHz if supported by the device, or convert via `Resampler`. |
| Python `import spacemit_audio` fails | Virtual environment not activated, or Python package not installed | Activate `~/.comm-env`, then install `spacemit-audio` or the wheel in `output/wheels/components_multimedia_audio/`. |
| Abnormal playback speed | WAV sample rate doesn't match playback configuration | Use `audio_demo play`'s resampling parameters, or explicitly resample in application. |

# System Services · DMA

## 1. Overview

- **Key Features**: A user-space DMA copy library built on the `/dev/me_dma` kernel driver. It provides high-speed memory transfer capability, supports synchronous/asynchronous dma-buf copies, and can be used for zero-copy or efficient memory-transfer scenarios.
- **Specifications and Features**:
  - Supports three transfer directions: MEM_TO_MEM (memory to memory), MEM_TO_DEV (memory to device), and DEV_TO_MEM (device to memory).
  - Supports synchronous and asynchronous transfer modes.
  - Supports interrupt callbacks and cyclic mode (for audio/video streams).
  - Works together with libshm to implement cross-process zero-copy transfers.
- **Directory Structure**:

  ```
  components/system/dma/
  ├── include/dma.h          # Public API header
  ├── src/                   # Library implementation source
  ├── ko/                    # me_dma kernel driver
  │   ├── me_dma.c          # Driver source
  │   └── README.md         # Driver documentation
  ├── test/test_dma.c       # Test cases
  ├── CMakeLists.txt        # Build configuration
  └── README.md             # Module documentation
  ```

## 2. Environment Setup

### Prerequisites

- **Runtime Environment**: Linux kernel (with DMA-HEAP support), CMake ≥ 3.16, gcc/clang compiler.
- **Dependencies and External Resources**:
  - The `me_dma.ko` kernel driver module is loaded.
  - The libshm shared-memory library (in the sibling directory `../shm`).
  - The kernel must support DMA-HEAP and a DMA engine.
- **Environment Variables and Initialization**: If building through the SDK, first run `source build/envsetup.sh` and `lunch <target>`.
- **Hardware and Connections**: The target board must support a DMA engine; confirm that the `/dev/me_dma` device node exists.
- **Tools and Permissions**: Loading the kernel driver requires root privileges (`insmod`).

### Build

- **Getting the Code**: The code is located in the SDK's `components/system/dma` directory.
- **Module Compilation**:

    **Standalone build:**

    ```bash
    cd components/system/dma
    mkdir build && cd build
    cmake ..
    cmake --build .
    ```

    **Build via SDK `mm`:**

    ```bash
    source build/envsetup.sh
    lunch <target>
    cd components/system/dma
    mm clean && mm -v
    ```

- **Artifacts**:
  - User-space library: `libdma.so` or `libdma.a`
  - Kernel driver: `dma/ko/build/output/me_dma.ko`
  - Test program: `build/output/test_dma`

### 3.1 Basic DMA Copy Test

**Prerequisites**: libdma and me_dma.ko are built; the target board is powered on and accessible via serial or SSH.

**Step 1**: Load the kernel driver.

```bash
cd components/system/dma/ko/build/output
sudo insmod me_dma.ko
```

Expected result: `lsmod | grep me_dma` shows the module is loaded, and `ls /dev/me_dma` confirms the device node exists.

**Step 2**: Run the test program.

```bash
cd components/system/dma/build/output
./test_dma --help
```

Expected result: The test program's help information is displayed, listing the available test options.

**Step 3**: Run the synchronous copy test.

```bash
./test_dma
```

Expected result: The terminal prints output similar to the following, indicating the DMA copy succeeded and data correctness was verified:

```text
[INFO] DMA channel requested successfully
[INFO] Sync transfer: 4096 bytes
[INFO] Transfer completed, verifying data...
[INFO] Data verification passed
[TEST] PASSED
```

## 4. Application Development

- **API / Interface**:

  - Header file: `include/dma.h`
  - Library name: `libdma.so` or `libdma.a`
  - Main APIs:
    - `dma_request_channel()` — request a DMA channel
    - `dma_release_channel()` — release a DMA channel
    - `dma_submit()` — submit an asynchronous transfer task
    - `dma_transfer_sync()` — perform a synchronous transfer
    - `dma_wait()` — wait for an asynchronous transfer to complete
    - `dma_stop()` — stop a transfer
- **Usage and Notes**:

  - Thread safety: A single `dma_chan` does not support concurrent calls from multiple threads; the upper layer must add locking or use a separate channel per thread.
  - Permissions: Ensure the `/dev/me_dma` device node is accessible (typically requires root or membership in the corresponding user group).
  - Resource cleanup: Always call `dma_release_channel()` when you are done to release the channel.
  - Memory alignment: Align transfer addresses and lengths according to the DMA engine's requirements (typically 4-byte or 8-byte).
  - Working with shm: When transferring a `shm_buffer`, ensure the buffer is correctly allocated and has not been freed.
- **Reference demos and example paths**: `components/system/dma/test/test_dma.c`

## 5. Debugging Guide

- **Kernel log inspection**: `dmesg | grep me_dma` shows driver load and transfer error messages.
- **User-space logging**: Add `printf` statements in the code or use `strace` to trace system calls.
- **Common debugging steps**:
  1. Confirm the driver is loaded: `lsmod | grep me_dma`
  2. Confirm the device node exists: `ls -l /dev/me_dma`
  3. Check permissions: `sudo chmod 666 /dev/me_dma` (for testing)
  4. Use `strace ./test_dma` to identify the cause of failed system calls.
- **Information collection checklist when working with hardware/kernel colleagues**:
  - Kernel version and configuration (`uname -a`, `cat /proc/config.gz | gunzip | grep DMA`)
  - DMA engine type and channel count
  - The dmesg log at the time of the transfer failure
  - Transfer parameters (source address, destination address, length, direction)

## 6. FAQ

| Symptom | Possible Cause | Resolution |
| --- | --- | --- |
| `insmod me_dma.ko` fails | The kernel does not enable DMA-HEAP, or the DMA engine is unsupported | Check the kernel configuration and confirm hardware support |
| `/dev/me_dma` does not exist | The driver is not loaded or failed to load | Run `dmesg` to view the driver load log |
| `dma_request_channel()` returns NULL | Insufficient device node permissions or the driver is not ready | Check permissions and confirm the driver is loaded |
| Transfer data verification fails | Unaligned addresses or a cache sync issue | Ensure address alignment; use the shm cache sync API |
| Asynchronous transfer times out | The DMA engine is busy or a hardware fault occurred | Check the dmesg log and confirm the hardware status |

# System Services · System Control

## 1. Overview

- **Key Features**: The system control module provides system power-mode management, watchdog control, and wakeup-source configuration. It is used for system-level management scenarios such as suspend, wakeup, and watchdog feeding.
- **Specifications and Features**:
  - Supports multiple power modes: ACTIVE, IDLE, SENSOR_OFF, SUSPEND, HIBERNATE, POWEROFF, and REBOOT.
  - Supports mode-switch hook functions, allowing custom logic to run before a mode switch.
  - Watchdog control: based on the `/dev/watchdog` device, with support for automatic initialization and periodic feeding.
  - Wakeup-source control: supports Wake-on-LAN and GPIO wakeup (high/low level triggered).
- **Directory Structure**:

  ```text
  components/system/sys/
  ├── include/sys.h          # Public API header
  ├── src/sys.c              # Library implementation source
  ├── test/test_sys.c        # Test cases
  ├── CMakeLists.txt         # Build configuration
  └── README.md              # Module documentation
  ```

## 2. Environment Setup

### Prerequisites

- **Runtime Environment**: Linux kernel (with watchdog, GPIO sysfs, and ethtool support), CMake ≥ 3.16, gcc/clang compiler.
- **Dependencies and External Resources**: No additional external dependencies — only the standard C library.
- **Environment Variables and Initialization**: If building through the SDK, first run `source build/envsetup.sh` and `lunch <target>`.
- **Hardware and Connections**: The target board must support a watchdog and GPIO; confirm that `/dev/watchdog` and the GPIO sysfs exist.
- **Tools and Permissions**: Watchdog, Wake-on-LAN, and GPIO operations require root privileges.

### Build

- **Getting the Code**: The code is located in the SDK's `components/system/sys` directory.
- **Module Compilation**:

    ```bash
    cd components/system/sys
    mkdir build && cd build
    cmake ..
    cmake --build .
    ```

    To build only the library (without tests):

    ```bash
    cmake -DBUILD_SYS_TESTS=OFF ..
    cmake --build .
    ```

- **Artifacts**:
  - User-space library: `libsys.so` or `libsys.a`
  - Test program: `build/test_sys`

## 4. Application Development

- **API / Interface**:

  - Header file: `include/sys.h`
  - Library name: `libsys.so` or `libsys.a`
  - Main APIs:
    - `sys_set_mode()` — set the system power mode
    - `sys_get_mode()` — get the current power mode
    - `sys_register_hook()` — register a mode-switch hook function
    - `sys_watchdog_feed()` — feed the watchdog (reset the watchdog timer)
    - `sys_enable_wakeup_net()` — enable/disable Wake-on-LAN
    - `sys_enable_wakeup_gpio()` — configure a GPIO wakeup source
- **Usage and Notes**:

  - Permissions: Most operations require root privileges.
  - Hook functions: Returning a non-zero value prevents the mode switch.
  - Watchdog: The first call to `sys_watchdog_feed()` automatically initializes the watchdog; call it periodically to prevent a system reboot.
  - GPIO wakeup: Confirm the GPIO number and trigger level are correct.
- **Reference demos and example paths**: `components/system/sys/test/test_sys.c`

## 5. Debugging Guide

- **System log inspection**: `dmesg | grep -E "watchdog|gpio|wakeup"` shows the relevant kernel logs.
- **Watchdog status**: `cat /dev/watchdog` or the `wdctl` command shows watchdog information.
- **GPIO status**: `cat /sys/class/gpio/gpio*/value` shows the GPIO status.
- **Wake-on-LAN**: `ethtool eth0 | grep Wake-on` shows the WoL status.

## 6. FAQ

| Symptom | Possible Cause | Resolution |
| --- | --- | --- |
| `sys_set_mode()` fails | Insufficient permissions, or the kernel does not support the mode | Use root privileges and check the kernel power-management configuration |
| Watchdog test fails | `/dev/watchdog` does not exist or permissions are insufficient | Confirm the kernel enables the watchdog and use sudo |
| Wake-on-LAN does not work | The NIC does not support WoL or it is not enabled | Check hardware support and use `ethtool -s eth0 wol g` |
| GPIO wakeup fails | Wrong GPIO number or the sysfs does not exist | Confirm the GPIO number and check `/sys/class/gpio/` |
| System reboots unexpectedly | The watchdog timed out because it was not fed | Ensure `sys_watchdog_feed()` is called periodically |

# ROS2 Camera Sensor Usage

## RealSense Notes

### Install Required Dependencies

```bash
sudo apt install udev cmake build-essential
```

Install udev rules. Ensure no RealSense devices are connected:

```bash
cd ~
wget https://archive.spacemit.com/ros2/prebuilt_libs/source_code_common/librealsense-2.57.4.tar.gz
tar xzvf librealsense-2.57.4.tar.gz
cd librealsense-2.57.4/
./scripts/setup_udev_rules.sh
cd ..
rm -rf librealsense-2.57.4 librealsense-2.57.4.tar.gz
```

For depth cameras, the RealSense D4xx series is recommended.

The Humble and Jazzy packages are independent and use different library versions. Install the packages for the ROS 2 distribution you are using.

### Humble

```bash
sudo apt install ros-humble-librealsense2
```

This standalone C++ library corresponds to tag 2.57.7 of the https://github.com/realsenseai/librealsense repository.

```bash
# You can check the library installation location
# The cmake export files are at: /opt/ros/humble/lib/riscv64-linux-gnu/cmake/realsense2/
dpkg -L ros-humble-librealsense2
```

The `realsense` built-in demo programs are installed in `/opt/ros/humble/bin`.

**RealSense ROS2 SDK**

```bash
sudo apt install ros-humble-realsense2-camera
```

This package wraps `ros-humble-librealsense2` and corresponds to tag 4.57.7 of the https://github.com/realsenseai/realsense-ros repository.

### Jazzy

```bash
sudo apt install ros-jazzy-realsense2-camera
```

This installs `ros-jazzy-librealsense2` as a dependency package.

**Version numbers:**

```bash
ros-jazzy-librealsense2 2.58.4
ros-jazzy-realsense2-camera 4.58.4
```



## Orbbec Camera Notes

On K3, Orbbec cameras can be used directly with Debian packages. The package includes the camera driver, Orbbec SDK, device enumeration tools, launch files, and udev rules; you do not need to download the source or create an `orbbec_ws` workspace. This example uses ROS 2 Humble and an **Orbbec Gemini 335** connected over USB.

### Install Software Package

First complete source configuration and ROS 2 environment installation according to [ROS2 Installation](6.6.1-ROS2-INSTALL.md), then run:

**Humble**

```bash
sudo apt update
sudo apt install ros-humble-orbbec-camera udev
source /opt/ros/humble/setup.bash
```

Install udev rules:

```bash
sudo install -m 644 \
  /opt/ros/humble/share/orbbec_camera/udev/99-obsensor-libusb.rules \
  /etc/udev/rules.d/99-obsensor-libusb.rules
sudo udevadm control --reload-rules
sudo udevadm trigger
```

**Jazzy**

```
sudo apt update
sudo apt install ros-jazzy-orbbec-camera udev
source /opt/ros/jazzy/setup.bash
```

Install udev rules:

```bash
sudo install -m 644 \
  /opt/ros/jazzy/share/orbbec_camera/udev/99-obsensor-libusb.rules \
  /etc/udev/rules.d/99-obsensor-libusb.rules
sudo udevadm control --reload-rules
sudo udevadm trigger
```

After installing the rules, reconnect the camera and run the remaining ROS 2 commands as a regular user. A USB 3.x data cable and port are recommended.

For the examples below, replace DISTRO with the actual ROS 2 version in use.

### Check Camera and Supported Configurations

Before launching the camera node, first confirm that the device can be detected and enumerate the supported resolutions, formats, frame rates, and IMU configurations:

```bash
ros2 run orbbec_camera list_devices_node
ros2 run orbbec_camera list_camera_profile_mode_node
```

The device information should identify `Orbbec Gemini 335` and include its serial number, connection type, and firmware version. The device used to validate this guide was connected over `USB3.2` and ran firmware `1.4.60`. It supported the 640×480 MJPG color, Y16 depth, and 200 Hz accelerometer and gyroscope profiles used below.

### Launch Gemini 335

The package installs `gemini_335_vslam.launch.py` for K3. Launch it directly:

```bash
ros2 launch orbbec_camera gemini_335_vslam.launch.py
```

The command runs in the foreground; use `Ctrl+C` to stop. Under this launch file's default configuration:

| Item | Default Configuration |
| --- | --- |
| Color Image | 640×480, 30 FPS, device-side format MJPG |
| Depth Image | 640×480, 30 FPS, format Y16, software-aligned to color image |
| Image Sync | Frame sync enabled, using `full_frame` aggregation |
| IMU | Accelerometer 200 Hz / 4g, Gyroscope 200 Hz / 1000 dps, merged output |
| Timestamps | Host time sync enabled, using `global` time domain |
| Calibration & Transforms | Publishes CameraInfo, static TF, and extrinsics |
| Point Cloud | Disables plain and color point clouds to reduce CPU load and topic bandwidth |

View the parameters supported by this launch file:

```bash
ros2 launch orbbec_camera gemini_335_vslam.launch.py --show-args
```

The installed launch file is located at `/opt/ros/DISTRO/share/orbbec_camera/launch/gemini_335_vslam.launch.py` and can be inspected for its specific configuration; there is no need to manually create this file. To modify resolution or other node parameters, copy the launch file to a user directory, modify it, and then run it via `ros2 launch /absolute/path/to/file.launch.py` to avoid custom configuration being overwritten by package upgrades.

### Verify Data Output

Keep the camera launch running and load the environment in another terminal to check topics:

```bash
source /opt/ros/DISTRO/setup.bash
ros2 topic list
```

Using the default `camera_name:=camera`, the main outputs are:

| Topic | Type | Content |
| --- | --- | --- |
| `/camera/color/image_raw` | `sensor_msgs/msg/Image` | Color image |
| `/camera/depth/image_raw` | `sensor_msgs/msg/Image` | Depth image aligned to color image |
| `/camera/color/camera_info` | `sensor_msgs/msg/CameraInfo` | Color camera calibration parameters |
| `/camera/depth/camera_info` | `sensor_msgs/msg/CameraInfo` | Calibration parameters for depth image |
| `/camera/gyro_accel/sample` | `sensor_msgs/msg/Imu` | Merged accelerometer and gyroscope data |
| `/tf_static` | `tf2_msgs/msg/TFMessage` | Static transforms between camera coordinate frames |

Under this configuration, the color image ROS encoding is `rgb8`, the depth image is `16UC1`, and the `frame_id` for both images and their CameraInfo is `camera_color_optical_frame`.

Check data rates by running each command separately, using `Ctrl+C` to exit before running the next:

```bash
ros2 topic hz /camera/color/image_raw
ros2 topic hz /camera/depth/image_raw
ros2 topic hz /camera/gyro_accel/sample
```

`ros2 topic hz` shows the actual receive rate at the current subscriber, which may be affected by CPU load and subscription overhead. Color/depth images and their CameraInfo use `SENSOR_DATA` QoS; custom subscriber programs or visualization tools should choose compatible QoS, such as `best_effort` reliability.

Query device information and SDK version via services:

```bash
ros2 service call /camera/get_device_info orbbec_camera_msgs/srv/GetDeviceInfo '{}'
ros2 service call /camera/get_sdk_version orbbec_camera_msgs/srv/GetString '{}'
```

If `camera_name` was modified, replace the `/camera` prefix in the above topics and services with the corresponding name.

### RISC-V Usage Limitations and Troubleshooting

The current RISC-V Debian package does not include the vendor's closed-source library `libob_frame_processor.so`. The Gemini 335 launch file uses `depth_registration=true`, `align_mode=SW`, and `align_target_stream=COLOR` to align depth images to color images in software, and passes a reduced set of parameters to the node. Startup logs may warn about the missing library or passthrough processing; check the image, IMU, and service outputs to determine whether the camera is operating correctly.

Only the Gemini 335 has been verified with this K3 workflow. The package also contains launch files for other models; list them with:

```bash
ls /opt/ros/humble/share/orbbec_camera/launch/
```

For other Gemini 330 series models, use the reduced parameter set and software alignment approach in `gemini_335_vslam.launch.py` as a reference. First enumerate the device's profiles and verify color, depth, alignment, and IMU outputs individually. GMSL and Ethernet models require their own drivers or network configuration; the USB configuration cannot be used directly. If depth decoding, disparity conversion, or required filtering depends on the closed-source extensions missing from the current RISC-V package, those operations cannot run.

# Localization and Navigation · SpacemiT VSLAM

## 1. Module Overview

SpacemiT VSLAM is the Robot SDK's stereo localization and 3D reconstruction application for K3. It estimates the camera pose from stereo images (VO) and can fuse the camera's embedded IMU data (VIO). LAS2 estimates depth in metres and produces a left color image aligned to that depth. The mapping module fuses depth with the pose at each image timestamp and displays a colored TSDF surface and an ESDF distance slice in the desktop window.

This guide runs stereo VIO with live reconstruction. The desktop launcher leaves loop closure and pose graph optimization disabled by default. The `VIO` status means visual-inertial tracking is active. Saving a localization map and loading one for relocalization are currently unavailable in the localization library.

```text
Stereo UVC camera (embedded exposure timestamps and IMU)
  └─ camera_io
       ├─ vio: pose at the image timestamp ──┐
       └─ las2: depth and aligned RGB ────────┴─→ esdf_drm: TSDF / ESDF → desktop window
```

The project is located at `middleware/ros2/slam/spacemit-vslam` in the SDK.

| Directory | Purpose |
| --- | --- |
| `modules/camera/` | Camera metadata parsing, calibration, and time alignment |
| `modules/vslam/` | Public headers, CMake configuration, and prebuilt K3 localization library |
| `modules/mapping/` | Public headers, CMake configuration, and prebuilt K3 mapping and rendering library |
| `src/camera_io/` | ROS 2 camera input, image and IMU publishing, recording, and replay |
| `src/vio/` | Stereo VO/VIO, including pose, trajectory, features, and tracking state |
| `src/las2/` | Uses the SDK's `stereo_matching` to publish depth and aligned RGB descriptors |
| `src/esdf_drm/` | Pairs depth with poses, updates TSDF and ESDF, and renders the desktop view |
| `src/common/` | Depth and feature messages and lifecycle tools |
| `src/bringup/` | Launchers for the desktop application, recording, and replay |

## 2. Environment and Build

Run the commands on a K3 board. See [2.3 Build and Compilation](../../02-快速入门/2.3-构建编译.md) for the SDK checkout and base environment.

| Item | Requirement |
| --- | --- |
| System | K3, Bianbu 4.0.1, and ROS 2 Humble |
| Libraries | OpenCV 4.10 (`libopencv_*.so.410`), MPP libraries and plugins for the board image, and OpenCL and EGL/GLES/DRM support |
| Camera and calibration | A supported stereo UVC camera with embedded exposure timestamps and IMU samples, and Kalibr calibration for that physical camera. A standard UVC image stream does not provide the required metadata. |
| Desktop and permissions | An active X11 or Xwayland session, and an account with access to the camera, MPP, DMA-BUF, and the GPU. |

Load the build environment from the SDK root, then enter the module directory:

```bash
cd "$HOME/spacemit_robot"
source build/envsetup.sh
cd middleware/ros2/slam/spacemit-vslam
mm --with-deps
```

`mm --with-deps` builds the Camera module, the ROS 2 packages, and the required MPP, LAS2, and IMU components. VSLAM and Mapping use the supplied K3 Linux RISC-V 64-bit libraries, which the build verifies before installing. Follow the SDK prompts for missing system dependencies. The default output directory is `output/staging` in the SDK. If your checkout is elsewhere, adjust the `cd` path.

The SDK component supplies the LAS2 inference runtime, and the build installs the required files. There is no separate ONNX Runtime or SpacemiT execution provider download. Download the depth model before running the application; the build does not need it.

## 3. Run the Desktop Example

### 3.1 Download the LAS2 Model

Download the model as the account that will run the application. By default, the desktop launcher reads it from that account's `~/.cache/models/vision/`. The following commands move it to the default filename only after the SHA-256 check passes:

```bash
model_path="$HOME/.cache/models/vision/LAS2_M_288x384.fp16.onnx"
mkdir -p "$(dirname "$model_path")"
wget -O "$model_path.part" \
  https://archive.spacemit.com/spacemit-ai/model_zoo/vision/stereo_depth/LAS2_M_288x384.fp16.onnx &&
printf '%s  %s\n' aa4f22f0f2433dc317ae3fa028549b9e228200c117d95121e19cfa0f1615145a "$model_path.part" |
  sha256sum -c - &&
mv -- "$model_path.part" "$model_path"
```

This is the ExternalStereo model used by VSLAM. The original LAS2 still-image demo produces a disparity image and needs a different tensor model with the same filename. To run it separately, follow the still-image demo section of the [Stereo Matching guide](https://github.com/spacemit-robotics/perception/blob/main/stereo_matching/README.md).

### 3.2 Configure the Camera and Calibration

The project uses a DECXIN USB/UVC stereo wide-angle camera. Each camera captures 1920×1200 images, and the stereo pair is packed into a 4000×1200 frame. The device supports MJPEG at 30 or 60 fps. It has a built-in six-axis IMU, and the image stream carries exposure timestamps and IMU data.

The default `src/camera_io/config/usb_stereo_4000x1200.json` uses `/dev/video9`, captures packed 4000×1200 MJPEG stereo frames, and outputs 640×400 per camera. The desktop script requests 30 FPS by default. The device path and bundled `0.yaml` are for the example setup. Verify your capture device and use calibration for your physical camera.

Run `v4l2-ctl --list-devices` on the board. Use `v4l2-ctl -d /dev/videoX --list-formats-ext` to check supported capture modes, substituting the actual capture device for `/dev/videoX`. Copy the example JSON to your configuration directory:

```bash
config_dir="$HOME/spacemit-vslam-config"
mkdir -p "$config_dir"
cp "$HOME/spacemit_robot/middleware/ros2/slam/spacemit-vslam/src/camera_io/config/usb_stereo_4000x1200.json" \
  "$config_dir/camera.json"
```

Save your Kalibr calibration as `$config_dir/calibration.yaml`, then check these settings in `camera.json`:

| Setting | What to check |
| --- | --- |
| `camera.device` | Use the actual image capture device, preferably a stable path under `/dev/v4l/by-id/` when available. |
| `camera.width`, `camera.height`, `camera.fps` | Select a mode supported by the camera. The desktop script's `camera_fps` overrides the JSON frame rate. |
| `streams.left/right.crop`, `streams.left/right.output` | Match the crop to the physical left and right cameras and their calibration. If you change the output dimensions, pass matching `image_width` and `image_height` launch arguments. |
| `calibration.file` | Set it to `calibration.yaml`; relative paths are resolved from the JSON directory. Use the same stereo calibration for the camera node, VIO, and LAS2. |
| `timestamp.source`, `metadata.region`, `imu.samples_per_frame` | Match the camera's embedded metadata format. The example uses the exposure midpoint and 10 IMU samples per frame. |

Kalibr's `cam0` and `cam1` correspond to the physical left and right cameras. The calibration resolution must match the cropped image for each camera before scaling. The application scales the intrinsics to the output dimensions and uses the original distortion and rigid transforms. VIO also needs the camera-to-IMU extrinsics and the `imu0` noise parameters. If the IMU calibration is stored separately, append `imu_calibration_file:="$config_dir/imu.yaml"` at launch. If calibration includes `cam0.timeshift_cam_imu`, VIO applies it to the IMU timestamps and keeps the original exposure timestamps.

### 3.3 Launch and Check the Output

From a terminal in the board's active desktop session, load the SDK runtime environment and start the application with your configuration:

```bash
cd "$HOME/spacemit_robot"
source build/envsetup.sh
sros2_setup
config_dir="$HOME/spacemit-vslam-config"
ros2 run bringup run_vslam_desktop.sh \
  camera_config_file:="$config_dir/camera.json" \
  calibration_file:="$config_dir/calibration.yaml"
```

If your device and calibration match the bundled example, run `ros2 run bringup run_vslam_desktop.sh` without arguments. The default window is 1280×720. Add `desktop_fullscreen:=true` for full screen, or pass `model_path:=/path/to/model.onnx` if the verified model is stored elsewhere.

The camera normally waits for LAS2 to initialize. Once images appear, slowly move and turn the camera in a well-lit scene with visible texture until the tracking state shows `VIO`. The window displays the image, colorized depth, trajectory, TSDF surface, and gravity-aligned ESDF slice. Press `Ctrl+C` to stop the application.

To inspect ROS 2 output, open another terminal and run `source build/envsetup.sh` and `sros2_setup` from the SDK root. Use the same `ROS_DOMAIN_ID` as the application. Run these commands one at a time and press `Ctrl+C` to stop each `hz` command:

```bash
ros2 node list
ros2 topic hz /camera/left/frame_desc
ros2 topic hz /las2/depth_desc
ros2 topic hz /vio/pose/image
ros2 topic echo /vio/tracking_mode --qos-reliability best_effort --once
```

`ros2 topic hz` measures the rate seen by the subscriber, so it is useful for checking whether data continues to arrive. Use `ros2 launch bringup vio_las2_esdf_launch.py --show-args` to list all launch arguments. For recording and replay, see the [spacemit-vslam README](https://github.com/spacemit-robotics/ros2_spacemit_vslam/blob/main/README.md).

## 4. Development Interfaces

### 4.1 ROS 2 Topics

| Default topic | Message type | Purpose |
| --- | --- | --- |
| `/camera/left/frame_desc`, `/camera/right/frame_desc` | `mpp_msgs/msg/MppVideoFrameDesc` | Left and right NV12 image descriptors |
| `/camera/left/camera_info`, `/camera/right/camera_info` | `sensor_msgs/msg/CameraInfo` | Intrinsics for the published image dimensions |
| `/camera/imu/data_raw` | `sensor_msgs/msg/Imu` | Raw IMU samples |
| `/vio/pose/image` | `nav_msgs/msg/Odometry` | Pose at the image timestamp for pairing with depth and other data |
| `/vio/trajectory` | `nav_msgs/msg/Path` | Pose trajectory |
| `/vio/tracking_mode` | `std_msgs/msg/String` | Tracking state |
| `/vio/features` | `common/msg/FeaturePointArray` | Tracking features |
| `/las2/depth_desc` | `common/msg/DmaDepthFrameDesc` | Depth, aligned RGB, and calibration metadata |
| `/esdf/render/frame_desc` | `mpp_msgs/msg/MppVideoFrameDesc` | Composited frame for the desktop window |

Image and depth pixels stay in DMA-BUF while ROS 2 carries descriptors and metadata. To read pixels, use `VB_Import()` on the token from the descriptor and pair each successful import with `VB_ReleaseBuffer()`. Preserve source timestamps, frame numbers, dimensions, stride, pixel format, and calibration. Treat shared inputs as read-only and use bounded downstream queues. The desktop launcher leaves high-rate pose extrapolation disabled. If `/vio/pose/imu` has no output, use `/camera/imu/data_raw` to check the raw IMU stream.

### 4.2 C++ Interfaces

| Function | Public header | CMake target |
| --- | --- | --- |
| Stereo localization | `spacemit_vslam.h` | `spacemit_vslam::spacemit_vslam` |
| Mapping and rendering | `spacemit_mapping.h` | `spacemit_mapping::spacemit_mapping` |
| LAS2 depth (ExternalStereo) | `stereo_pipeline.h` | `stereo_matching::external_input` |

ExternalStereo takes stereo NV12 DMA-BUFs and Kalibr calibration and produces depth in metres and aligned left RGB.

## 5. Troubleshooting

| Symptom | What to check |
| --- | --- |
| The camera produces no images | Verify the capture device and supported mode in the JSON, and check whether another process is using the device. If startup is waiting for `/las2/ready`, check the model and LAS2 logs first. |
| Model loading fails | Verify the model path for the runtime account and check its SHA-256 to confirm it is the ExternalStereo model. You can also pass a verified file with `model_path`. |
| Tracking stays at `VO - IMU INIT` or is unstable | Check the mapping of the physical left and right cameras, calibration, and capture mode. Inspect `/camera/imu/data_raw` and timestamps, then move the camera slowly in a textured scene. |
| Depth arrives but the map does not update | Check whether `/vio/pose/image` is publishing and whether the depth and pose source timestamps can be paired. |
| The window does not open or show frames | From the board's desktop session, check `DISPLAY`, `XAUTHORITY`, and `/esdf/render/frame_desc`. Inspect the renderer in the `Desktop EGL ready` log. `llvmpipe` and `softpipe` indicate software rendering; check the board's GPU driver. |

If the board image requires an authorized hardware account, run the backend and viewer with the same runtime UID. Set `SPACEMIT_DESKTOP_UID` to the logged-in desktop user's numeric UID and preserve that session's `DISPLAY` and `XAUTHORITY`. If the runtime account changes, pass a readable model path with `model_path`. Run `ros2 run bringup run_vslam_desktop.sh --help` for the options to run without a window or start the viewer separately.

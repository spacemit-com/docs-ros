# Localization and Navigation · ORB-SLAM3

## 1. Overview

- **Key Features**: `orbslam3_run` wraps ORB-SLAM3 as a ROS 2 RGB-D visual odometry and sparse mapping node. In this project, it lives at `middleware/ros2/slam/orbslam3_run`. It consumes synchronized color and aligned depth images and publishes robot pose, trajectory, tracking state, and sparse map points.
- **Specifications and Features**:
	- Algorithm type: RGB-D visual odometry, RGB-D sparse SLAM
	- Input resolution: 640×480 only; the node does not rescale images internally
	- Recommended frame rate: 15 FPS
	- Supported cameras: configured for the Intel RealSense D455 by default, with a D415 configuration also provided
	- Odometry output: 3D odometry, 2D planar odometry, and tracking state
	- Mapping output: global pose, trajectory, sparse map points, and tracking state
	- Mapping results: ORB-SLAM3 Atlas and TUM-format trajectories can be saved
	- K3 optimization: SpacemiT RVV 1.0 build options are enabled by default
- **Processing Flow**:

  ```text
  RealSense RGB-D camera
          │
          ├── /camera/color/image_raw (640×480)
          └── /camera/aligned_depth_to_color/image_raw (640×480)
                           │
                           ▼
                     orbslam3_run
                      ├── Visual odometry: odom / odom_2d / tracking_state
                      └── Sparse mapping: pose / path / map_points / Atlas
  ```

- **Directory Structure**:

  | Path | Responsibility |
  | --- | --- |
  | `middleware/ros2/slam/orbslam3_run/launch/rgbd_odometry.launch.py` | RGB-D visual odometry launch entry point |
  | `middleware/ros2/slam/orbslam3_run/launch/rgbd_slam.launch.py` | RGB-D sparse mapping launch entry point |
  | `middleware/ros2/slam/orbslam3_run/config/d455_rgbd.yaml` | D455 odometry configuration |
  | `middleware/ros2/slam/orbslam3_run/config/d455_rgbd_slam.yaml` | D455 mapping configuration |
  | `middleware/ros2/slam/orbslam3_run/config/d415_rgbd.yaml` | D415 odometry configuration |
  | `middleware/ros2/slam/orbslam3_run/config/d415_rgbd_slam.yaml` | D415 mapping configuration |
  | `middleware/ros2/slam/orbslam3_run/README.md` | Module description and quick start |

## 2. Environment Setup

### 2.1 Prerequisites

- **Getting the Code**:

  For SDK source code acquisition and basic build environment setup, refer to [Linksee Reference Solution](../../03-参考方案/3.2-轮式机器人Linksee.md). After completing SDK initialization, return to this document to continue.

- **Runtime Environment**:
	- K3 series development board and Bianbu 2.6
	- ROS version: ROS 2 Humble
	- RGB-D camera: Intel RealSense D455 or D415
	- Both the color image and the aligned depth image must be 640×480

- **Installing Build and Runtime Dependencies**:

  ```bash
  sudo apt update
  sudo apt install git cmake ninja-build build-essential patchelf \
    libeigen3-dev opencv-spacemit=4.14.0-2bb4 \
    libboost-serialization-dev libssl-dev libsuitesparse-dev \
    libglew-dev libepoxy-dev libx11-dev libwayland-dev \
    libjpeg-dev libpng-dev libtiff-dev wget
  ```

  For instructions on installing the RealSense packages, see [ROS2 Installation](../../06-系统与平台/6.6-ROS2/6.6.1-ROS2-INSTALL.md).

- **Installing the K3 RVV Build of ORB-SLAM3**:

  ```bash
  wget https://archive.spacemit.com/ros2/prebuilt_libs/bianbu26/opt/ext/orbslam3_rvv/4452a3c4ab75b1cde34e5505a36ec3f9edcdc4c4/orbslam3.tar.gz
  sudo tar xzf orbslam3.tar.gz -C /opt
  echo /opt/orbslam3/lib | sudo tee /etc/ld.so.conf.d/orbslam3.conf
  sudo ldconfig
  ```

  After installation, verify the key files:

  ```bash
  test -f /opt/orbslam3/share/orbslam3/ORBvoc.txt && echo "ORB vocabulary ready"
  test -f /opt/orbslam3/lib/libORB_SLAM3.so && echo "ORB-SLAM3 library ready"
  ```

- **Environment Variables and Initialization**:

  ```bash
  source ~/spacemit_robot/output/staging/setup.bash
  ```

- **Hardware and Connections**:
	- Mount the camera securely and keep its field of view unobstructed
	- Use a USB 3.x connection. Even when USB bandwidth is limited, the color and depth streams must both run at 640×480@15
	- The color and depth images must be time-synchronized, and the depth image must be aligned to the color image
	- The camera extrinsics in the node are set for the current D455 mounting arrangement. Update the extrinsics whenever the mounting position or orientation changes

### 2.2 Building

- **Full SDK Build**:

  ```bash
  cd ~/spacemit_robot
  source build/envsetup.sh
  lunch # Select the corresponding K3 product configuration
  m
  ```

- **Standalone colcon Build**:

  ```bash
  cd ~/spacemit_robot
  source /opt/ros/humble/setup.bash
  colcon build --packages-select orbslam3_run \
    --cmake-args -DCMAKE_BUILD_TYPE=Release
  source install/setup.bash
  ```

  On a non-RISC-V host used only for code debugging, disable the default RVV build option:

  ```bash
  colcon build --packages-select orbslam3_run \
    --cmake-args -DCMAKE_BUILD_TYPE=Release -DORB_SLAM3_USE_RVV=OFF
  ```

- **Artifacts**:
	- SDK build artifacts are located under `~/spacemit_robot/output/staging/`
	- Standalone build artifacts are located under `install/orbslam3_run/`
	- The ORB-SLAM3 library, Pangolin, and the vocabulary file are loaded from `/opt/orbslam3` by default
	- If the dependencies are installed elsewhere, set `ORB_SLAM3_PREFIX` before building and running

## 3. Example Usage

This section uses a 640×480@15 stream from a RealSense D455 as the example. Load the runtime environment in every terminal first:

```bash
source ~/spacemit_robot/output/staging/setup.bash
```

**Step 1: Start the RGB-D camera**

```bash
ros2 launch realsense2_camera rs_launch.py camera_namespace:=/ \
  enable_color:=true enable_depth:=true \
  rgb_camera.color_profile:=640,480,15 \
  depth_module.depth_profile:=640,480,15 \
  align_depth.enable:=true enable_sync:=true
```

**Expected result**: The following two 640×480 image topics are published continuously, with closely matching timestamps:

- `/camera/color/image_raw`
- `/camera/aligned_depth_to_color/image_raw`

Check the image rates in a new terminal:

```bash
ros2 topic hz /camera/color/image_raw
ros2 topic hz /camera/aligned_depth_to_color/image_raw
```

**Step 2: Run visual odometry**

```bash
ros2 launch orbslam3_run rgbd_odometry.launch.py
```

**Expected result**: After loading the vocabulary, the node waits for synchronized images. Once the camera moves and tracking is working, `/orbslam3/odom` and `/orbslam3/odom_2d` are published continuously and the tracking state is `2`.

```bash
ros2 topic echo /orbslam3/tracking_state --once
ros2 topic hz /orbslam3/odom
ros2 topic echo /orbslam3/odom_2d --once
```

Odometry mode does not publish TF by default. To publish `orb_odom -> base_footprint`, run:

```bash
ros2 launch orbslam3_run rgbd_odometry.launch.py publish_tf:=true
```

**Step 3: Run SLAM mapping**

Stop the odometry node before starting the mapping node, to avoid two ORB-SLAM3 instances processing the same camera data:

```bash
ros2 launch orbslam3_run rgbd_slam.launch.py
```

**Expected result**: Once tracking is working, the node starts publishing the current pose, trajectory, and sparse map points, and publishes the `orb_map -> base_footprint` TF by default.

```bash
ros2 topic echo /orbslam3_slam/tracking_state --once
ros2 topic hz /orbslam3_slam/pose
ros2 topic echo /orbslam3_slam/map_points --once
```

**Step 4: Save the mapping results**

After finishing data capture, call the following before exiting the mapping node:

```bash
ros2 service call /orbslam3_slam/finish_mapping std_srvs/srv/Trigger '{}'
```

The default save directory is `~/.ros/orbslam3_slam`. The main outputs are:

| File | Description |
| --- | --- |
| `orbslam3_atlas.osa` | ORB-SLAM3 Atlas |
| `CameraTrajectory.txt` | Camera trajectory in TUM format |
| `KeyFrameTrajectory.txt` | Keyframe trajectory in TUM format |

After the service call completes, the node keeps running but no longer processes new images. Confirm that the files were saved before exiting the node.

**Using the D415 configuration**

The D415 requires its own camera intrinsics file:

```bash
ros2 launch orbslam3_run rgbd_odometry.launch.py \
  settings:=$(ros2 pkg prefix orbslam3_run)/share/orbslam3_run/config/d415_rgbd.yaml

ros2 launch orbslam3_run rgbd_slam.launch.py \
  settings:=$(ros2 pkg prefix orbslam3_run)/share/orbslam3_run/config/d415_rgbd_slam.yaml
```

## 4. Application Development

- **Visual Odometry Interfaces**:

  | Interface | Type | Description |
  | --- | --- | --- |
  | `/camera/color/image_raw` | `sensor_msgs/Image` | 640×480 color image input |
  | `/camera/aligned_depth_to_color/image_raw` | `sensor_msgs/Image` | 640×480 aligned depth image input |
  | `/orbslam3/odom` | `nav_msgs/Odometry` | Odometry that retains the full 3D pose |
  | `/orbslam3/odom_2d` | `nav_msgs/Odometry` | 2D odometry that retains only x, y, and yaw |
  | `/orbslam3/tracking_state` | `std_msgs/UInt8` | Tracking state; `2` means normal |

- **SLAM Mapping Interfaces**:

  | Interface | Type | Description |
  | --- | --- | --- |
  | `/orbslam3_slam/pose` | `geometry_msgs/PoseStamped` | Current global pose |
  | `/orbslam3_slam/path` | `nav_msgs/Path` | Current mapping trajectory |
  | `/orbslam3_slam/map_points` | `sensor_msgs/PointCloud2` | Sparse map points currently tracked |
  | `/orbslam3_slam/tracking_state` | `std_msgs/UInt8` | Tracking state; `2` means normal |
  | `/orbslam3_slam/finish_mapping` | `std_srvs/srv/Trigger` | Finish mapping and save the results |
  | `/orbslam3_slam/reset_map` | `std_srvs/srv/Trigger` | Clear the active map and restart mapping |

- **Common Launch Parameters**:

  | Parameter | Applies to | Default | Description |
  | --- | --- | --- | --- |
  | `vocabulary` | Both | `/opt/orbslam3/share/orbslam3/ORBvoc.txt` | ORB vocabulary file |
  | `settings` | Both | D455 configuration | Camera and ORB-SLAM3 parameter file |
  | `publish_tf` | Both | `false` for odometry, `true` for mapping | Whether to publish the pose TF |
  | `color_topic` | Both | `/camera/color/image_raw` | Color image input topic |
  | `depth_topic` | Both | `/camera/aligned_depth_to_color/image_raw` | Aligned depth image input topic |
  | `odom_frame` | Odometry | `orb_odom` | Odometry frame |
  | `map_frame` | Mapping | `orb_map` | Map frame |
  | `base_frame` | Both | `base_footprint` | Robot base frame |
  | `save_directory` | Mapping | `~/.ros/orbslam3_slam` | Directory for the Atlas and trajectory files |
  | `map_publish_period` | Mapping | `1.0` | Map point publish period, in seconds |
  | `max_path_poses` | Mapping | `10000` | Maximum number of poses retained in the trajectory |

  To list all launch arguments and their defaults:

  ```bash
  ros2 launch orbslam3_run rgbd_odometry.launch.py --show-args
  ros2 launch orbslam3_run rgbd_slam.launch.py --show-args
  ```

- **Usage and Notes**:
	- The camera intrinsics in the configuration file must match the actual camera, resolution, and image streams
	- This module does not convert the sparse visual map into a 2D occupancy grid. Keep using a depth point cloud or LiDAR for the Nav2 obstacle layer
	- Only one node in the system may publish a given parent-child TF pair, so make sure it does not conflict with other odometry or localization modules
	- After changing the camera mounting position, recalibrate and update the extrinsics from the robot base to the camera optical frame
	- The map point topic uses transient local, reliable QoS; visualization subscribers must use a compatible QoS

## 5. Debugging Guide

- **Check image size and frame rate**:

  ```bash
  ros2 topic echo /camera/color/image_raw --field width --once
  ros2 topic echo /camera/color/image_raw --field height --once
  ros2 topic echo /camera/aligned_depth_to_color/image_raw --field width --once
  ros2 topic echo /camera/aligned_depth_to_color/image_raw --field height --once
  ```

  The four results should be `640`, `480`, `640`, and `480`. If the input size does not match, the node periodically reports `ORB-SLAM3 expects 640x480 RGB-D images`.

- **Check image synchronization and alignment**:
	- The color and depth images must have the same size
	- The camera driver must be started with `align_depth.enable:=true` and `enable_sync:=true`
	- If the two image rates fluctuate heavily, check USB bandwidth, power supply, and cabling first

- **Check the ORB-SLAM3 dependencies**:

  ```bash
  ldconfig -p | grep ORB_SLAM3
  ls -l /opt/orbslam3/share/orbslam3/ORBvoc.txt
  ```

  If ORB-SLAM3 is installed elsewhere, set the following in both the build and run terminals:

  ```bash
  export ORB_SLAM3_PREFIX=/path/to/orbslam3
  ```

- **Troubleshoot tracking quality**:
	- A `tracking_state` of `2` means tracking is normal
	- If state `2` is never reached, check scene texture, lighting, motion speed, and the valid depth range
	- Avoid fast camera rotation, lens obstruction, and pointing the camera at large blank walls or glass
	- D415 and D455 parameter files are not interchangeable; other cameras require recalibration and a new configuration

- **Troubleshoot TF and pose**:
	- Odometry mode publishes TF only when `publish_tf:=true` is set
	- Mapping mode publishes `orb_map -> base_footprint` by default
	- If the robot model position or direction of motion is wrong, check the camera mounting extrinsics and `base_frame` first
	- When running alongside other localization nodes, check for duplicate TF publishers

## 6. Troubleshooting

| Symptom | Possible Cause | Resolution |
| --- | --- | --- |
| Build reports that RVV can only be enabled on RISC-V | Default build options were used on an x86 host | Add `-DORB_SLAM3_USE_RVV=OFF`; keep the default on K3 boards |
| CMake cannot find ORB-SLAM3 or Pangolin | `/opt/orbslam3` is missing or incomplete | Reinstall the prebuilt package, or point `ORB_SLAM3_PREFIX` at the correct prefix |
| `ORBvoc.txt` not found at startup | The vocabulary file is missing or the dependency prefix is wrong | Check `/opt/orbslam3/share/orbslam3/ORBvoc.txt` and override the `vocabulary` parameter if needed |
| Image size errors reported continuously | The camera was not started at 640×480 | Set both the color and depth profiles to 640×480 and restart the camera driver |
| Color and depth image sizes reported as different | Depth is not aligned to color, or the two profiles differ | Enable `align_depth.enable` and confirm both input topics have the same size |
| Tracking state never reaches `2` | Mismatched parameter file, insufficient scene texture, poor lighting, or excessive motion | Select the correct D415/D455 configuration and improve the scene and motion conditions |
| Odometry topics are present but there is no TF | Odometry mode disables TF publishing by default | Add `publish_tf:=true` at launch and confirm no other node publishes a conflicting TF |
| The mapping service returns success but no files are found | A custom save directory was used, or the directory lacks write permission | Check the `save_directory` parameter and the write permissions on the target directory |
| No 2D grid map in RViz | ORB-SLAM3 outputs sparse map points | Display `/orbslam3_slam/map_points`; build 2D costmaps from a depth point cloud or LiDAR |

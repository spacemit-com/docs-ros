# Basic Sensors · Motor

## 1. Overview

- **Key Features**: `motor_node` is the ROS 2 motor hardware abstraction layer node, part of the `peripherals` package. It converts ROS 2 topic/service messages into motor control commands for multiple bus protocols (CAN, UART, EtherCAT) in a unified way, and reports motor state through standard topics, so upper-level control algorithms don't need to be concerned with the underlying hardware differences.
- **Specifications and Features**:
  - Supported interface protocols: EtherCAT (CiA402), CAN (Damiao MIT protocol), UART (Feetech SCS/STS protocol)
  - Control modes: IDLE / POS / VEL / TRQ / HYBRID(MIT) / CSP / CSV / CST / HM — 9 modes total
  - EtherCAT bus cycle: 2–5 ms (configurable)
  - State feedback frequency: up to 100 Hz (configurable)
  - Real-time scheduling: EtherCAT thread uses SCHED_FIFO priority 80
- **Directory Structure**:

| Path | Responsibility |
| --- | --- |
| `components/peripherals/motor/include/motor.h` | Unified C-layer motor API header (mode enums, cmd/state structs) |
| `components/peripherals/motor/src/motor_core.c` | Motor core scheduling logic |
| `components/peripherals/motor/src/drivers/` | Per-protocol driver implementations (`drv_ethercat_jmc`, `drv_can_dm`, `drv_uart_feetech`, etc.) |
| `middleware/ros2/peripherals/motor/src/motor_node.cpp` | ROS 2 node wrapper (topics, services, parameter management) |
| `middleware/ros2/peripherals/motor/config/` | YAML parameter configuration files (`ecat_motor_params.yaml`, `can_motor_params.yaml`, `uart_motor_params.yaml`) |

## 2. Environment Setup

### Prerequisites

- **Runtime Environment**: Linux (Ubuntu 22.04 recommended); ROS 2 Humble; CMake ≥ 3.10; GCC/G++ with C99 / C++17 support
- **Dependencies and External Resources**:
  - ROS 2 Humble base packages (`rclcpp`, `std_srvs`, `std_msgs`)
  - `motor` component library (`components/peripherals/motor`, builds `libmotor.so`)
  - EtherCAT driver dependency: SOEM or IgH EtherCAT Master (system-level installation)
  - CAN tools: `can-utils` (`sudo apt install can-utils`)
- **Environment Variables and Initialization**:
  ```bash
  cd spacemit_robot # SDK root directory
  source build/envsetup.sh
  ```
- **Hardware and Connections**:
  - EtherCAT: K3 COM260 board + JMC IHSS42-EC stepper servo, RJ45 cable to `eth0`
  - CAN: K3 COM260 + Damiao motor, CAN transceiver to `can0`
  - UART: K3 COM260 + Feetech SCS/STS servo, USB-TTL to `/dev/ttyACM0`
  - Ensure the motor has stable power supply and good heat dissipation
- **Tools and Permissions**:
 
  - CAN requires `sudo ip link set can0 up type can bitrate 1000000`
  - UART requires the current user to be in the `dialout` group or to have read/write access to `/dev/ttyACM0`

### Configuration File Notes

The runtime parameters of `motor_node` are defined by YAML configuration files. When using them, note the following:

- **Parameter array sizes must match the number of motors**:
  - The element count of array parameters like `profile_vel`, `profile_acc`, `profile_dec` must equal the length of `motor_ids`
  - Example: `motor_ids: [1]` (1 motor) requires `profile_vel: [10000.0]` (1 value)
  - For multiple motors `motor_ids: [1, 2]`, use `profile_vel: [10000.0, 10000.0]` (2 values)
  - **Error message**: If the array size does not match, startup reports the error `Parameter 'profile_vel' size mismatch`

- **Parameter expansion rule**:
  - If an array parameter provides only **1 value**, it is automatically expanded into copies matching the number of motors
  - Example: `motor_ids: [1, 2, 3]` + `profile_vel: [10000.0]` is automatically expanded to `[10000.0, 10000.0, 10000.0]`

- **Recommended configuration per protocol**:
  - **EtherCAT** (`ecat_motor_params.yaml`):
    - `ecat_cycle_ms: 2~5` (2 ms recommended for applications with strong real-time requirements, 5 ms for non-RT kernels)
    - `profile_vel/acc/dec`: typical values 10000–100000 (unit rad/s², determined by motor model)
  - **CAN** (`can_motor_params.yaml`):
    - `pid_kp/ki/kd`: for Damiao motors, recommended Kp=25–30, Ki=0, Kd=1–2
    - `max_velocity`, `max_torque`: set safe limits according to motor specifications
  - **UART** (`uart_motor_params.yaml`):
    - `baud: 1000000` (Feetech servos are typically 1 Mbps)
    - `motor_iface`: serial device path (e.g. `/dev/ttyACM0` or `/dev/ttyUSB0`)

## 3. Example Usage (From Scratch)

### 3.1 EtherCAT Motor Control (JMC IHSS42-EC, CSP Mode)

**Prerequisites**: See Section 2. Ensure the EtherCAT cable is connected to `eth0`, the motor is powered on, and you are running as `root`.

**Step 1**: Load the environment
```bash
sros2_setup  # source build/envsetup.sh already run in the SDK root directory

```

**Step 2**: Start motor_node
```bash
ros2 run peripherals motor_node --ros-args --params-file config/ecat_motor_params.yaml
```
Expected result: the terminal prints `[motor_node] EtherCAT slaves ready, entering RUNNING state` with no ERROR logs.

**Step 3**: Send a position command (CSP mode, move to 3.14 rad)
```bash
ros2 topic pub /cmd/motor peripherals/msg/MotorCommandArray \
  "{commands: [{id: 1, mode: 5, pos_des: 3.14}]}" --rate 100
```
Expected result: the motor rotates smoothly to the target position; running `ros2 topic echo /motor/state` shows `pos` gradually approaching 3.14.

**Step 4**: Check state feedback
```bash
ros2 topic echo /motor/state
```
Expected output includes the `pos`, `vel`, `trq`, and `error_flags` fields.

### 3.2 CAN Motor Control (Damiao, Velocity Mode)

**Prerequisites**: See Section 2. Ensure the CAN bus is enabled:
```bash
sudo ip link set can0 up type can bitrate 1000000
```

**Step 1**: Load the environment
```bash
sros2_setup  # source build/envsetup.sh already run in the SDK root directory
```

**Step 2**: Start motor_node
```bash
ros2 run peripherals motor_node --ros-args --params-file config/can_motor_params.yaml
```
Expected result: the terminal prints `[motor_node] CAN interface can0 opened`.

**Step 3**: Enable the motor (required step)
```bash
ros2 service call /motor/enable std_srvs/srv/SetBool "{data: true}"
```
Expected result: returns `success: true`.

**Step 4**: Send a velocity command (VEL mode, 3.0 rad/s)
```bash
ros2 topic pub /cmd/motor peripherals/msg/MotorCommandArray \
  "{commands: [{id: 2, mode: 2, vel_des: 3.0}]}" --rate 10
```
Expected result: the motor rotates at a constant speed of about 3.0 rad/s.

### 3.3 UART Motor Control (Feetech, Position Mode)

**Prerequisites**: See Section 2. Ensure the USB-TTL is connected and `/dev/ttyACM0` is accessible.

**Step 1**: Load the environment
```bash
sros2_setup  # source build/envsetup.sh already run in the SDK root directory
```

**Step 2**: Start motor_node
```bash
ros2 run peripherals motor_node --ros-args --params-file config/uart_motor_params.yaml
```

**Step 3**: Enable the motor (required step)
```bash
ros2 service call /motor/enable std_srvs/srv/SetBool "{data: true}"
```

**Step 4**: Send a position command (POS mode, move to 1.57 rad)
```bash
ros2 topic pub /cmd/motor peripherals/msg/MotorCommandArray \
  "{commands: [{id: 1, mode: 1, pos_des: 1.57}]}" --rate 10
```
Expected result: the servo rotates to approximately the 90° position.

## 4. Application Development

- **API / Interface**:
  - ROS 2 topics:
    - `/cmd/motor` (subscribe): `peripherals/msg/MotorCommandArray` — send control commands
    - `/motor/state` (publish): `peripherals/msg/MotorStateArray` — motor state feedback
  - ROS 2 services:
    - `/motor/enable`: `std_srvs/srv/SetBool` — enable/disable motors (CAN and UART motors must call this first)
    - `/motor/set_param`: `peripherals/srv/MotorSetParam` — write motor register parameters
    - `/motor/get_param`: `peripherals/srv/MotorGetParam` — read motor register parameters
  - C layer API (`motor.h`): `motor_init`, `motor_set_cmds`, `motor_get_states`, `motor_free`

- **Control Mode Mapping**:

  | mode value | Enum | Description | Supported Hardware |
  | :--- | :--- | :--- | :--- |
  | 0 | `IDLE` | Stop output, motor standby/release | All |
  | 1 | `POS` | Position closed-loop (rad) | All |
  | 2 | `VEL` | Velocity closed-loop (rad/s) | All |
  | 3 | `TRQ` | Torque closed-loop (Nm) | CAN, EtherCAT |
  | 4 | `HYBRID` | MIT hybrid mode (P/V/T/Kp/Kd) | Damiao CAN |
  | 5 | `CSP` | Cyclic Synchronous Position | EtherCAT |
  | 6 | `CSV` | Cyclic Synchronous Velocity | EtherCAT |
  | 7 | `CST` | Cyclic Synchronous Torque | EtherCAT |
  | 8 | `HM` | Homing mode | EtherCAT |

- **Usage Notes**:
  - The EtherCAT driver thread uses SCHED_FIFO (priority 80), requiring `root` or `CAP_SYS_NICE` permissions
  - The first position command on EtherCAT triggers zero-position anchoring (to prevent enable jumps), and subsequent commands move relative to that anchor
  - CAN/UART motors must call the `/motor/enable` service before responding to commands
  - You can dynamically modify parameters like `max_velocity`, `profile_acc`, `profile_dec` via `ros2 param set`

- **Reference demos and config paths**:
  - Config files: `middleware/ros2/peripherals/motor/config/`
  - Node source: `middleware/ros2/peripherals/motor/src/motor_node.cpp`
  - Low-level drivers: `components/peripherals/motor/src/drivers/`

## 5. Debugging Guide

- **Verbose logging**: Add `--log-level debug` at startup to inspect per-frame command parsing and mapping:
  ```bash
  ros2 run peripherals motor_node --ros-args --params-file config/ecat_motor_params.yaml --log-level debug
  ```
- **State monitoring**:
  ```bash
  ros2 topic echo /motor/state
  ```
  Fields to watch: `pos` (current position, rad), `vel` (velocity, rad/s), `error_flags` (CiA402 Statusword, e.g. `0x0637` = OPERATION_ENABLED)
- **Runtime parameter tuning**:
  ```bash
  ros2 param set /motor_node max_velocity 5.0
  ros2 param set /motor_node profile_acc "[50000.0, 50000.0]"
  ```
- **EtherCAT diagnostics**:
  - Check slave status: `ethercat slaves` (requires IgH tools)
  - Packet capture: `tcpdump -i eth0 ether proto 0x88a4 -w ecat.pcap`
- **CAN diagnostics**:
  ```bash
  candump can0       # View raw bus frames
  cansend can0 001#0102030405060708  # Manually send a test frame
  ```
- **Information collection checklist** (when collaborating with hardware/kernel colleagues):
  - `dmesg | grep -i ecat` or `dmesg | grep -i can`
  - `uname -r` (kernel version, whether it is an RT kernel)
  - `cat /proc/sys/kernel/sched_rt_runtime_us`
  - Complete motor_node logs (debug level)

## 6. FAQ

| Symptom | Possible Cause | Resolution |
| --- | --- | --- |
| `Parameter 'profile_vel' size mismatch` error at startup | Array parameter size in the config file does not match `motor_ids` | Ensure the element count of arrays like `profile_vel`, `profile_acc`, `profile_dec` equals the length of `motor_ids`; or keep just 1 value to let the system auto-expand |
| Motor does not respond to position commands, tpos always equals apos | EtherCAT zero-position anchoring logic: the first command is treated as the current position | Send a **changing** `pos_des` value (e.g. from 0.0 to 0.1) to trigger actual motion |
| EtherCAT reports `UNMATCHED` warning | `ecat_cycle_ms` too small, non-RT kernel cannot keep up | Set `ecat_cycle_ms` to 5 or above, and match the ROS 2 publish rate accordingly (e.g. 200 Hz) |
| `[Adapter] WARNING: EtherCAT loop overrun detected` | System scheduling jitter too large | Lower the publish rate, reduce system load, or use an RT kernel |
| CAN motor does not respond to commands | Enable service not called | First run `ros2 service call /motor/enable std_srvs/srv/SetBool "{data: true}"` |
| UART motor does not respond | Insufficient serial port permissions or baud rate mismatch | Confirm the user is in the `dialout` group, check that the `baud` parameter matches the motor's actual baud rate |

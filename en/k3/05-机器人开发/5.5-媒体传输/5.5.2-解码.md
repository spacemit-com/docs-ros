# Media Transmission · Decoding

## 1. Overview

- **Key Features**: Video decoding module that decompresses H.264/H.265/JPEG bitstreams into raw YUV/RGB video frames for display or subsequent image processing.
- **Specifications and Features**:
  - Supported decoding formats: H.264 (AVC), H.265 (HEVC), MJPEG
  - Supported resolutions: up to 4K (3840x2160)
  - Supported frame rates: up to 60fps (4K)
  - Hardware acceleration: uses hardware decoder for low power consumption and high performance
  - Output formats: YUV420, NV12, NV21, etc.
- **Directory Structure**: Based on the MPP framework, see [Multimedia · MPP](../../06-系统与平台/6.3-多媒体/6.3.1-mpp.md)

## 3. Example Usage (From Scratch)

### 3.1 Command-Line Decoding Test (File to File)

Use the MPP built-in `test_vdec_file` tool to decode a compressed bitstream into raw YUV frames and quickly verify decoding functionality.

**Prerequisites**: MPP compiled, development board powered on and accessible via SSH

**Step 1**: SSH into the development board

```bash
ssh root@<Board_IP>
# Password: root
```

**Step 2**: Navigate to the SDK build directory, copy related test files, then enter the test program directory

```bash
cd spacemit_robot
cp components/multimedia/mpp/test/assets/1920x1080.jpg output/build/cmake/pkgs/components_multimedia_mpp/test/
cd output/build/cmake/pkgs/components_multimedia_mpp/test
```

**Step 3**: Run MJPEG decoding

```bash
./test_vdec_file ./1920x1080.jpg 1920 1080 ./dec_out_nv12.yuv mjpeg
```

Parameter description:

| Parameter | Description |
| --- | --- |
| `./1920x1080.jpg` | Input bitstream file path |
| `1920` | Image width |
| `1080` | Image height |
| `./dec_out_nv12.yuv` | Output YUV file path |
| `mjpeg` | Decoding format (supports `h264`, `h265`, `mjpeg`) |

Expected output:

```text
[INFO] VDEC file test: ./1920x1080.jpg -> ./dec_out_nv12.yuv, codec=mjpeg, size=105692
[INFO] decoded frame: 1920x1080 planes=2 stride=1920 pts=0
```

After decoding completes, the `dec_out_nv12.yuv` file is generated in the current directory.

**Step 4**: Verify output YUV

Copy `dec_out_nv12.yuv` to a PC and use `ffplay` to verify playback:

```bash
ffplay -f rawvideo -pix_fmt nv12 -s 1920x1080 dec_out_nv12.yuv
```

> **Tip**: You can also first use the encoding example (see [Video Encoding](5.5.1-编码.md)) to generate an H.264 bitstream, then use `test_vdec_file` to decode it and verify the full encode-decode loop.

### 3.2 H.264 Decoding API Example

The following code example demonstrates the core calling flow using the MPP API for decoding.

**Step 1**: Create decoder context

```c
#include "vdec.h"

MppVdecCtx *ctx = vdec_ctx_create();
vdec_ctx_init(ctx);
```

**Step 2**: Set decoding parameters

```c
ctx.eCodecType = MPP_CODEC_H264;
vdec_ctx_set_param(&ctx);
```

**Step 3**: Submit bitstream and decode

```c
MppData input_stream;
// Populate input_stream with bitstream data
vdec_ctx_decode(ctx, &input_stream);
```

**Step 4**: Retrieve decoded video frame

```c
MppData output_frame;
vdec_ctx_get_output_frame(ctx, &output_frame);
// Process output_frame (display or save)
vdec_ctx_return_output_frame(ctx, &output_frame);
```

Expected result: Output YUV video frame, which can be saved to a file or sent to display

## 4. Application Development

- **API / Interface**:

  - Header file: `include/vdec.h`
  - Library name: `libmpp_vdec.so`
  - Main APIs:
    - `vdec_ctx_create()` - Create decoder context
    - `vdec_ctx_init()` - Initialize decoder
    - `vdec_ctx_set_param()` - Set decoding parameters
    - `vdec_ctx_decode()` - Decode bitstream
    - `vdec_ctx_get_output_frame()` - Get output frame
    - `vdec_ctx_destroy()` - Destroy decoder
- **Usage and Notes**:

  - Initialization sequence: create → init → set_param → decode
  - Thread safety: Single context does not support multi-threaded concurrent access
  - Memory management: Output frames must be released promptly to avoid memory leaks
  - Frame release: After retrieving a frame, must call `return_output_frame()` to release
  - Bitstream format: Ensure the input bitstream format is correct and contains complete SPS/PPS
- **Reference Demo / Example Path**: `mpp/test/test_vdec_file.c`, `mpp/mpi/vdec/vdec.c`, `mpp/sample/sample_uvc_vdec.c`

## 5. Debugging Guide

- **Frame data verification**: Save output YUV to a file and use `ffplay` to verify playback
- **Performance analysis**: Record decoding time, calculate actual frame rate
- **Error handling**: Check return values and handle decoding failures

## 6. Common Issues

| Symptom | Possible Cause | Resolution |
| --- | --- | --- |
| Decoder initialization failed | Hardware decoder plugin not loaded | Check if libv4l2_linlonv5v7_codec2.so exists |
| Corrupted output (artifacts/glitches) | Incorrect or corrupted bitstream format | Confirm bitstream format and check SPS/PPS |
| Low decoding frame rate | Bitstream bitrate too high or resolution too large | Reduce bitstream bitrate or resolution |
| Memory leak | Output frames not released | Ensure `return_output_frame()` is called |

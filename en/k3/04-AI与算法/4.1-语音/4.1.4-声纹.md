# 4.1.4 Voiceprint

## 1. Overview

The voiceprint component supports speaker enrollment, identification, and verification. Use it to determine which enrolled speaker produced an audio sample or whether the sample matches a specified speaker. The component is located in `components/model_zoo/voiceprint` and provides a C++ API and two command-line tools: `register_speaker` and `identify_speaker`.

The current backend is the CamP+ (3D-Speaker) ONNX model. It produces a 192-dimensional L2-normalized embedding and uses cosine similarity for 1:N identification and 1:1 verification. The default threshold is `0.6`, and the default database file is `speakers.db`.

Typical data flow:

```text
Enroll WAV/PCM -> CamP+ embedding -> speakers.db
Test WAV/PCM -> CamP+ embedding -> cosine similarity -> Identify/Verify result
```

Key directories:

| Path | Description |
| --- | --- |
| `components/model_zoo/voiceprint/include/vp_service.h` | Public C++ API. |
| `components/model_zoo/voiceprint/src/` | Voiceprint engine, backend factory, WAV reader, and database logic. |
| `components/model_zoo/voiceprint/tools/register_speaker.cpp` | Enrollment tool source. |
| `components/model_zoo/voiceprint/tools/identify_speaker.cpp` | Identification and verification tool source. |

## 2. Environment Setup

### Prerequisites

For SDK source acquisition and base build-environment setup, see [2.3-Building and Compilation](../../02-快速入门/2.3-构建编译.md). After initializing the SDK, return to this page and continue with [Build](#build).

Unless stated otherwise, run the following commands from the `spacemit_robot` SDK root directory.

### Build

The speech components use the `target/k3-com260-omni-agent.json` target configuration. Install the following dependencies if needed:

```bash
sudo apt install libcurl4-openssl-dev portaudio19-dev libsndfile1-dev
```

Load the SDK environment and build the voiceprint component:

```bash
source build/envsetup.sh
lunch k3-com260-omni-agent
cd components/model_zoo/voiceprint
mm
```

The recording commands in this document also require the audio component. If `audio_demo` is unavailable in the current environment, build the audio component:

```bash
cd ../../multimedia/audio
mm
```

On first run, the model is downloaded or loaded from `~/.cache/models/vp/campplus/` by default. The model file is `3dspeaker_speech_campplus_sv_zh-cn_16k-common.onnx`.

The build installs the following executables in `output/staging/bin`:

| Tool | Purpose |
| --- | --- |
| `register_speaker` | Enrolls a speaker from a WAV file or live recording and writes the result to `speakers.db`. |
| `identify_speaker` | Performs 1:N identification on an input WAV file, or 1:1 verification with `-v`. |

## 3. Examples

### 3.1 Enroll a Speaker

To enroll from a live recording:

```bash
register_speaker -n muggle -t 2
```

The tool enters recording mode and, by default, records three samples of approximately four seconds each. It averages their embeddings and saves the result to `speakers.db`. Expected output includes:

```text
Embedding RTF: 0.1442
Successfully registered speaker 'muggle'
Database saved to: speakers.db
```

To enroll from a file:

```bash
register_speaker -n muggle sample.wav
```

Common options:

| Option | Description |
| --- | --- |
| `-n, --name NAME` | Required speaker name. |
| `-d, --database FILE` | Database file. Defaults to `speakers.db`. |
| `-t, --threads NUM` | Number of inference threads. Defaults to 1. |
| `-f, --force` | Overwrites an existing speaker with the same name. |
| `-l, --list-devices` | Lists recording devices. |
| `-i, --input-device N` | Selects a recording device. |

### 3.2 Identify a Speaker

First, record test audio:

```bash
audio_demo record test.wav --duration 5 --rate 16000 --channels 2 --device -1
```

Then identify the speaker:

```bash
identify_speaker ./test.wav
```

The output includes the number of loaded speakers, threshold, RTF, identification result, and top-N matches:

```text
Loaded 1 speakers from database
Threshold: 0.6
IDENTIFIED: muggle (score: 0.802)
```

To verify a specified speaker:

```bash
identify_speaker -v muggle ./test.wav
```

## 4. Application Development

This section describes how to integrate the voiceprint component into a C++ application. `components/model_zoo/voiceprint/include/vp_service.h` is the authoritative API reference; this section covers only common public APIs and typical calling patterns. The C++ entry point is `SpacemiT::VpEngine`. **This component currently provides only a C++ SDK; Python bindings are not available.**

### 4.1 API Reference

The main voiceprint entry point is `SpacemiT::VpEngine`. Use this class to create an engine, enroll speakers, perform 1:N identification to find the closest match, perform 1:1 verification against a specified speaker, and persist the speaker database.

#### 4.1.1 Common Data Structures

| Type | Description |
| --- | --- |
| `VpConfig` | Engine configuration. Common fields include `backend`, `model_dir`, `num_threads=1`, `provider="cpu"`, `threshold=0.6` (identification and verification threshold), `sample_rate=16000`, and `db_path` (the database path, configurable during construction). Use `Preset(name)` to create a preset. Chainable methods include `withThreshold`, `withNumThreads`, `withProvider`, `withDbPath`, and `withSampleRate`. |
| `VpBackendType` | Backend enumeration: `CAMPPLUS` (default), `ERES2NET`, `ECAPA_TDNN`, `HTTP` (remote service), and reserved `CUSTOM`. |
| `SpeakerMatch` | A single match result: `name` (candidate) and `score` (similarity, [0, 1]). |
| `VpResult` | Identification, verification, or extraction result. Provides `GetName()`, `GetScore()`, `IsIdentified()` (1:N; score is at least the threshold), `IsVerified()` (1:1; score is at least the threshold and the name matches), `GetMatches()` (top-N candidates), `GetEmbedding()` (feature vector; CamP+ defaults to 192 dimensions), `GetRTF()`, `GetProcessingTimeMs()`, `IsSuccess()`, and `GetErrorMessage()`. |

#### 4.1.2 Engine Initialization and Presets

| API | Description | Parameters | Return value |
| --- | --- | --- | --- |
| `VpEngine(VpConfig)` | Constructs an engine with a complete configuration, including the backend, model path, threshold, and database path. | `config`: `VpConfig` instance. | Engine instance. |
| `VpEngine(backend, model_dir)` | Constructs an engine from a backend enumeration. Uses the default cache when no model path is specified. | `backend`: `VpBackendType`; `model_dir`: optional model directory. | Engine instance. |
| `VpConfig::Preset(name)` | Static factory that returns the specified preset. | `name`: currently only `campplus` is registered. The `ERES2NET` and `ECAPA_TDNN` backend enumerations are defined but have no registered presets; passing either throws `std::invalid_argument`. | `VpConfig`. |
| `VpConfig::AvailablePresets()` | Static method that lists available presets. | None. | `std::vector<std::string>`. |
| `IsInitialized()` / `GetEngineName()` / `GetBackendType()` / `GetEmbeddingDimension()` / `GetConfig()` | Query engine state and configuration. `GetEmbeddingDimension()` returns the feature-vector dimension for the current backend. | None. | Varies by method. |

#### 4.1.3 Register

| API | Description | Parameters | Return value |
| --- | --- | --- | --- |
| `Register(name, audio_path)` | Enrolls a speaker from one WAV file. | `name`: speaker name; `audio_path`: WAV path; 16 kHz mono is recommended. | `bool`; `true` on success. |
| `Register(name, vector<paths>)` | Enrolls a speaker from multiple WAV files for the same speaker. The engine aggregates and averages their embeddings for greater robustness. | `name`: speaker name; `audio_paths`: multiple WAV paths. | `bool`. |
| `Register(name, vector<float>, sample_rate=16000)` | Enrolls a speaker from in-memory floating-point PCM, such as microphone recordings or a decoded WAV file. | `name`: speaker name; `audio`: floating-point PCM; `sample_rate`: sample rate. | `bool`. |
| `RegisterWithEmbedding(name, embedding)` | Enrolls a speaker from a precomputed embedding and skips model inference. Suitable for migrating feature databases from other systems. | `name`: speaker name; `embedding`: feature vector whose length must match `GetEmbeddingDimension()`. | `bool`. |

#### 4.1.4 Identification and Verification

| API | Description | Parameters | Return value |
| --- | --- | --- | --- |
| `Identify(audio_path)` / `Identify(vector<float>, sample_rate=16000)` | **1:N**: finds the closest match among all speakers in the database. `IsIdentified()` indicates that the score meets the threshold. | Input audio. | `shared_ptr<VpResult>`; `GetMatches()` returns the top-N candidates. |
| `Verify(name, audio_path)` / `Verify(name, vector<float>, sample_rate=16000)` | **1:1**: compares only with the specified speaker. `IsVerified()` indicates success. It is much faster than `Identify` and is suitable for authentication when the expected identity is known. | `name`: speaker to verify; input audio. | `shared_ptr<VpResult>`. |
| `ExtractEmbedding(audio_path)` / `ExtractEmbedding(vector<float>, sample_rate=16000)` | Extracts only the feature vector without querying the database. Use it to implement custom comparison logic or export features. | Input audio. | `shared_ptr<VpResult>`; use `GetEmbedding()` to retrieve the vector. |

**Choosing between Identify and Verify:**

| Scenario | Recommended API | Input | Output | Performance tradeoff |
| --- | --- | --- | --- | --- |
| The speaker is unknown and you need the closest match | `Identify` | Audio | Ranked candidate list and whether the score meets the threshold | Linear with the number of speakers in the database |
| The expected speaker is known and needs verification | `Verify` | Speaker name and audio | Match result and score | One comparison; fastest |
| Compare two audio samples temporarily without adding them to the database | `ExtractEmbedding` × 2 + cosine similarity | Two audio samples | Application-calculated similarity | Fully controllable; you implement the comparison |

#### 4.1.5 Database Management and Runtime Configuration

| API | Description | Parameters | Return value |
| --- | --- | --- | --- |
| `SaveDatabase(path="")` | Saves the database to disk. Uses `VpConfig::db_path` when `path` is empty. | `path`: optional target path. | `bool`. |
| `LoadDatabase(path="")` | Loads the database from disk. If the file does not exist, returns `false` but leaves the engine usable with an empty database. | `path`: optional source path. | `bool`. |
| `RemoveSpeaker(name)` / `ContainsSpeaker(name)` / `GetSpeakerCount()` / `GetAllSpeakers()` | Manage and query database entries. | `name`: speaker name. | `bool` / `int` / `vector<string>`. |
| `SetThreshold(threshold)` / `GetThreshold()` | Adjusts the identification and verification threshold at runtime. A threshold that is too high causes missed identifications; one that is too low causes false identifications. A common range is 0.5-0.7. | `threshold`: [0, 1]. | None / `float`. |

### 4.2 C++ Examples

The following examples assume that you completed the build steps in Section 2. The CamP+ model is stored under `~/.cache/models/vp/campplus/`. For input audio, use 16 kHz mono recordings that are 2-5 seconds long, without background speech or very low volume.

After building the voiceprint component, `vp_service.h` and the static library `libvoiceprint.a` are installed in `output/staging`. Use the following CMake configuration to link the voiceprint library from a downstream component:

```cmake
add_executable(my_app main.cpp)

find_library(VP_LIB NAMES voiceprint
    PATHS ${CMAKE_INSTALL_PREFIX}/lib NO_DEFAULT_PATH)
find_path(VP_INCLUDE_DIR NAMES vp_service.h
    PATHS ${CMAKE_INSTALL_PREFIX}/include NO_DEFAULT_PATH)
if(NOT VP_LIB OR NOT VP_INCLUDE_DIR)
    message(FATAL_ERROR "voiceprint not found. Build components/model_zoo/voiceprint first.")
endif()

target_include_directories(my_app PRIVATE ${VP_INCLUDE_DIR})
target_link_libraries(my_app PRIVATE ${VP_LIB})
```

Declare `<depend>voiceprint</depend>` in the current component's `package.xml` is recommended.

#### 4.2.1 Enroll a Speaker from Multiple WAV Files

Use this approach to enroll existing speakers in batches from recordings. Collect two or three clean WAV files for each speaker, preferably recorded at different times, so that the engine can aggregate them internally.

Steps:

1. Create a preset with `VpConfig::Preset("campplus")`, then set the threshold, thread count, and database path.
2. Construct the engine and call `LoadDatabase`; if the file does not exist, the engine starts with an empty database.
3. Call `Register(name, vector<paths>)` to enroll the speaker.
4. Call `SaveDatabase` after successful enrollment.

```cpp
#include <iostream>
#include <vector>
#include "vp_service.h"

int main() {
    auto config = SpacemiT::VpConfig::Preset("campplus")
        .withThreshold(0.6f)
        .withNumThreads(2)
        .withDbPath("speakers.db");

    SpacemiT::VpEngine engine(config);
    if (!engine.IsInitialized()) {
        std::cerr << "声纹引擎初始化失败" << std::endl;
        return 1;
    }
    engine.LoadDatabase("speakers.db");  // Uses an empty database if the file does not exist.

    std::vector<std::string> samples = {
        "muggle_sample_1.wav",
        "muggle_sample_2.wav",
        "muggle_sample_3.wav",
    };
    if (!engine.Register("muggle", samples)) {
        std::cerr << "注册失败" << std::endl;
        return 1;
    }
    engine.SaveDatabase();
    std::cout << "已注册 muggle，库内共 "
              << engine.GetSpeakerCount() << " 人" << std::endl;
    return 0;
}
```

For a complete example that enrolls from microphone recordings using `AudioRecorder` and prompts the user to speak multiple times, see `components/model_zoo/voiceprint/tools/register_speaker.cpp`.

#### 4.2.2 1:N Identification

Use this approach when the current speaker is unknown and you need to find the closest match among enrolled speakers, such as when identifying meeting participants or speakers in a household.

Steps:

1. Load the existing database.
2. Call `Identify(audio)` to obtain a `VpResult`.
3. Use `IsIdentified()` to determine whether the score meets the threshold, and use `GetMatches()` to retrieve the top-N candidates for additional decision-making.

```cpp
SpacemiT::VpEngine engine(SpacemiT::VpConfig::Preset("campplus")
                              .withThreshold(0.6f));
engine.LoadDatabase("speakers.db");

auto result = engine.Identify("test.wav");
if (!result || !result->IsSuccess()) {
    std::cerr << "识别失败" << std::endl;
    return;
}

if (result->IsIdentified()) {
    std::cout << "识别为: " << result->GetName()
              << " (score=" << result->GetScore() << ")" << std::endl;
} else {
    std::cout << "未识别（最高 score=" << result->GetScore()
              << " 低于阈值）" << std::endl;
}

std::cout << "前 N 候选:" << std::endl;
for (const auto& m : result->GetMatches()) {
    std::cout << "  " << m.name << "  " << m.score << std::endl;
}
```

For a complete example with verbose mode, the `verify` subcommand, and speaker listing, see `components/model_zoo/voiceprint/tools/identify_speaker.cpp`.

#### 4.2.3 1:1 Verification

Use this approach when the expected speaker is known, such as a signed-in user, and you only need to confirm whether the current audio belongs to that speaker. It is much faster than `Identify` and is the core operation used by `omni_agent --vp-verify`.

```cpp
auto result = engine.Verify("muggle", "test.wav");
if (result && result->IsVerified()) {
    std::cout << "验证通过 (score=" << result->GetScore() << ")" << std::endl;
} else {
    std::cout << "验证不通过" << std::endl;
}
```

#### 4.2.4 Extract Embeddings for Custom Comparison

Use this approach for temporary authentication without enrolling a speaker, such as remembering a voice during a conversation, migrating feature databases between systems, or using a custom distance metric.

Steps:

1. Call `ExtractEmbedding` for each audio sample to obtain its feature vector.
2. Implement cosine-similarity comparison and apply the threshold required by your application.

```cpp
#include <cmath>
#include <vector>

float Cosine(const std::vector<float>& a, const std::vector<float>& b) {
    float dot = 0, na = 0, nb = 0;
    for (size_t i = 0; i < a.size(); ++i) {
        dot += a[i] * b[i];
        na += a[i] * a[i];
        nb += b[i] * b[i];
    }
    return dot / (std::sqrt(na) * std::sqrt(nb) + 1e-8f);
}

auto e1 = engine.ExtractEmbedding("user_say_hello.wav");
auto e2 = engine.ExtractEmbedding("user_say_goodbye.wav");
if (e1 && e2) {
    float sim = Cosine(e1->GetEmbedding(), e2->GetEmbedding());
    std::cout << "相似度: " << sim
              << "  (维度 " << engine.GetEmbeddingDimension() << ")" << std::endl;
}
```

#### 4.2.5 Database Persistence

Use this approach to retain enrolled speakers after a service restart or share a speaker database across devices.

```cpp
// At process startup.
engine.LoadDatabase("speakers.db");

// After enrollment or modification.
engine.Register("alice", {"alice_1.wav", "alice_2.wav"});
engine.RemoveSpeaker("old_user");
engine.SaveDatabase();          // Equivalent to SaveDatabase("speakers.db") using VpConfig::db_path.
engine.SaveDatabase("backup_speakers.db");  // You can also specify a different path.
```

The database file uses an internal component format and is not guaranteed to be compatible across versions. After upgrading the SDK, rebuild the database or migrate embeddings with `RegisterWithEmbedding`.

## 5. Troubleshooting

When troubleshooting voiceprint recognition, retain the enrollment samples, identification samples, and threshold configuration so you can reproduce score changes:

- Use `register_speaker -l` or `audio_demo list` to confirm the recording device. Use the same device for enrollment and identification.
- Use multiple 2-5 second clean speech samples for enrollment. Avoid background speech and very low volume.
- When identification fails, record the top-N scores and current `--threshold` to determine whether the issue is with the samples or threshold.
- When reproducing tests, use a fixed `speakers.db` path to avoid accidentally using an outdated database.

## 6. FAQ

| Symptom | Possible Cause | Resolution |
| --- | --- | --- |
| `UNKNOWN: No match above threshold` | The score is below the threshold, enrollment samples are insufficient, or recording conditions differ | Add enrollment samples, reduce noise, and adjust `--threshold` if necessary. |
| Verification intermittently fails for the same speaker | Speech is too short, volume is too low, or microphone position varies significantly | Use 2-5 seconds of clear speech and use the same device for enrollment and identification. |
| Scores are too high for different speakers | Enrollment samples are poor quality or the threshold is too low | Raise the threshold and collect new enrollment samples. |
| No recording device is found | The PortAudio default device is incorrect | List devices with `register_speaker -l`, then select one with `-i`. |

# Vision · Multi-Object Tracking

## 1. Overview

- **Key Features**: Multi-object tracking (MOT) based on a detector and tracker. Assigns a unique ID to each target in a video stream and maintains associations across frames. Supports ByteTrack and OC-SORT, both using YOLOv8 as the upstream detector.
- Specifications and features:
    - Supported trackers: ByteTrack, OC-SORT
    - Upstream detector: YOLOv8n
    - Detector input size: `[1, 3, 640, 640]`
    - Quantization: int8 (detector)
    - Output: Bounding box + confidence + class + tracking ID (`track_id`)
    - Inference backend: ONNX Runtime + SpaceMITExecutionProvider
    - Interfaces: C++ (`vision_service.h`), Python (`spacemit_vision` wheel: `VisionServiceNative`)
- Related directory structure:

```
examples/bytetrack/
├── config/bytetrack.yaml    # ByteTrack configuration
├── cpp/bytetrack.cpp        # C++ example
├── python/bytetrack.py      # Python example
└── scripts/                 # Model download scripts
examples/ocsort/
├── config/ocsort.yaml       # OC-SORT configuration
├── cpp/ocsort.cpp           # C++ example
├── python/ocsort.py         # Python example
└── scripts/                 # Model download scripts
src/deploy/bytetrack/        # ByteTrack deployment implementation
src/deploy/ocsort/           # OC-SORT deployment implementation
```


After loading the build environment from the SDK root, build the vision component:

```bash
source build/envsetup.sh
cd components/model_zoo/vision

```

The SDK integrated build installs the `bytetrack`, `ocsort`, and other example programs to `output/staging/bin`. After loading `build/envsetup.sh`, you can run them directly.

Before running the Python examples, install the `spacemit_vision` wheel:

```bash
cd components/model_zoo/vision
python3 -m pip install -U pybind11 build setuptools wheel
cmake -S . -B build && cmake --build build -j
python3 -m pip install --force-reinstall src/python/dist/*.whl
python3 -c "from spacemit_vision import VisionServiceNative; print('ok')"
```

Model weights are stored by default under `~/.cache/models/vision/yolov8/` and `~/.cache/models/vision/ocsort/`. You must run the download scripts manually first; if the weights are missing, the program fails immediately with a "Model file not found" error.

## 4. Application Development

This chapter is for application developers and explains how to integrate the multi-object tracking component into your own C++ or Python applications. The complete interface definitions are in `include/vision_service.h` and `src/python/spacemit_vision/vision_service_native.py`; this section covers the commonly used public APIs and typical usage patterns.

### 4.1 Interface Overview

The multi-object tracking component supports ByteTrack and OC-SORT, both based on the detection-and-tracking paradigm. Applications provide video frames one at a time, and the component outputs detection boxes and unique tracking IDs maintained across frames.

#### 4.1.1 Common Data Structures

| Type | Description |
| --- | --- |
| vision::Tracking | Tracking result type in `namespace vision`. Fields include the bounding box `bbox` (`BoundingBox`, containing x1/y1/x2/y2), confidence score `score`, class ID `label`, tracking ID `track_id`, and tracking state `state` (Tentative/Confirmed/Lost). |
| VisionServiceResponse | Inference response. The `results` field is a `vision::ResultList` variant list containing all results from the inference call (`vision::Tracking` in tracking scenarios). |
| vision::get_track_id / get_bbox / get_label / get_score | Convenience functions for reading common fields from variant results; read `track_id` with `vision::get_track_id(result)`. |

#### 4.1.2 Service Initialization

**C++ API**

| API | Description | Parameters | Return Value |
| --- | --- | --- | --- |
| VisionService::Create | Creates a tracking service instance from a YAML config file | config_path: path to the YAML config file | Smart pointer to a VisionService |
| VisionService::LastCreateError | Gets the error message from the most recent failed creation attempt | None | Error description string |

**Python API**

| API | Description | Parameters | Return Value |
| --- | --- | --- | --- |
| VisionServiceNative.create | Creates a service instance from a YAML config file | config_path: path to the YAML file; model_path_override: optional model-path override | A VisionServiceNative instance |
| VisionServiceNative.last_create_error | Gets the error message from the most recent failed creation attempt | None | Error description string |

#### 4.1.3 Multi-Object Tracking

**C++ API**

| API | Description | Parameters | Return Value |
| --- | --- | --- | --- |
| Infer | Runs detection and tracking on an image file | image_path: path to the image file; response: output response | VisionServiceStatus |
| Infer | Runs detection and tracking on a cv::Mat image | image: OpenCV Mat object; response: output response | VisionServiceStatus |
| Draw | Draws tracking results on an image (bounding boxes, tracking IDs, and classes). Stateless; the result must be passed explicitly | image: input image; response: inference response; out_image: output image | VisionServiceStatus |
| LastError | Gets the error message from the most recent inference call | None | Error description string |

**Python API**

| API | Description | Parameters | Return Value |
| --- | --- | --- | --- |
| infer_image | Runs inference on an image | image_or_path: a BGR numpy array or image path; conf/iou: optional thresholds (<=0 uses YAML defaults) | (VisionServiceStatus, results list) |
| draw | Draws the most recent inference result | image: BGR numpy array | (VisionServiceStatus, image with results drawn) |
| supports_draw | Whether the current model supports drawing on the C++ side | None | bool |
| last_error | Gets the most recent inference error | None | Error description string |

#### 4.1.4 Performance Monitoring

**C++ API**

| API | Description | Parameters | Return Value |
| --- | --- | --- | --- |
| SetTimingOptions | Enables/disables performance timing | options: VisionServiceTimingOptions (including enabled and print_to_stdout) | void |
| GetLastTiming | Gets per-stage timing from the most recent inference call | None | A VisionServiceTiming struct (tracking pipeline: detect_ms, track_ms, infer_ms; general image pipeline: preprocess_ms, model_infer_ms, postprocess_ms) |

### 4.2 Typical Usage

#### 4.2.1 C++ Video Tracking (ByteTrack)

```cpp
#include "vision_service.h"
#include <opencv2/opencv.hpp>
#include <iostream>
#include <variant>

int main() {
    // 1. Create the tracking service
    auto tracker = VisionService::Create("examples/bytetrack/config/bytetrack.yaml");
    if (!tracker) {
        std::cerr << "Failed to create tracker: "
                  << VisionService::LastCreateError() << std::endl;
        return -1;
    }

    // 2. Enable performance timing (optional)
    VisionServiceTimingOptions timing_options;
    timing_options.enabled = true;
    tracker->SetTimingOptions(timing_options);

    // 3. Open the video
    cv::VideoCapture cap("video.mp4");
    cv::Mat frame, output;

    while (cap.read(frame)) {
        // 4. Run tracking
        VisionServiceResponse response;
        VisionServiceStatus ret = tracker->Infer(frame, &response);
        if (ret != VISION_SERVICE_OK) {
            std::cerr << "Tracking failed: " << tracker->LastError() << std::endl;
            continue;
        }

        // 5. Process results (response.results is a list of vision::Result variants)
        std::cout << "Frame: " << cap.get(cv::CAP_PROP_POS_FRAMES)
                  << ", Tracked objects: " << response.results.size() << std::endl;

        for (const auto& result : response.results) {
            vision::BoundingBox box = vision::get_bbox(result);
            // Read the tracking state from the concrete vision::Tracking type
            const vision::Tracking* trk = std::get_if<vision::Tracking>(&result);
            std::cout << "  Track ID: " << vision::get_track_id(result)
                      << ", Class: " << vision::get_label(result)
                      << ", Score: " << vision::get_score(result)
                      << ", Box: [" << box.x1 << "," << box.y1 << ","
                      << box.x2 << "," << box.y2 << "]";
            if (trk) {
                std::cout << ", State: " << static_cast<int>(trk->state);
            }
            std::cout << std::endl;
        }

        // 6. Draw results (stateless; pass response explicitly)
        tracker->Draw(frame, response, &output);
        cv::imshow("Tracking", output);

        if (cv::waitKey(1) == 'q') break;
    }

    // 7. Check performance metrics (optional)
    auto timing = tracker->GetLastTiming();
    std::cout << "Detection: " << timing.detect_ms << " ms" << std::endl;
    std::cout << "Tracking: " << timing.track_ms << " ms" << std::endl;

    return 0;
}
```

#### 4.2.2 C++ Real-Time Camera Tracking

```cpp
#include "vision_service.h"
#include <opencv2/opencv.hpp>

int main() {
    auto tracker = VisionService::Create("examples/bytetrack/config/bytetrack.yaml");
    cv::VideoCapture cap(0);  // Open the camera
    cv::Mat frame, output;

    while (cap.read(frame)) {
        VisionServiceResponse response;
        if (tracker->Infer(frame, &response) != VISION_SERVICE_OK) continue;
        tracker->Draw(frame, response, &output);

        cv::imshow("Real-time Tracking", output);
        if (cv::waitKey(1) == 'q') break;
    }

    return 0;
}
```

#### 4.2.3 Python Video Tracking (ByteTrack)

```python
import cv2
from spacemit_vision import VisionServiceNative, VisionServiceStatus

tracker = VisionServiceNative.create("examples/bytetrack/config/bytetrack.yaml")
cap = cv2.VideoCapture("video.mp4")

while True:
    ret, frame = cap.read()
    if not ret:
        break

    status, tracks = tracker.infer_image(frame)
    if status != VisionServiceStatus.OK:
        raise RuntimeError(tracker.last_error())

    for r in tracks:
        print(f"Track ID: {r.track_id}, Class: {r.label}, Score: {r.score:.4f}")

    output = frame
    if tracker.supports_draw():
        st, output = tracker.draw(frame)
    cv2.imshow("Tracking", output)
    if cv2.waitKey(1) & 0xFF == ord('q'):
        break

cap.release()
cv2.destroyAllWindows()
```

#### 4.2.4 Python Tracking Trajectory Recording

```python
import cv2
from collections import defaultdict
from spacemit_vision import VisionServiceNative, VisionServiceStatus

tracker = VisionServiceNative.create("examples/bytetrack/config/bytetrack.yaml")
cap = cv2.VideoCapture("video.mp4")
trajectories = defaultdict(list)

while True:
    ret, frame = cap.read()
    if not ret:
        break

    status, tracks = tracker.infer_image(frame)
    if status != VisionServiceStatus.OK:
        break

    for r in tracks:
        cx, cy = (r.x1 + r.x2) / 2, (r.y1 + r.y2) / 2
        trajectories[r.track_id].append((cx, cy))

    output = frame.copy()
    if tracker.supports_draw():
        st, drawn = tracker.draw(frame)
        if st == VisionServiceStatus.OK:
            output = drawn
    for track_id, points in trajectories.items():
        for i in range(1, len(points)):
            cv2.line(output,
                     (int(points[i-1][0]), int(points[i-1][1])),
                     (int(points[i][0]), int(points[i][1])),
                     (0, 255, 0), 2)

    cv2.imshow("Tracking with Trajectories", output)
    if cv2.waitKey(1) & 0xFF == ord('q'):
        break

cap.release()
cv2.destroyAllWindows()
```

### 4.3 Configuration

#### 4.3.1 ByteTrack Configuration

```yaml
# Detection model path (YOLOv8)
model_path: ~/.cache/models/vision/yolov8/yolov8n_no_dfl.q.onnx

# Test video path (used by the example program)

# Inference parameters

    # Detection confidence threshold
  conf_threshold: 0.25
  
    # NMS IoU threshold
  iou_threshold: 0.45
  
    # Number of frames to retain after a target is lost
  track_buffer: 30
  
    # Video frame rate (used for speed estimation)
  frame_rate: 30
  
    # Number of inference threads (example default: 8; recommended K3 intra-op maximum: 8; reduce as needed)
  num_threads: 8
  
    # Inference backend (SpaceMITExecutionProvider is preferred)
  providers:
    - SpaceMITExecutionProvider
    - CPUExecutionProvider  # Fallback backend
```

#### 4.3.2 OC-SORT Configuration

```yaml
# Detection model path (YOLOv8)
model_path: ~/.cache/models/vision/ocsort/yolov8n_no_dfl.q.onnx

# Test video path (used by the example program)
test_video: ~/.cache/assets/video/003_palace.mp4

# Class label file path (80 COCO classes)
label_file_path: assets/labels/coco.txt

# Deployment class name (C++ model-factory registration name; Python uses it indirectly through the YAML path)
class: deploy.ocsort.OCSortTracker

# Inference parameters
default_params:
    # Detection confidence threshold
  conf_threshold: 0.25
  
    # NMS IoU threshold
  iou_threshold: 0.45
  
    # Number of inference threads (example default: 8; recommended K3 intra-op maximum: 8; reduce as needed)
  num_threads: 8
  
    # Inference backend
  providers:
    - SpaceMITExecutionProvider
  
    # OC-SORT-specific parameters
    track_thresh: 0.6        # Tracking confidence threshold
    track_iou_thresh: 0.3    # Tracking IoU threshold
    track_buffer: 60          # Number of frames to retain after a target is lost
    min_hits: 3               # Minimum number of hits
    delta_t: 3                # Time interval for speed estimation
    asso_func: "iou"          # Association function (iou or giou)
    inertia: 0.2              # Inertia coefficient
    use_byte: false            # Whether to use the ByteTrack strategy
```

**Choosing Between ByteTrack and OC-SORT**:

- **ByteTrack**: Simple parameters, suitable for general scenarios. It tracks quickly and is suitable for real-time applications.
- **OC-SORT**: More parameters and better performance with occlusion and nonlinear motion, making it suitable for complex scenarios.

**Parameter tuning recommendations**:

- **track_buffer**: Number of frames to retain after a target is lost. Increasing it can reduce ID switches but increases memory usage.
- **frame_rate**: Must match the actual video frame rate; otherwise, speed estimation is inaccurate.
- **conf_threshold**: Detection confidence threshold. Setting it too high can cause tracks to be lost.
- **track_thresh** (OC-SORT): Tracking confidence threshold. Lowering it can reduce ID switches.
- **num_threads** (detector): The example YAML defaults to 8. The recommended maximum K3 intra-op thread count is 8; reduce it as needed.

### 4.4 Performance Monitoring

Enabling performance timing lets you analyze the duration of each inference stage for performance tuning and bottleneck identification.

**C++ example**:

```cpp
VisionServiceTimingOptions timing_options;
timing_options.enabled = true;
tracker->SetTimingOptions(timing_options);

VisionServiceResponse response;
tracker->Infer(frame, &response);

auto timing = tracker->GetLastTiming();
std::cout << "Detection: " << timing.detect_ms << " ms" << std::endl;
std::cout << "Tracking: " << timing.track_ms << " ms" << std::endl;
std::cout << "Total: " << timing.infer_ms << " ms" << std::endl;
```

**Performance tuning tips**:

- High detection latency: Detection is the main bottleneck; use a lighter detection model (yolov8n instead of yolov8m).
- High tracking latency: Tracking algorithms usually take very little time (less than 5 ms). If latency is high, check whether track_buffer is too large.
- Low overall frame rate: Reduce the input resolution or use a faster detection model.

**Reference demo paths**:
- `examples/bytetrack/`, `examples/ocsort/`
- Application example: `applications/intrusion_detection/` (intrusion detection, a combined detection and tracking application)

## 5. Debugging Guide

- Enable timing: Use `SetTimingOptions` to view `detect_ms` (detection latency) and `track_ms` (tracking latency).
- Frequent ID switches: Increase `track_buffer` and lower `track_thresh`.
- Lost tracks: Confirm that the detector's `conf_threshold` is not too high to maintain detection continuity.
- Mismatched video frame rate: Confirm that `frame_rate` matches the actual video frame rate.

## 6. FAQ

| Symptom | Possible Cause | Resolution |
| --- | --- | --- |
| `Model file not found` | Model not downloaded | Run the `download_models.sh` script for the corresponding example |
| `No module named 'spacemit_vision'` | Wheel not installed | Build as described in Section 2 and run `pip install src/python/dist/*.whl` |
| Frequent tracking ID changes | `track_buffer` is too small or detection is unstable | Increase `track_buffer` and lower `conf_threshold` |

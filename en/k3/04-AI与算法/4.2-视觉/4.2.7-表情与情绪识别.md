# Vision · Expression and Emotion Recognition

## 1. Overview

- **Key Features**: Facial expression classification based on ResNet50. Accepts a facial image and outputs an expression category (such as happy, sad, angry, surprise, or neutral) with a confidence score. Typically used with a face detection model: first detect the face region, then crop it and send it to the expression recognition model.
- Specifications and features:
    - Supported model: Emotion ResNet50
    - Input size: `[1, 3, 224, 224]`
    - Quantization: int8
    - Output: Expression category + confidence score
    - Inference backend: ONNX Runtime + SpaceMITExecutionProvider
    - Interfaces: C++ (`vision_service.h`), Python (`spacemit_vision` wheel: `VisionServiceNative`)
- Related directory structure:

```
examples/emotion/
├── config/emotion.yaml    # Configuration file
├── cpp/emotion.cpp        # C++ example
├── python/emotion.py      # Python example
└── scripts/               # Model download scripts
src/deploy/emotion/        # Deployment implementation (C++ / Python)
assets/labels/emotion.txt  # Expression category labels
```


## 4. Application Development

This chapter is for application developers and explains how to integrate the expression and emotion recognition component into your own C++ or Python applications. The complete interface definitions are in `include/vision_service.h` and `src/python/spacemit_vision/vision_service_native.py`; this section covers the commonly used public APIs and typical usage patterns.

### 4.1 Interface Overview

The core entry points of the expression recognition component are `VisionService` (C++) and `VisionServiceNative` (Python, `spacemit_vision` wheel). Applications use these interfaces to load expression recognition models and classify emotions in facial images.

#### 4.1.1 Common Data Structures

| Type | Description |
| --- | --- |
| VisionServiceResponse | Inference response. `results` is a variant list `vision::ResultList`; `ok`/`error_message` indicate the status. |
| vision::Classification | Concrete expression recognition result type. Contains the expression category ID (`label`), confidence (`score`), and per-category probabilities (`class_scores`). |

#### 4.1.2 Service Initialization

**C++ API**

| API | Description | Parameters | Return Value |
| --- | --- | --- | --- |
| VisionService::Create | Creates an expression recognition service instance from a YAML config file | config_path: path to the YAML config file | Smart pointer to a VisionService |
| VisionService::LastCreateError | Gets the error message from the most recent failed creation attempt | None | Error description string |

**Python API**

| API | Description | Parameters | Return Value |
| --- | --- | --- | --- |
| VisionServiceNative.create | Creates a service instance from a YAML config file | config_path: path to the YAML file; model_path_override: optional override for the model path | A VisionServiceNative instance |
| VisionServiceNative.last_create_error | Gets the error message from the most recent failed creation attempt | None | Error description string |

#### 4.1.3 Expression Recognition

**C++ API**

| API | Description | Parameters | Return Value |
| --- | --- | --- | --- |
| Infer | Runs expression recognition on a facial image | image_path: path to the image file; response: output VisionServiceResponse | VisionServiceStatus |
| Infer | Runs expression recognition on a cv::Mat image | image: an OpenCV Mat object; response: output VisionServiceResponse | VisionServiceStatus |
| LastError | Gets the error message from the most recent inference call | None | Error description string |

**Python API**

| API | Description | Parameters | Return Value |
| --- | --- | --- | --- |
| infer_image | Runs expression classification on an image | image_or_path: a BGR numpy array or an image path | (VisionServiceStatus, list of results; read `results[0].class_scores` for the probabilities of each category) |
| get_class_names | Gets the list of expression category names in the configuration | None | List of strings |
| last_error | Gets the error from the most recent inference call | None | Error description string |

> Emotion is a classification model. `get_capabilities()` does not register drawing support, and `supports_draw()` is always `False`; for visualization, draw labels manually with `cv2.putText` or similar methods (consistent with `examples/emotion/python/emotion.py`).

#### 4.1.4 Performance Monitoring

**C++ API**

| API | Description | Parameters | Return Value |
| --- | --- | --- | --- |
| SetTimingOptions | Enables/disables performance timing | options: VisionServiceTimingOptions struct | void |
| GetLastTiming | Gets per-stage timing from the most recent inference call | None | VisionServiceTiming struct (`preprocess_ms`, `model_infer_ms`, `postprocess_ms`, `infer_ms`, etc.) |

### 4.2 Typical Usage

#### 4.2.1 C++ Single-Image Expression Recognition

```cpp
#include "vision_service.h"
#include <opencv2/opencv.hpp>
#include <iostream>

int main() {
    // 1. Create the service
    auto service = VisionService::Create("examples/emotion/config/emotion.yaml");
    if (!service) {
        std::cerr << "Failed to create service: " 
                  << VisionService::LastCreateError() << std::endl;
        return -1;
    }

    // 2. Enable performance timing (optional)
    VisionServiceTimingOptions timing_opts;
    timing_opts.enabled = true;
    service->SetTimingOptions(timing_opts);

    // 3. Run inference
    VisionServiceResponse response;
    VisionServiceStatus ret = service->Infer("face.jpg", &response);
    if (ret != VISION_SERVICE_OK) {
        std::cerr << "Inference failed: " << service->LastError() << std::endl;
        return -1;
    }

    // 4. Process the results
    if (!response.results.empty()) {
        int emotion_class = vision::get_label(response.results[0]);
        float emotion_score = vision::get_score(response.results[0]);
        std::cout << "Emotion: class " << emotion_class
                  << ", Score: " << emotion_score << std::endl;
    }

    // 5. View performance metrics (optional)
    auto timing = service->GetLastTiming();
    std::cout << "Preprocess: " << timing.preprocess_ms << " ms" << std::endl;
    std::cout << "Inference: " << timing.model_infer_ms << " ms" << std::endl;
    std::cout << "Postprocess: " << timing.postprocess_ms << " ms" << std::endl;

    return 0;
}
```

#### 4.2.2 Python Single-Image Expression Recognition

```python
import cv2
import numpy as np
from spacemit_vision import VisionServiceNative, VisionServiceStatus

svc = VisionServiceNative.create("examples/emotion/config/emotion.yaml")
face_image = cv2.imread("face.jpg")

status, results = svc.infer_image(face_image)
if status != VisionServiceStatus.OK:
    raise RuntimeError(svc.last_error())

if results:
    scores = list(results[0].class_scores)
    emotion_class = int(np.argmax(scores))
    emotion_score = float(scores[emotion_class])
    labels = svc.get_class_names()
    emotion_name = labels[emotion_class] if emotion_class < len(labels) else f"class_{emotion_class}"
    print(f"Emotion: {emotion_name} (class {emotion_class}, score: {emotion_score:.4f})")

    # Classification models have no C++ draw support; draw the label manually
    result_image = face_image.copy()
    cv2.putText(result_image, f"{emotion_name} {emotion_score:.2f}",
                (10, 30), cv2.FONT_HERSHEY_SIMPLEX, 1.0, (0, 255, 0), 2)
    cv2.imwrite("result.jpg", result_image)
```

### 4.3 Configuration

The YAML configuration file defines model loading and inference parameters. The complete configuration is described below:

```yaml
# Model file path (ResNet50 expression recognition model)
model_path: ~/.cache/models/vision/emotion/emotion_resnet50_final.q.onnx

# Test image path (used by the example program)
test_image: ~/.cache/assets/image/003_face0.png

# Category label file path (expression categories)
label_file_path: assets/labels/emotion.txt

# Model input size [height, width]
image_size: [224, 224]

# Deployment class name (C++ model factory registration name; Python uses it indirectly through the yaml path)
class: deploy.emotion.EmotionRecognizer

# Inference parameters
default_params:
    # Number of inference threads (example default: 8; K3 platform recommends a maximum of 8 intra-op threads; reduce as needed for the scenario)
  num_threads: 8
  
    # Inference backend (SpaceMITExecutionProvider is preferred)
  providers:
    - SpaceMITExecutionProvider
        - CPUExecutionProvider  # Fallback backend
```

**Supported expression categories** (refer to `assets/labels/emotion.txt`):

- 0: neutral (neutral)
- 1: happiness (happy)
- 2: sadness (sad)
- 3: surprise (surprised)
- 4: fear (fearful)
- 5: disgust (disgusted)
- 6: anger (angry)

**Parameter tuning recommendations**:

- **image_size**: The standard input for expression recognition is [224, 224]; modification is not recommended.
- **num_threads**: The example YAML defaults to 8. A maximum of **8** intra-op threads is recommended for the K3 platform. If CPU contention or unstable latency occurs, try reducing this value to 4; values above 8 are not recommended.
- **providers**: SpaceMITExecutionProvider is preferred for optimal performance.
- **Input requirements**: Input should be a cropped and aligned facial image. Use a face detection model to locate the face region first.

### 4.4 Performance Monitoring

Enable performance timing to analyze the time spent in each inference stage for performance optimization and bottleneck identification.

**C++ example**:

```cpp
VisionServiceTimingOptions opts;
opts.enabled = true;
service->SetTimingOptions(opts);

VisionServiceResponse response;
service->Infer("face.jpg", &response);

auto timing = service->GetLastTiming();
std::cout << "Preprocess: " << timing.preprocess_ms << " ms" << std::endl;
std::cout << "Inference: " << timing.model_infer_ms << " ms" << std::endl;
std::cout << "Postprocess: " << timing.postprocess_ms << " ms" << std::endl;
std::cout << "Total: " << timing.infer_ms << " ms" << std::endl;
```

**Performance optimization recommendations**:

- High preprocessing time: Expression recognition preprocessing is relatively simple (resizing + normalization) and should take little time.
- High inference time: Confirm that SpaceMITExecutionProvider is in use and check the thread count setting.
- High postprocessing time: Expression classification postprocessing consists only of softmax and should take very little time.

**Reference demo path**: `examples/emotion/`

**Application example**: `applications/emotion_detection/` (combined face detection + expression recognition application)

## 5. Debugging Guide

- Enable timing: Use `SetTimingOptions` to view the time spent in each stage.
- Input requirements: A cropped facial image (224×224) is recommended. Full-body images or images with complex backgrounds affect accuracy.
- Confirm that the label file `assets/labels/emotion.txt` exists.

## 6. FAQ

| Symptom | Possible Cause | Resolution |
| --- | --- | --- |
| `Model file not found` | Model not downloaded | Run `bash examples/emotion/scripts/download_models.sh` |
| `No module named 'spacemit_vision'` | Wheel not installed | Build as described in Section 2 and run `pip install src/python/dist/*.whl` |
| Inaccurate classification results | The input is not a facial image or the face is too small | Use face detection to crop the face region before sending it to expression recognition |
| Label mismatch | Label file missing | Confirm that `assets/labels/emotion.txt` exists |
